# 1.18.0 release verification

Knowledge, Research and the selected game-decision-support Skill now route draft answers through condition, counterexample and provenance review. BM25 remains default; optional hybrid and original Query fallback are unchanged. No new model, service, schedule, corpus migration or website deployment is included.

The responsible caller first checks the relevant source inventory, then reviews the actual draft. The optional read-only Query review action binds that assessment to current answer text, actual source receipts, quoted evidence, scope and budget. Answer-bearing assembly repeats that validation; legacy evidence-only assembly stays compatible and does not imply final-answer review. Mechanical ready does not certify semantic correctness or inventory completeness. Auxiliary model self-assessment is not an unattended release gate.

Source verification includes 18 new mechanical review checks, 41 existing Query regressions, both Skill validations, generated mirror consistency and the portable source contract. Private host regression exercised three previous real answers and two labeled fault injections: three revisions and two retained answers. Earlier auxiliary-model omissions and invalid spans were preserved privately rather than converted into a success claim. These bounded observations do not establish long-term accuracy or savings.

Distribution verification runs the full installer test suite, actual installed Node contracts, the real 1.17.0 predecessor upgrade and reverse recovery, and explicitly selected Codex/CodeBuddy Skill upgrade and rollback. Private Wiki, local retrieval binding, audit canaries and host rules are preserved. Historical 1.14.0→1.14.1 feedback and 1.16→1.17 interaction tests use their immutable destination bundles rather than interpreting future HEADs as those releases; their original inventory and recovery assertions remain. Skill inventory validation compares registered IDs with actual library entries and retains required licensed-Skill checks, instead of fixing the old total of 17. These are fixture corrections; production upgrade and conflict gates are unchanged.

Only the Knowledge, Research and Skills inventories change; the other nine component inventories are preserved. Publication uses committed, explicitly curated source inputs. The existing portable Query/navigation and optional-analysis adaptations are retained; private ingestion controllers and audit changes are excluded. Private research answers, reports, model receipts, user paths and conversation links are outside the whitelist.

Installed runtime testing also reproduced a pre-existing 1.17.0 layout-contract failure: the three already shipped retrieval tests occupied `tests/`, but the formal directory contract omitted that directory. The source-owned portable contract now registers those three tests plus the new answer-review test, rejects undeclared regression files and still rejects unknown directories. A negative installed fixture adds an undeclared file with an otherwise matching inventory count to verify that the explicit boundary remains effective; no corpus or approval rules are relaxed.

The initial full run executed 96 tests (92 passed; three failures and one error exposed the issues above). All affected cases and installed contracts were rerun after correction. The additional negative fixture first failed because its synthetic marker used Windows newlines; writing valid LF bytes made the intended undeclared-file rejection pass. Across preserved full-run and targeted evidence, all 97 distinct cases have passing executions. Unchanged passing cases were reused; this is not a claim that the initial full run was clean.

Remote tag, anonymous release-asset hash and fresh public clone/install are verified after the release commit; this document does not pre-certify network actions. Recovery and optional interface details are in [the upgrade guide](../../upgrades/1.18.0.md).

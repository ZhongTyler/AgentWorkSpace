## Integrity and ownership

AWS catalog schema 2 fixes module versions, Git commits, module.json and inventory digests, payload hashes, capability declarations and optional relationships. Metadata checks and downloaded-payload checks have separate output fields. Explicit verification of a missing selected module fails. Runtime does not fetch unselected modules.

Modules provide their baseline domain rules. Optional host governance can come from meta or an existing framework. Meta remains one complete edition. Optional business integration still needs responsibility, I/O, authority/data ownership and recovery review.

Existing verified standalone instances retain their actual path, Git and file ownership. Registration rollback preserves the instance. Edited, duplicate or different-version instances require separate review. Installation and retrieval use separate locks. Failed retrieval preserves staging and actual transaction state. Existing managed files keep their original edit/conflict/rollback protection.

Legacy publisher copy-export is refused for catalog schema 2. Independent module repositories are the publication authority. AWS carries gitlinks and combination metadata. User projects, reports, accounts, runtime and private learning records remain with their owners.

## Artifact and public gates

Release artifacts are built from fixed clean Git commits. The default aggregate ZIP is lightweight and retrieves selected modules. A full offline ZIP can include the fixed child trees explicitly. Existing 1.x tags/assets and historical blobs remain available. Use shallow clones or the lightweight archive to avoid old-history transfer.

Formal public repository state, module and aggregate tags, release names, asset hashes, anonymous downloads and new public clones are separate post-publication gates. Local tests and synthetic data do not establish real travel research, report acceptance, artistic quality, user benefit or live-tool service behavior. The two optional Travel browser cases retain their skipped status.

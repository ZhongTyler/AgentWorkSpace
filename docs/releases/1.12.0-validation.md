Scope: optional pinned game-source reference routing and external-home recovery in Research; committed FLUX klein and CPU cutout maintenance inventory in Tools; reviewed asynchronous closure guidance and selected-Skill catalog sealing. Private research, game snapshots, model weights, GPU environments, host trial receipts and host-only governance changes are excluded. Exact source revisions are recorded in generated _release.json files.

Source checks passed: 23 Research tests, including nine reference safety/portability cases and existing phase-cost/weekly/REA boundaries; nine Tools maintenance tests. Public-source export contracts verified 113 Research files and 119 Tools files, including provenance markers, source preservation and traversal rejection. Every sealed source input was also checked against staged Git bytes before committing, preserving all 19 license originals and catching LF/profile risks before publication.

The new release checks cover metadata-only installation, no implicit source/model downloads or startup, refusal to restore within managed modules, external home/profile integrity, private reference receipt rejection and preservation across rollback. Historical coordination/model-policy fixtures advance through actual published predecessors before the current upgrade; conflicts select an actually changed file rather than treating unchanged local edits as conflicts. Production upgrade rules remain unchanged.

The source-only reference preparation and one actual Brogue archive recovery/read are checked independently of generated fixtures. No game or GPU model is executed for this publication. Previous maintainer image trials do not establish recipient quality, bulk stability or game adoption. Installation, upgrade/recovery, remote tag/archive verification and delivery receipts are distinct stages; final results are recorded by the release run rather than pre-certified here.

Recent-content audit: conditional Knowledge coordination, observed phase costs and REA/game-development support already existed in prior releases. Cutout and closure guidance became committed during this run and their reusable parts are now included; private image comparisons and host-governance adoption remain with their owners. Source caches staying local is compatible with distributing reusable workflow instructions and maintenance code; it must not silently remove those public capabilities.

The initial regression executed 73 tests with 71 passes and two fixture failures: an unchanged upstream file was selected as a conflict canary, and a new check incorrectly expected rollback to delete empty directories instead of only owned files. Both fixtures were corrected without changing production upgrade/rollback behavior. The original logs are retained; final affected-package and recovery results are recorded separately. The first portability test also hit the known Windows temporary-root ACL restriction; using the task-owned fixture root passed ordinary sandbox checks.

The existing PersonalSite presentation explicitly describes the 1.9.0 snapshot and links to latest package instructions separately. This release does not invalidate that historical description or its URLs. No website deployment is included. A future expanded capability showcase can follow the site's owner and deployment contract.

The guide and explicit whitelist are now present, and the source catalog builder refuses sealing without a matching guide. Production installers and version gates remain unchanged. Recovery reruns cover the affected seven tests, including real 1.11.0 Research/Tools upgrade, selected closure Skill conflict/upgrade/rollback, no implicit model startup and external-home preservation; unaffected checks are reused rather than reclassified as a green initial run.

Final public-boundary inventory: Research 113 files, Tools 124 files, Skills 48 files, each including provenance. Private-content scanning and all portable-profile hashes passed. The final external Tools home includes cutout maintenance, with no runtime created or models loaded. The original Brogue archive recovery/read remains valid because its library code and pinned identity are unchanged by the later Skill guide repair.

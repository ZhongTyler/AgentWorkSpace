# Agent 盲评

## 触发与预期结果

用户需要运行候选对照或准备可执行评测协议时使用。交付可复核的比较结果或交接包，说明所测任务支持哪些判断，以及设计或资源限制；已有结果的论证核查可用 evidence-audit，不自动重跑评测。

## 硬边界

- 在查看候选输出前冻结题目、条件、评分与汇总规则；不得根据结果调权重、删题或改门槛再声称预注册有效。
- 评委只接收等价题面、匿名候选和冻结 rubric；隔离隐藏提示词、身份映射、生成过程与其他评委意见。保护私密材料，评测授权不扩大外发、工具或写入范围。
- 独立性必须来自真实隔离上下文，多个角色名不等于独立评审。评委数量、汇总和有效性条件在运行前按风险与预算确定；人数本身不证明有效性，缺少正式条件时如实作探索性比较。
- 候选生成与 rubric 编写按实际需要安排，不固定 agent 人数；缺少独立委派能力时提供可执行方案或明确降格，不模拟多个评委冒充独立评测。
- 评测分数不产生采用、发布或长期规则晋升授权；用户已授权的本地选择与修改可在原范围内继续，不因评测结束重新索要同一授权。

## 执行与完成标准

实际运行评测或准备可交接评测包时，读取 [评测协议](references/evaluation-protocol.md)，按任务覆盖与预算预注册。普通方案讨论不必展开完整协议。

完成时能追溯冻结输入、匿名化与顺序、有效评分、汇总结果和失效项；报告题型差异、分歧与证据边界。缺失证据或资源导致的降格可作为诚实交付，不能写成正式胜负或普遍优势。呈现形式由评测规模和用户用途决定。

## 按需重复与稳定性分析

首次生成候选前，由执行Agent自主判断重复是否有望改变本次选择，无需用户点名。稳定性是关键目标、既有独立证据显示同条件波动，或预期方案差异相对已知波动很小时，结合隔离能力和原预算考虑启用；普通确定性检查或仅有评分分歧时不因此增加生成。把启用/跳过理由简记在原设计中，遵守用户明确的次数与成本限制。

需要权衡上述条件或决定启用时读取[重复试验细则](references/repeated-trials.md)，与原评测协议配合。启用后每道题的A、B两组采用相同重复次数，至少各3次；在原授权和预算内冻结次数、并发与停止线。每次从等价初始状态和隔离上下文重新执行，支持并行或分批，不能用重复评分同一答案冒充重复生成。

先按题目和条件观察均值、波动、失败及配对差异，再汇总；重复不能消除题目选择或评委的系统偏差。看过本轮输出后才发现需要重复时，保留原结果，将追加部分另列新设计或探索性轮次，不为分出胜负持续加次数。

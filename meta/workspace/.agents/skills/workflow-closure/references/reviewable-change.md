# 让变更可审查，而不只让检查变绿

交付涉及多个要求/消费者、已有审查漏项，或代码/配置虽通过工具但不确定是否完成用户任务时使用。明确小改直接按宿主验证，不新增固定评审表、Agent数量或批准门。

## 要求与规范分开判断

先固定实际比较对象：必要的基线、当前提交/暂存/未暂存或本次产物。只比较HEAD会漏工作区；对象已由任务明确就复用，不要求用户再指定。需求可来自本次请求、已批准规格或宿主决定，不必为了审查安装跟踪器。

分别回答两类问题，不能用一个总分抵消另一类失败：

- **任务要求**：缺少/部分实现了什么，哪里做错了，是否扩张范围；每项回到原要求和实际消费者/输出。
- **宿主规范**：本范围的权限、版本/来源、数据保全、编码/发布等合同是否满足；引用真实规则。结构异味是待判断的启发，不自动构成硬违例；明确宿主选择优先于通用偏好。

同一发现可以同时影响两类，保留关联即可；缺规格或缺规范的部分标未知，不把缺少标准说成通过。机器已经可靠检查的项目复用结果，不让模型重新抄一份检查器。自审与独立审查如实标注；本方法不自动启动并行Agent，也不把分两栏当独立性。

## 将结论变成可复核的交付说明

说明触发问题与改变后的实际行为，带足够的前后证据和版本身份。复杂的职责/调用变化可选一张最小调用图、差异示意或文件职责树；普通修复不强制画图。截图适合视觉变化，日志/行为断言适合对应机制，不能给所有证据排统一等级。

指出恢复路径、受影响消费者和不可回退部分：能撤销代码不代表能恢复已经发出的消息、删掉的数据或迁移后的状态。原始输入未改、仅改实验副本、已经集成、生产发布分别写清。对未知和失败给实际停点，不用“低风险”概括所有消费者。

## 多仓验证与发布中断

以下为宿主实际修复的补充方法，用于隔离环境、多模块发布或尾部失败；按本次风险选用，普通文档修改不增加整套运行验证。

1. **先确认实际输入。** 大型验证前，用小范围预检核对固定来源、兄弟目录及静态导入、工作区依赖的真实解析目标、子进程实际使用的解释器、文本编码和依赖。Windows检出换行差异按原始来源字节识别；依赖目录可见、环境变量已设置或父进程能运行，都不足以证明测试实际消费了目标版本。前提失败先修对应环境，不启动必然失败的完整验证。
2. **提早核对发布依赖。** 读取真实现网基线、远端引用和各模块安装描述，分别审阅源码同步范围、包内容变化与实际部署集合。模块只选两项，仍可能同步多项历史。固定已验证候选及输入指纹；后续记录提交另行保留，不移动已验证源码来追齐记录。相关输入改变时按宿主规则重验，输入未变且仍覆盖目标的结果继续使用。
3. **从实际完成阶段继续。** 多阶段链路分别核对输入、排除、积压、产出和最终消费，解释材料停在哪一步。发布命令非零时先读真实线上release和阶段结果：网关已切换、尾部运维失败，下一动作是修复并复核尾部。保留原退出码和恢复结果；仅在实际需要时重做部署，不把重复运行整条命令当默认恢复。
4. **绑定恢复对象。** 核验备份ID、内容哈希、来源版本、创建时间、恢复目标和终态的对应关系。原始包与加密包的哈希分开；旧源的成功演练不证明新源/新包可恢复。备份生成、隔离恢复、生产数据恢复和公开查询就绪分别判断。恢复仅写入已授权的目标，缺失、陈旧或不适用的证据保持未知，不能由文件名或一次成功推断全部通过。
5. **用短交接关闭整题。** 一个owner负责本次修复执行，独立验收有明确对象；交接传精确版本、已完成阶段、真实退出码、证据位置、剩余缺口和下一动作。接收者复用证据并验证自己的消费者，避免重复采集、模型、备份或全量测试。收口对照原要求及每级直接父gitlink；独立旧告警仍交原owner，不用全局零告警替代本题完成条件，也不忽略本题的必要依赖。

下次相似交付观察环境导致的完整重跑、重复部署、交接返工和人工介入是否减少，同时核对原验收覆盖。上述方法已有单次实际修复依据，尚未证明跨项目长期节时；预检工具和可恢复发布命令只有实际实现、接入并验证后才记为已具备。

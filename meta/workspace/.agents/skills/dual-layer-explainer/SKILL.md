# 双层解释

## 触发与预期结果

用户需要理解概念为什么存在、如何运作及怎样使用，或明确要求“让我操作看看”“换个条件会怎样”时使用。按已有背景与用途调整深度，使直观认识能够对应准确术语并支持实际判断。用途不限真实机械：算法与协议、检索筛选、推断与信息缺失、游戏资源与事件、任务交接等抽象关系也可进入；这些例子说明理解缺口，不按关键词强制触发。

## 硬边界

- 类比用于帮助理解，不是机制证据；明确类比失效处，不为通俗而抹掉关键限制。
- 时效、版本或高风险事实按所需准确度核查；无法确认的前提明确标注，不伪装成定论。
- 尊重用户请求的深度与节奏，不强制自测、先答题或扩展成课程。

## 方法选择

从用户熟悉的具体问题解释运作，再补足机制、术语与适用条件；已有专业基础时可从术语切入。示例、图示或对应表只在能澄清关系时采用，不必拆成固定两栏。

用户想检验掌握程度，或存在会影响应用的误解时，可给辨析题、反例或最小练习；按需要给答案或反馈，数量随用途决定。缺少背景不自动阻断解释，可先用说明过的合理假设展开。

## 按需交互解释

解释给当前用户听、帮助其自己理解时，若空间关系、状态变化、抽象因果或动手探索有预期增量，可从宿主已配置 Tools home 的 `integrations/anatomy/README.md` 选择已登记的 Anatomy；不可用则继续文字、简图或已有交互能力，不要求安装。技术用法与版本由工具入口拥有，不在此复制；可参考[固定公开工具说明](https://github.com/ZhongTyler/AgentWorkSpace/blob/v1.20.0/packages/tools/integrations/anatomy/README.md)。适合时先看已有样例，再决定复用或定制；官网组件说明不等于本机已安装或验收。

先明确卡住的关系，再选能逐项对应对象、动作、读数与失败条件的表达。按本题选择最小模型，不强制精细机械风格、实体隐喻或部件数量；抽象关系无需原本就有真实机器。操作、画面和数字应消费同一模型，提供本题有用的逐步、参数对照或恢复；只读数变化而实际算法未变不算生效。交互操作沿可用的 interaction-design，不在此复制界面方法。

说明数据与计算性质：真实算法、合成输入、手工特征、示教向量、规则重排和真实模型分别标明。展示影响判断的条件、反例或不可恢复信息，不能以类比替代事实、以同源模型或几何检查证明机制正确。解释页与正式项目/知识库分开，未经对应授权不读取私人资料、接服务或修改宿主。

验证已交付模型的实际操作、结果对应和恢复；用户是否理解、能否迁移与长期省时另行观察，不强制普通解释先答题。用户需要声音或顺序讲解时再考虑短视频，不能把动画运行成功当作理解成立。此入口不自动授权项目修改、对外发布或付费服务。

## 完成标准

解释覆盖用户关心的机制与边界，直观说法和专业术语相容，常见误用可被识别。自测完成与否不作为普通解释交付的门槛。

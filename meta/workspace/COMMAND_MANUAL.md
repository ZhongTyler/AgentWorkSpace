# 风险、交付与恢复

普通任务直接推进；跨仓发布、实质重叠并行写入或长时间高影响工作先记录 owner、范围、基线与恢复方法，并选择独立分支/工作目录。已有受管任务使用原工具恢复，不伪造收据或清除其他任务锁。

## 完成条件

- W0：回答/只读，无空记录和空提交。
- W1：本任务改动、必要引用、相关验证和已授权提交。
- W2：在 W1 上保存实际命中的正式决定、状态迁移或易失证据，不复制到多个台账。
- W3：在 W2 上保留隔离和恢复证据；实现、验证、提交、集成、发布、人工验收分别报告。

用户请求收尾/提交，或已授权任务到达交付时按实际风险闭合；询问进度不触发写入。Git 提交用英文 Conventional Commits。核对实际消息与结果树，子仓逐级闭合直接父指针。现有检查器适用时运行，不适用则说明人工核验范围。最终命令成功不能掩盖前置命令失败。

状态/文档只在因本次改变而失真时更新。项目事实、建议、正式决定、用户体验验收仍由实际 owner 拥有。没有可迁移增量不制造记录。外发、发布和用户数据删除按对应授权，不由收尾自动授予。

## 维护与更新

健康检查按明确范围只读报告；修复与删除须在已授权范围。重复同类失败、实际反例、重要交付或用户要求复盘时检查原因及消费者，不无信号定时空审查。

框架和包通过发布仓 scripts/workspace.py 更新：先计划，处理冲突，保全数据，再应用与验证。未知版本拒绝升级；有本地修改不静默覆盖。升级恢复只回滚本次框架变更。具体操作见发布仓 README 和对应 upgrades 文档。

## 投入与过程检查

长任务或新阶段先明确要关闭的缺口、可交付结果、可复用证据与复看时点。时间、token、执行与返工均有成本；未知消耗保持未知。连续两个可比工作单元没有新增证据、排除解释或可验收进展时，先复查前提与批次安排，合并碎片往返、缩小回传或复用仍有效的检查。调整后看下一阶段的实际结果，不把增加脚本、提醒或局部PASS当作整体提效。

重复的确定性操作可交给已有脚本；目标、解释、语义判断和验收仍由对应owner负责。简单任务不新建流水线、全局监控或逐步审批。

## 停止与决策边界

反复失败的修复、效果不确定的优化或付费实验，先沿任务记录明确待区分原因、验证预测，以及费用、主动工作时间和试验轮次上限；没有可靠读数不编造预算。普通明确修改不因此新增实验流程。

同类路线连续两轮失败、触及既有上限或任务的停止条件时，停止依赖动作，保全现场，报告已用/未知消耗、证据与下一选择，请用户决定。不要通过换会话、模型或新版本重置累计投入；可继续不依赖该结果的已授权工作。必要保全和收尾不等于产品接受。

## Git交付与真实结果

任务完成后按现行授权把分支集成到实际主干，核对真实差异；子仓逐级提交匹配的直接父仓gitlink。推送沿已有授权执行并独立核对远端可达，不把本地提交当成送达。产品发布、部署和删除仍各有对应授权。

清理只针对本任务已完成且不再使用的分支/工作树，先核owner、未跟踪/忽略数据、独有提交和恢复引用；共享、活跃或承载唯一历史的检出保持。应用管理的工作树沿应用归档，其他检出沿Git生命周期；失败保留现场，不强行删除。

# 工程边界指导

这是模板的工程 SSOT；项目可在其基础上增加自己的架构说明。

具体的 Godot 工程组织、场景、资源与验收建议见 [Godot 工程指导](godot-practices.md)。项目按真实需要渐进采用，不把示例目录当作初始化必建项。

## 当前原则

- 玩法规则、状态转换与判定不依赖节点坐标、动画回调、UI 文案或帧时序。
- 表现层消费规则结果并负责输入、动画和反馈；它不能拥有隐式的真实游戏规则。
- 内容配置、运行时状态和持久化数据分开，分别定义所有权和版本变化。
- 模块依赖从具体玩法向基础能力收敛，避免通过全局单例或万能事件总线绕过边界。
- 每个系统说明输入、输出、状态所有者、可观察副作用和测试入口；只有真实需求证明必要时再抽象通用接口。

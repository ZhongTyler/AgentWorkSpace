# 状态维护与防漂移
阶段接受、交付、撤回或重要阻塞改变时执行；纯查询只报告。
1. 先确认状态owner及证据：里程碑工作单拥有产品状态，NOW只保留当前/下一步/恢复，资源catalog拥有用途，安装收据拥有实际安装，历史验证报告只描述当时结果。
2. 更新权威文件，再核对README/NOW/路线图/资源规划中的摘要；尽量链接权威而非复制细节。将逐轮旧“当前/待验”迁到历史区，保留原决定/失败并修复相对引用。
3. maintenance/status-references.json只登记需要联动复核的权威路径、SHA256及消费者路径，不复制状态枚举。权威字节变化时health-check报待复核；人工阅读消费者并纠正后才能更新该hash，禁止为过关直接刷新。
4. 检查消费者中的承诺和证据一致、链接可达、历史不参与当前判断；再运行health-check和相关验证。脚本不能识别全部语义矛盾或判定验收，消费者单独改动也需人工审核。
5. 证据不足保留未知/待验，不替制作人改变决定。学习归因交实际owner，不自动写共享知识或个人记忆。

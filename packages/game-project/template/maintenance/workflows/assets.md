# 资源操作入口

从配置 assets.directory 定位规划、catalog 和规格。新增先登记用途；修改建立新源/工作版本；退役先查引用与安装依赖。源与交付版本不原地覆盖，移动保全哈希和历史失败，旧制作卡改为路由。

通用合同由 assets.workflow_contract 定位；离线不可达时仍可保全/登记/检查，但停止发布，不猜测最新规则。当前本地检查支持清单、来源哈希、精确legacy和新工作台收据，receive/receive-generated→seal→publish复用可恢复事务；按通用合同操作，来源/采用绑定仍由维护显式编辑。

原画、地图棋子、头像按用途分ID和门；外部可商用不代替效果认可。实际安装从引擎receipt读取；catalog只写期望版本。源/完整提示/内部参考不能进入引擎或PCK；插件走工程流程。

变更后运行 health-check；保全/迁移不强制重跑游戏，交付引擎则验证实际资源、回退和包排除。未获效果认可不得标ready。

资源审阅按通用GamePresentation的resource-review.md完成。交付图册同时展示独立资源、实际尺寸及状态组合，逐项检查裁框/邻图残片、透明与锯齿，并验证实际浏览入口。制作人意见绑定资源ID和版本，图册保存在assets工作目录。

## 固定图册与资源操作

项目全资源入口为[assets/index.html](../../assets/index.html)，通过[本机入口](../previews/open-asset-atlas.cmd)打开。新增需求、版本登记、逐项/批量审阅及归档按[项目图册合同](../../assets/specs/project-atlas.md)。需求/版本/审阅写入唯一catalog，实际安装读取receipt，源与release保持不可变。

新增角色、敌人、技能或界面时核对用途覆盖与动态表现需求。交制作人前先完成单体和全部状态的视觉自审，保存问题、修复及实际画面。更新版本后重开对应审阅，归档前解除消费者。服务运行时通过API修改清单，保存冲突先保留输入再刷新。health-check包含图册哈希、引用和状态检查，技术通过后才交当前待审范围。

结构与通用工具更新同步模板和GamePresentation，按各自实际验证记结果。图册功能版本记在assets/atlas-changelog.md，操作历史随catalog保存。

页面级需求变更同步assets/atlas-pages.json及双方关联。图册交互更新检查三行平铺筛选的窄宽屏显示、多选组合、每类独立二级分组及关闭恢复、抽屉连续切换、文件预览和Markdown显示；按模板合同同步通用实现与空页面数据。

工作台自身的功能、结构及接口变更先走[工作台维护](workbench.md)，再核对本流程的资源合同。

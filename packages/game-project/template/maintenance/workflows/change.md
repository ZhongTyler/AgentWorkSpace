# 新增或修改流程

讨论、写Spec或实现前先按 [决定接收](decision-reception.md) 查本功能相关既有决定及当前权威；只讨论真正未定的细则或有证据的新冲突。已定但延期的功能不重复拍板，也不因找到旧方向就自动扩入本切片。

1. 明确本次功能切片的目标、进入／退出、影响模块、验收和恢复方式。
2. 定位产品、工程、交付、验证及决定中受影响的 SSOT；核心体验或范围变化交由用户确认。
   工程结构/场景/资源边界变化时对照 [Godot 指导](../../docs/engineering/godot-practices.md)，记录适用项与必要例外，不强制全量重构。
3. 先处理已证实阻碍本切片的债务，再实现规则、交互、表现、数据与测试。
4. 在实际目标环境验证受影响行为；同步必要的 README 路由、NOW、验证记录和 CHANGELOG。
5. 将单一可恢复的改动范围提交为基线。

当前问题难以观察、复现或比较时，在本切片按需补足开发反馈能力，覆盖玩法/数值/AI/输入/生成/性能/表现等系统。先复用Inspector、参数源、日志、测试与开发预览；不足再做最小入口，不强制面板/Skill。写清参数何时生效，以相同相关条件比较，并分别验证状态重置、参数基线恢复及异步清理；必要时用脚本、模拟或统计而非只看截图。实验配置不自动改变正式决定或存档，开发工具不进入玩家包；共用宿主支持方法可达时引用其当前版本，不复制项目状态。

定义本切片验收、处理反馈或反复调整时，检查观察/调节/复现/比较是否成为瓶颈；有则加载可发现的 `feedback-loop`，按可达宿主支持入口或[本版共用运行反馈方法](https://github.com/ZhongTyler/AgentWorkSpace/blob/v1.14.1/meta/workspace/collaboration/support-and-learning.md#运行反馈按需观察调参与复现)复用或补齐最小入口。缺Skill不阻断直接使用共用方法；已有Inspector/日志/测试足够或只是明确修改时不预建工具。按实际对象验证调整生效、可比较条件与恢复边界，不以加载Skill替代完成。

禁止用未验证的未来通用性扩张当前架构；若设计假设被推翻，记录并回到对应草案或决定入口。

项目资源进入 [资源操作](assets.md)：同步用途清单、版本、引用与门；保留历史和原文件哈希。

定义新切片、重要取舍或反馈推翻假设时，识别项目事实、资料、分析或资源缺口；按需多源探索及反例核对，将实际消费影响写回已有草案/验证。共享方法按可达宿主的支持与学习入口查阅；没有宿主入口时沿本项目既有证据边界继续，不为纯机械修改强制查库。

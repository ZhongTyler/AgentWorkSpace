# 工作台维护

工作台的页面、导航、表单、类型、筛选、接口、数据结构和启动入口发生增删改时，从本流程进入。维护前读取当前工作台合同、数据和已有修改，明确影响面及回退基线。

1. 先更新受影响的职责和数据合同，明确需求、资源、版本及审阅的归属。需求页管理尚无资源产出的条目，全部资源只读展示资源，审阅台填写版本审阅。页面属于资源类型，状态组合沿系统和页面关联。
2. 保存清单和原版本，数据迁移明确映射、兼容及失败恢复。界面调整不能重置用户意见、覆盖资源版本或把机器结果写成人工采用。
3. 实现时检查入口与操作归属、旧服务和旧数据兼容、草稿及并发保存、媒体比例和显示边界。新增写接口复用输入版本与本机会话校验，Agent与人的操作写入同一清单。
4. 全程headless检查受影响行为，通过localhost审查宽窄窗口、抽屉及状态组合。覆盖各工作台允许和禁止出现的表单，需求登记产出后的归属变化，以及页面状态与控件关联。概览与列表复用相同范围，逐进度检查数量及跳转，覆盖旧筛选清除和外部修改后的刷新。媒体归档检查原件、哈希、索引及查阅入口。失败留证，修复后使用新证据目录。
5. 同步模板的通用实现、合同、入口与验证，项目游戏数据保留在项目。分别运行项目及空模板健康检查，更新功能版本日志。识别实际运行的旧服务，说明是否需要重开，保留已保存资料及草稿。
6. 按宿主Git合同提交本任务改动与直接父仓指针。记录技术验证、实际截图自审和制作人待审范围。

资源内容的新增、版本登记与审阅沿[资源操作](assets.md)，工作台功能合同见[项目图册合同](../../assets/specs/project-atlas.md)。

## 目录

无下级目录。

登记梳理按[梳理合同](../../assets/specs/atlas-audit.md)，实施前先写范围、登记边界和验收，健康检查复用独立核对脚本。

工作台已有健康检查。每次功能或登记变更，先更新受影响合同并保存基线，运行登记梳理独立命令与health-check；涉及模型规则时运行test-atlas-audit.mjs，涉及交互时运行test-asset-atlas.mjs。错误阻断依赖交付，警示逐项说明处理或保留原因。组件来源、内容覆盖、历史版本与人工审阅均须核对，禁止通过删除历史记录消除错误。

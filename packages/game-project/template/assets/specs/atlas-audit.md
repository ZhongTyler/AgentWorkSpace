# 工作台登记梳理与健康检查

本次先确定合同，再实施界面与数据修改。概览的制作进度合并为每行一个入口。待确认需求、有需求待制作进入需求管理，待自审、待审阅和需修改进入审阅清单，其余进度进入全部资源。统计取目标视图的同进度范围，跳转清空旧筛选。

## 登记边界

以明确用途登记资源身份，来源、加工和交付属于同一身份的版本。图标集、切图图板与拆出的组件记录来源关系，来源图板不作为待制作或待审组件重复计数，仍能从来源记录及组件详情查阅。整页和控件组合具有组合审阅用途，继续独立登记。

相同图片可用于不同用途，例如头像与地图棋子，但必须说明用途及复用关系。相同字节不直接等于重复，历史版本和来源/交付副本也不自动合并。无明确用途、纯过程产物以及已被组件替代的来源登记保留历史关系，退出当前制作与审阅队列。

程序资源说明触发时机、玩家看到或听到的结果、实现位置及验证入口。仅有需求的条目说明需要什么及验收条件。名称、描述、类型和制作进度须可理解。技术检查通过不改变制作人采用结论，纠正状态必须引用现有采用或退役证据。

## 全量核对

检查每条登记与每个版本的用途、媒体、当前版本、类型、状态、采用依据、来源关系和消费者。对照实际安装收据、交付release、当前引擎资源目录及资源需求来源核对漏登记。扫描媒体区分已登记、已归档和未归属，归档不等于覆盖核对完成。

检查器输出每条登记的核对结果及问题，区分错误、需人工判断及有依据的复用。来源集与组件的父子关系、同哈希复用说明、非图像说明及状态依据可由脚本重复核对。新的异常不得自动补成采用或静默忽略。

## 实施与验收

先保存只读基线与修改计划，逐类解释问题及处理依据。数据修正使用同一存储接口的输入版本校验与原子写入，仅更新审阅过的元数据，保留版本、审阅、门、来源及安装收据。遇并发变更停止写入并重新核对。

独立梳理命令支持只读报告，健康检查调用同一核对函数。通过异常夹具验证漏登记、无说明复用、错误来源关系、含糊程序资源及状态矛盾能被发现，再核对真实项目。浏览器无头检查每个概览按钮的数量与跳转，以及来源和当前组件的分离。结果与逐项梳理记录归项目工作目录。

通用合同、模型与检查同步空项目模板。项目命名、具体修正、采用依据和资源数据留在项目。维护入口为[工作台维护](../../maintenance/workflows/workbench.md)。

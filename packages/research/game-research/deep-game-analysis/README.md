# 游戏深度拆解研究流程

便携方法v1.3。以一款游戏的一份档案为事实源，先盘点全部适用领域，再按问题、证据与依赖分批推进。它是研究协议和辅助接口，不是自动观看或一键研究服务；不附作者私人案例、媒体或验收记录，不声明跨游戏收益。

可直接交代：“研究《游戏名》的……，重点看……，已有材料是……”。先查同游戏、同版本、同问题的档案，重叠时续接原档案。重点决定顺序；局部补证使用focused_extension，分别返回本批回答程度与整作覆盖状态。

## 对象、证据与研究步骤

1. 明确原始完整目标、游戏代际/平台/版本、模式/角色/mod、owner、已有档案、来源和实际预算。冻结本次完整领域基线，逐项列适用、未知、不适用及依据。可用宿主领域导航或Knowledge；没有时按本游戏的系统、表现、制作与体验建立完整列表，不依赖作者知识库或固定域数。
2. 建立核心循环、系统与阶段地图，按依赖推进所有适用领域。正常与会改变判断的失败、资源不足、例外和后期变化按需取证；不以章节数或篇幅证明研究充分。
3. 优先原规则/补丁、开发者资料、公开源码与可追溯实际游戏过程。区分规则原文、实际观察、推断、玩家体验与作者意图。媒体保留来源、实际读取区间、解码画面、前态→动作→反馈→后态；字幕/OCR只作定位。抽帧、连续观看、实际游玩、听音各按真实执行报告。
4. 按[任务与证据模板](templates.md)维护来源、规则、事件、持续状态与稳定结论ID。数字同时写单位、版本、成本、升级/叠加/取整及条件；未知不猜填，同源转载不当互证。
5. 用[主报告模板](game-dossier-template.md)解释具体系统怎样运行、如何形成选择与代价、与其他系统怎样相互影响、何时失效。必要图与证据放在相邻解释处，保留机制链和反例。范围/深度与本批推进顺序分开。
6. 按[内容查证与审计](verification.md)先反查原始目标和重要遗漏，再查事实、来源保真、论证与实际交付物。可用source-fidelity/evidence-audit时按需调用；不可用则就地执行检查并说明，必要证据不足保持partial。自审如实叫自审，独立审计沿宿主真实要求与授权。
7. 返回原报告版本、稳定结论、证据、条件、反例、缺口和恢复点。按[输出合同](output-contract.md)保留本批与整作状态；项目决定由调用方拥有，不能把返回成功当真实采用或效果证明。

## 辅助工具与可选接线

[dossier.py](dossier.py)用Python标准库检查冻结领域、文件哈希、证据依赖、媒体声明和本地链接；可拒绝错游戏/错版本返回、传播partial并生成可校验交付文件夹。它不替研究者判断事实、机制或研究充分性。先运行`python example_dossier.py --output <new-empty-directory>`生成明确标为synthetic的练习输入，再按[输出合同](output-contract.md)运行check、return、export、check-bundle。

Knowledge、Skills、Tools、GameAnalysisDecision和GameHOT都不是必选包。可使用现有浏览器/媒体/计算工具；新增连接、付费服务、采集、模型或调度沿使用者授权，不随安装启动。面向人的表达可按需选择Skills中的human-research-expression，缺少时仍按读者任务组织报告。HTML/PDF只是载体，制作通过不证明理解。

研究档案保留在使用者指定的包外目录，供直接查阅，不作为本流程的Ingest/Raw/Wiki消化任务。可选Knowledge目录必须由接收者显式配置并接受准确版本；本包不携带作者目录、自动登记或写入授权。普通材料研究的知识去向仍沿其原合同。

默认交付文件夹，ZIP仅在用户要求时生成。素材版权与访问许可独立于本包MIT；脚本export是研究交付，不构成公开再发布授权。范围/深度、事实保真、表达、制作/Git及真实采用分别记录。跨游戏复用参见[复用核验](reuse-evaluation.md)。

# 游戏深度拆解研究

当前方法v1.5。一款游戏一份档案，逐层拆解对象与完整子系统，再按证据缺口成批推进；机制、实见、推演与适用边界分别记录。方法更新不代表接收方已完成研究，也不证明整作覆盖、真人体验或节时收益。

## 从真实问题开始

指定作品/平台/版本、问题、重点与已有材料。先查同一游戏、版本和问题的原档案，恢复或补丁式扩展，不重复开批。全作研究先盘点全部适用领域，重点决定推进顺序；局部请求保留其范围和未覆盖状态。详见[逐层拆解与成批研究](decomposition-and-batching.md)、[输出合同](output-contract.md)和[任务模板](templates.md)。

每批明确输入、预期证据、停止条件、已有授权与投入边界。按规则资料、稀疏画面、连续片段、亲玩、听音等真实证据性质判断；没有的维度保持未知，不编成完整体验。研究者自审、外部实质审计与读者接受分别保留身份。

## 制作与检查

已有study.json分节源稿时，`compile_study.py`使用包内版本化的研究表达渲染器制作同稿报告与阅读导航，`workflow.py`协调预检、生成、复用检查、外部审核回执、冻结和交接。运行 `python -B compile_study.py --help`、`python -B workflow.py --help`查看实际参数。它们不研究新事实、不调用模型、不观看游戏、不替代语义审核，也不写Knowledge目录。

流程见[脚本控制](workflow-control.md)、[导航](reader-navigation/README.md)和[查证](verification.md)。`dossier.py`提供原档案/证据图、校验、导出及离线返回；`example_dossier.py`构造合成旧合同示例，供检查兼容。原领域/证据要求继续，返回成功不代表整作研究完成。

## 内容与交接

报告以精简、清晰、有用为目标：保留具体机制、条件、反例及支持链；无增量领域可以不进入读者目录，研究侧完整盘点仍保留以查漏。编辑时选用可用的humanizer-zh、anti-defensive-writing、source-fidelity/evidence-audit；没有可发现Skill时沿包内标准审阅并说明方法缺失，不自动安装或虚称已调用。

默认在使用者指定的包外目录交付文件夹；只有明确要求才另打ZIP。按[关联交接](knowledge-handoff.md)把有用报告交给接收方Knowledge owner；Knowledge缺失时保留完整本地报告与交接数据。研究档案供直接查阅，不整份走Ingest。这里不提供作者真实档案、媒体、目录或既有批准。

公开包保留方法与合成检查，不携带作者的阶段验收快照。v1.5的跨游戏稳定性、真人效果及总成本改善仍需接收方实际任务验证，不能继承作者的模型选择或研究授权。

研究搜集可按可发现的research-collection和game-evidence-collection选择普通材料、源码、发行物或媒体取证，缺少这些Skill时沿本包证据合同执行已有路径。成本与效果沿[研究计量入口](../cost-evaluation/README.md)，新增或改进的解释先回写正文与同源底稿，再更新HTML、领域导读及交互。

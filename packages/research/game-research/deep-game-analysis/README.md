# 游戏深度拆解研究流程

> 方法v0.1。方法与模板已接入；不附私人首例或第三方工具，不声明完整战斗、整局或跨游戏效果已经验收。


## 职责与独立边界

以一款游戏的具体体验和机制为对象，还原规则、状态、选择、反馈及系统耦合，解释成立条件和可迁移边界。由 Research 管理方法和证据报告；它可以独立接受用户的游戏名称、问题或公开视频，也可被游戏研究、专题研究或项目研究按需调用。输入不要求来自 GameHOT，不依赖其标签、分数、采集器或服务。

沿用 [Research 协议](../../RESEARCH_PROTOCOL.md)、[媒体取证](../media-capture.md)、[视频文字](../video-text.md)及宿主可用的知识查询/审核合同，不创建第二套 Wiki、调度、模型服务或入库路径。Knowledge 未安装或宿主暂停写入时，只在原研究报告保留缺口或待消化，不能因调用本流程启动 Ingest。暂停日检不阻止用户明确委托的手动研究；手动研究不记作日检/周研究完成，不改变频率、发现窗口及原 owner。

## 调用与返回

自然语言入口：“按游戏深度拆解研究流程，研究《游戏名》的……，重点看……，已有材料是……”。调用者先查同游戏、同版本、同问题的原报告和未完成包；有重叠就恢复或补丁式扩展，跨专题共享原证据，不重复开批。

使用 [任务与证据模板](templates.md)。调用包至少明确：

- `case_id`、`caller_ref`、`owner`、`game`（作品/续作、平台、版本或 unknown、模组、难度/模式、角色及种子可见性）。
- `question`、`scope`：本次主要问题、体验阶段、重点维度及需要观察到的结果；全游戏请求先做覆盖地图，再分段推进，不能将首段样例宣布为整作完成。
- `materials`：原链接/文件及允许使用的来源；`knowledge_check`：实际查询、来源版本、已有覆盖与缺口。
- `evidence_target`、`stop_condition`：要核验的关键状态变化，何时足以回答；时间/费用上限沿调用方已有授权，没有配额就采用有界取证，不自动加模型、购买或扩大收集。
- `requested_depth`：机制片段 / 会话闭环 / 代表阶段 / 整作覆盖。范围与证据深度分别记录，缺口不能用篇幅补足。

返回同一 `case_id`、报告路径与版本、证据索引、已支持结论、反例/替代解释、适用条件、未知与恢复点、实际成本和调用者所需的案例摘录。状态为 `answered`（约定问题已回答）、`partial`、`blocked` 或 `deferred`；部分回答可以返回，但调用者必须保留范围和缺口，不将返回成功当结论验收。

## 执行步骤

1. **定对象与查重。** 区分观察“游戏系统”还是研究“玩家体验”。读取当前项目与已有研究，Knowledge 先检索相关 Wiki、必要时追原材料；有可用宿主反馈入口时按其合同归并实际消费，未配置时在原报告记录范围，不新增依赖。已有原则不替代游戏的具体规则。版本未知可以探索，但涉及版本敏感规则时明确阻断该结论。
2. **建立体验地图和证据计划。** 用一次初步浏览列出核心循环、主要状态/资源、关键界面和体验阶段。按问题选择正常路径及一个会改变判断的边界：失败、资源不足、替代动作、规则例外或后期变化。不要只看预告、开局教学、成功高光；也不固定要求前三关、五次回放或若干张图。
3. **获取并实际核验多模态证据。** 优先官方规则/补丁/开发者资料，以及保留上下文的实机过程；官方意图和实际表现分开。视频记录作者、发布日期、原 URL、实际观看区间、时间戳、可见版本和断点。逐条读取截图/多图/GIF，动作问题核验前态→动作→反馈→后态及必要中间过程；字幕、OCR和自动摘要只作定位辅助。时间跳转后必须看到已解码游戏画面；封面、缓存字幕、浏览器显示时间均不算对应帧。只抽帧就写抽帧观察，未完整观看/未实际游玩不得自称已经看完/亲玩。音效问题实际听音频；画面不足不能补写操作和情绪。
4. **建规则账与事件账。** 按模板以证据ID链接“所见”“规则原文”“本研究推断”。同时记录时点事件（出牌/点击/结算）和持续状态（状态效果/菜单打开区间），保留界面显示与隐藏/未知信息。数值写单位、基础/升级、条件、取整/叠加、成本与测量误差；算不清就保留未知。跨视频/译文/补丁不能当同一连续局面，同源转载不算互证。
5. **分域拆解并连接系统。** 回答“是什么→怎么运行→为什么形成此选择→条件变化会怎样→哪里可迁移”。规则复述不是机制解释。用状态图、资源流或决策表表达真实复杂点，不强制固定图数。体验、设计意图、商业结果各用对应证据，不能由销量反推因果，也不能由旁观推断玩家真实感受。
6. **反查并交付。** 检查关键结论是否有直接证据，反例是否改变适用边界，是否存在剪辑、遗物、种子、难度、熟练度等替代解释。按约定范围判定状态；补不了媒体则收窄/返回 partial，不把文字摘要升级为媒体核验。把可迁移原则、具体配方、原件工具及待消化内容分别写回原报告。调用者消费结果时记录采用了哪条、改变什么或为何暂缓。

## 拆解维度与覆盖

按问题和宿主已有领域导航选择维度，未安装Knowledge也可独立使用下表，以下是问题清单而非复制域知识。每域记“已观察 / 仅文献 / 推断 / 未覆盖 / 不适用”，并标证据与深度；未覆盖不等于不存在，不适用须说明理由。

| 维度 | 单游戏要核验的具体内容 |
|---|---|
| 战斗 | 状态/目标/行动时机，敌人意图与信息，命中、伤害、防御、失败、顺序及例外 |
| 玩法 | 核心动词、胜负目标、局内/局外循环、选择空间、技能与随机性的作用 |
| 系统 | 资源产消、成长/构筑、奖励、解锁、系统耦合与取舍 |
| 交互 | 信息显隐、层级、悬浮解释、输入/取消、不可操作状态、确认与反馈 |
| 文案 | 规则用词、叙事与机制关系、选项预期、条件和歧义、翻译/版本差异 |
| 数值 | 单位、消耗、阈值、收益、机会成本、叠加与边际效用；不从一局估总体概率 |
| 关卡 | 空间/路径、遭遇编排、教学、难度/节奏与阶段变化 |
| 音频与表现 | 实际可听可见的提示、动画时序、可读性；不以静态截图论手感 |
| 其他按需域 | 主策划定位、运营、工程与架构等须有相应材料；不由屏幕效果臆测内部代码或留存数据 |

再单列跨域关系，例如事件收益→牌组污染→后续抽牌/战斗→地图商店。领域表完整不等于游戏研究完整；整体覆盖至少交代角色、模式、早中后期、失败/成功等哪些已读、哪些仍缺，并围绕实际问题安排后续，不能机械全排列。

## 与现有研究和专题结合

- **日常材料研究**：文章足以回答则沿原流程；主张依赖具体玩法/画面、规则冲突、需要还原关键选择，或专题缺可比较案例时，调用本流程补关键证据。返回原材料包/报告，不另建一轮重叠研究；同批恢复不重复计数。日检不因本流程而主动翻历史或越过原时间/费用门。
- **专题研究**：专题围绕一个问题组织入门导读、案例对读和分歧。调用包只请求本游戏对应的案例切片；专题解释游戏之间条件差异，不要求每个案例先全作拆解。同一案例可被多个专题引用，底层证据与版本只维护一份。
- **独立单游戏研究**：用户可以直接调用，按其授权使用相关历史材料，不等待 GameHOT 新增；按阶段累计案例档案。
- **Knowledge**：确认长期价值、去重、正文/必要媒体完整且写入暂停已获准解除后，才交原单 writer/终审路径。专题和其他发布端只消费允许公开且已审阅的结果；本流程不直接部署或发布。

## 工具与完成门

先复用宿主浏览器、原有媒体/OCR/ffmpeg和公开资料；BORIS 仅在确有长视频事件标注瓶颈时再评估，不是固定依赖。本包不附外部Skill、BORIS或视频模型；外部执行指令不获得宿主权限。

工具可达、图文核验、机制解释、调用方采用及净收益分别报告。至少核对一条核心结论的来源/定位→真实内容→状态变化/规则→结论→边界；同时保留一个不被证据支持的主张，检验流程是否拒绝越界。只有约定范围内这些条件满足才能 answered；不要求固定洞见数、强行负面评价、固定情绪曲线或商业归因。

恢复从原报告与证据索引开始，失效只复核受影响部分。费用/token/人工未知保持 unknown；捕获、检查、方法搭建、局部样例不冒充四轮真实研究。暂停/恢复、来源窗口与内容审核仍由宿主合同拥有。

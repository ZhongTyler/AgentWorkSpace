# 游戏设计与开发中的按需研究支持

本路径把[Research](../RESEARCH_PROTOCOL.md)与[REA工具](../integrations/rea/README.md)用于当前游戏问题，不另建一套开发流程。现有Brainstorm、原型、开发、分析与维护节点只在下一判断有实际缺口时进入；不要求每阶段、每任务或每周探索固定运行REA。

| 缺口 | 按需选择 |
|---|---|
| 项目真实行为、约束或版本不清 | 查宿主代码、配置、运行和用户决定 |
| 经验、案例或反例不足 | 可用Knowledge查询与Research一手材料核查 |
| 设计取舍、因果或系统冲突不清 | 可用GameAnalysisDecision或宿主现有分析方法 |
| 参考机制、开发工具、源码/发行版差异必须查看产物才能回答 | `rea-investigate`，完整源码足以回答时直接读 |
| 玩法效果、平衡或采用价值尚不明 | 获准的原型、真实Play与反馈，不能仅靠静态结果 |

## 入口与操作

需要机制或实现证据时，可按题查[可选固定版本游戏源码参考库](../reference-library/README.md)，选最相关1–2项、实际读模块并引用固定提交与文件位置。先复用宿主事实和Knowledge，结果回原研究/项目；有用知识沿宿主消化与精确终审。安装不下载源码或授权运行，不轮询全库、自动追新或代替真实Play。

用户可直接说“研究这个机制怎么实现，并判断是否适合当前项目”，或点名 `$game-decision-support`、`$rea-investigate`。游戏支持Skill由可选Skills包提供；REA入口由本包提供，安装本包/Skills并不自动安装或启用两项客户端Skill。按宿主实际目录与可发现能力定位，不假定维护者目录、全局工具或其他包存在。缺少模块时继续普通源码、Markdown/网址和公开资料研究，诚实收窄依赖结论。

只在确有产物证据缺口时选定目标来源、版本/哈希、待回答问题、投入预算和停止条件。REA先静态摘要，再精查相关模块并复用Evidence；MCP适合交互追查，CLI适合批处理、保存完整输出、复现或连接回退。未支持、依赖缺失、预算耗尽或无新信息时保留partial/unknown并停止依赖动作，继续独立分析；不为了接线安装一整套原生后端。

## 消费与保存

产物身份、工具版本、证据位置、覆盖/未知及“支持、挑战或改变了哪个判断”写回项目已有草案、Evidence或验证记录。通用结论和可复核实验保存在宿主指定的包外研究目录，不写安装器拥有的modules。工具锁与依赖、私有设置与证据按REA入口的工具保存规范分别管理。

知识采用与工具调用分开记录；有迁移价值的结论交宿主已有Knowledge入库、去重与终审路径，安装包和本路由不授予自动消化权限。不新建重复台账，不把一次调查计为每周探索完成或项目已采用。GAD/宿主负责取舍，原型和真实Play负责体验验证。

运行目标、调试注入、账户访问、额外安装与外发沿原有授权判断。查到规则不代表恢复设计意图；静态识别不到不代表功能不存在。维护者只验证过JS/Electron静态路径，不能据此承诺Unity、Unreal、Godot或其他原生产物可完整分析。本接入的可安装性与路由完整性可验证，实际游戏开发收益仍待真实任务观察。

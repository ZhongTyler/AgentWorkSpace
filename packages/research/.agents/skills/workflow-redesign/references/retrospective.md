# 运行后复盘

用于已经发生的工作：回答旧改进是否生效、本轮结果与流程哪里值得保留或改变、投入是否合理。执行中已出现重复或低增量时也可提前使用，不必等结束。沿原任务记录，简单任务几段即可；不自动新建账本、评分器、Agent或监控。

## 从原任务找证据

先确定原目标、质量底线、覆盖范围、实际交付及本次复盘边界。选取相关旧复盘、采用决定、真实调用／失败／审核／消费记录；不从当前产物反推用户只需要这些，也不遍历全部历史。初次运行或缺少旧记录时标无基线，不补造失败史。复用仍有效的原件，按具体缺项取差异或字段；并行读取也要控制合计回传量，输出截断后只补缺失部分，不原样重发整批。

同时看四件事：结果是否满足目标，流程是否可靠，内容／框架是否帮助组织问题，产物是否被所需消费者正确使用。区分文件生成、实际运行、语义审查、人工体验和实际采用；其中一项通过不能代替其余项。专业判据留在宿主，不把某类任务的UI、知识库、Git或审计门推广成所有任务的固定工序。

回验标准是否按真实用途选择：底线有没有漏掉关键风险，推荐档是否足够支持使用，可选加强项是否被误当必修，额外证明带来了什么决定增量。同一结果不因缺少最高档证据就判失败，也不因成本低就忽略原本必要的验证；用当时约定及实际后果评估，不事后偷换标准。

## 先回验旧优化

对本轮相关的旧改进连接：**原问题 → 当时改了什么 → 本次是否实际调用 → 观察到的结果 → 成本或回归**。没有发生的场景标未覆盖，不算通过；只有规则或Skill存在，不能算执行生效。

结论按实际证据表述为本轮有效、部分有效、未落实／失效、同类复发或尚不能判断。只在可比任务、质量、模型、输入、环境及计量边界下比较效率；条件不同就解释差异，不算节省率，也不把一次成功推成通用收益。

旧问题再出现时，先定位规则缺失、入口未触发、实现未接、实际操作偏离、检查漏项或消费者未用的哪一层。已有规定被遗漏时修调用或执行，不再复制同义规定；单个反例只在其支持范围内收窄旧结论。

## 再检查本轮问题与产出

从原目标反查重要遗漏，随后沿实际输入到交付的关系找原因。区分：

- **复发**：与旧问题同因，原修复没有覆盖或没有执行；说明为什么又发生。
- **新暴露的情况**：输入、规模、环境或消费者不同；旧审查是否承诺覆盖它，不能事后臆测。
- **保护正常触发**：有界失败、拒绝、人工决定或并行版本保护可能正在发挥作用；有等待或报错不等于应删掉该门。
- **记录／判断错误**：统计范围、检查预期或证据解读有误；先纠正结论，不为满足错误指标改产品。

每项重要发现至少能说明证据、影响、原因把握及最小处置。原因未证实时保留假设，修复成功后再验证；不要把所有症状分别升级成新规则。审查自身也要看漏报、误报及未覆盖范围，不能只检查预设成功路线。

## 核算完整投入

跨流程计量、可比单位、效果与后续投入选择按[成本与效果评价](cost-and-effect.md)，脚本复用该处入口。原记录仍是依据，不为历史缺失补造现场计时。

先复用宿主现有日志、成本工具和回执，区分下列口径，不要求每个任务都有全部数字：

| 口径 | 怎样解释 |
|---|---|
| 总墙钟、活跃执行、外部等待 | 起止边界、并行区间和等待分别说明，不能相加重复统计 |
| token／模型调用 | 明确本聊天、子任务或独立协作的覆盖；有输入／缓存／输出数据才分摊 |
| 脚本耗时 | 只解释它实际覆盖的动作，不代替阅读、分析、制作、审核及收尾总时长 |
| 人工及货币 | 无实测保留unknown；用户必要决定不自动算流程缺陷，零额外API调用也不等于零模型成本 |
| 一次性与重复投入 | 分开建设、准备、正常运行、返修和维护；优化本身的阅读、测试和交接也有成本 |

粗阶段混有返修／协作时直接说明，不能将未细分的零值当作未发生，也不事后编百分比。只比较同口径数据。多个阶段都未测token时，不凭字数、命令数或墙钟给token分账。

成本记录与最终内容版本分开。若记录也要提交，事先确定计量终点和末次记账尾段的处置；保留未测区间，不为覆盖最后几秒反复改稿、冻结或提交。没有现成计量能力时给出已知边界与下一次可取得的最小信号，不默认建监控平台。

## 做有限决策，再停止

把必要修复与可选优化分开。优先处理影响正确性、用户目标或反复发生且能低成本消除的问题；比较预期收益、引入复杂度、验证及后续维护成本。证据支持保留现状时直接保留，不能因为复盘发现了问题就要求本轮全部改造。

需要机械化时先查已有脚本及真实消费边界，语义归因和专业质量留给模型／审核者；接线已缺失先接线，不另建一套控制器。实施权限沿用户本轮授权，单纯复盘不扩张为改造或重开暂停任务。

对决定采用的改进说明：改动落点、预计改变什么、保留哪些质量底线、用下一段或下次真实任务的什么证据判断；结果不符时撤回或收窄。只复验受影响关系，不重跑未变全链。前瞻的长期收益仍待验证，不能靠新增Skill或本次自审给自己签效果通过。

交付应让读者看清总判断、旧优化的回验、本轮新增／复发问题、实际及未知投入，以及保留／修复／延后／停止的有限决定。形式按任务裁剪，引用原证据即可；完成必要判断后结束复盘，不持续追加优化、例行复盘或下一任务。

# 深入验证清单

这是 Research 的统一候选索引，覆盖用户给材料后的续试、通用周研究和游戏周研究。只登记仍有价值、能说清验证问题的方向；文章研究完成不等于已经采用或效果通过。各主题报告、实验收据和宿主决定仍是事实维护源，本表只保存选择、触发与去向，不复制执行日志、Knowledge批次状态或项目DEC。

## 怎么进入工作流

1. **开题先查**：用户给材料仍先读材料，再按问题查本表和原报告最新结论；主动探索先看本路线触发条件。复用已验证证据，不重开已关闭方向，不抢已交接或执行中的owner。
2. **按需选择**：优先真实缺口、上行价值与低成本可逆验证。优先级是建议，不是自动排程；通用每轮最多深入一项，游戏围绕一个主题，沿原发现预算。没有条件满足时继续正常发现或结束，不为清单数量强行试跑。
3. **启动前落到原报告**：确认owner和写范围，在该主题报告/实验预案写清最小比较、实际基线、投入上限、成功与停止条件及授权。清单登记不授予安装、外发、付费、发布、修改正式项目或Knowledge终审权限；缺授权只停依赖动作。运行前将条目标为执行中并链接真实恢复入口，不能把计划写成已运行。
4. **收尾更新索引**：先保存原报告的结果、失败和完整成本，再更新本表状态、最后核对日和下一触发条件。按canonical来源、版本和验证问题去重；同一工具的全新用途可另设稳定ID，并说明与原项的区别。既有编号不重用。
5. **使用后再看效果**：技术验证与实际采用、净收益分开；采用后的结果回到宿主原记录。每四次两路复盘时检查本表的积压、重复、触发和实际消费，无实质变化不重发通知。不新增调度，不修改频率；报告沿[简报规则](../proactive/reporting.md)。

日常可说“看看待验证清单，挑一个适合当前项目的低成本项”或“继续指定候选ID”。主体结论过时，以原报告/用户最新决定为准，先修本表索引再推进；接手聊天链接只说明交接，不证明它当前仍在运行或已经完成。用户指定新题优先于队列排序。

## 状态与最低信息

| 状态 | 含义与下一步 |
|---|---|
| 备选 | 潜力已登记，未承诺实施；选题时再核对需求与可行性 |
| 待触发 | 原研究已回答，等待明确材料/业务条件才值得续试 |
| 执行中 | 有真实owner与同一报告/实验恢复入口，先恢复，不另开重叠试验 |
| 已交接 | 由指定聊天/宿主接手；核对原入口后才能改变，未授权不另发消息或接管 |
| 待用户决定 | 写明具体决定及报告/当前精确哈希，不能凭清单代替批准 |
| 观察中 | 已实施或已有观察合同，等真实使用窗口；不冒充净收益成立 |
| 已验证 | 在明示范围内验证完成，保留结果链接；采用、长期效果另由宿主确认 |
| 已关闭 | 本问题收敛或用户停止，保留理由；新证据/新决定才可重新评估 |

新条目用[候选模板](../templates/validation-candidate.md)：稳定ID、主题/路线、状态/优先级、owner、证据与最后核对日、要补的关键未知、review_when、最小比较/预算/停止线、结果去向。没有真实基线或实测成本时写未知，不填估造的节省。新预算是建议上限，不是实际花费；启动前可依当前任务收窄。

安装包使用者在包外研究目录维护自己的清单，并链接自己的主题报告；包内模板和指南不作为可写任务数据。安装不继承维护者的候选、聊天、账号、调度或任何实施授权。

## 使用者的清单

本包不附维护者的私人候选。使用候选模板在包外研究目录建立自己的清单；只在原有研究/复盘时按需更新，不自动创建任务或开始试验。

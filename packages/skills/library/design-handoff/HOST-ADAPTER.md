# Portable host adapter · v1

Apply the original method to the current host's actual design task. `/design-handoff $ARGUMENTS` and `/design-critique $ARGUMENTS` denote the supplied task/input; in Codex use the available Skill or read its entry directly. The attached CONNECTORS.md describes optional categories, not required installations. Use existing authorized tools; local files/screenshots work without a connector.

For handoff, reuse the host's existing UI specification/task record. Distinguish measured/current behavior, proposed changes and unresolved requirements; screenshots alone do not establish hidden states or exact measurements. Cover relevant states and implementation boundaries without inventing new decisions. Map web-specific fields to the actual engine/platform when needed; a small repair need not produce a full standalone specification.

For critique, use the target users, stage and current constraints. Inspect rendered output when available, tie findings to evidence and action, and keep positive observations. Mark contrast, keyboard, touch and screen-reader results as measured, not tested or not applicable; a screenshot is not an interaction test. Review does not automatically implement the recommendations.

Use the host's existing design and task records. A host may also use the optional meta interface method or its own equivalent. Review and handoff do not require meta, Tools, a connector, or another Skill. Connector examples grant no permission to send messages, create external issues, publish, or change approved decisions. Normal implicit selection remains available; apply each method only to its actual review or handoff need.

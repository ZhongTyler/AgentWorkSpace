# 任务小工具：选用、适配与制作

## 从工作障碍触发

执行中发现人反复描述位置/节奏、搬运和修正数据、逐项判断同类候选，或Agent反复改代码才能完成领域操作时，先看哪一步值得变成可复用入口。触发依据是具体障碍和预期价值，不是任务复杂、出现“工具”一词或已经重复固定次数。

在原授权内自主选择并完成最小可逆实现及验证，无需等待用户点名“做工具”。先查现有Inspector、CLI、编辑器、脚本与实际消费者：能直接完成就复用；优先原版直接采用，再比较薄适配与自行制作。综合省下的准备/返修、避免错误与制作/接线/学习/维护成本；一次高代价操作也可能值得做校验工具。只有未来假想用途时，先完成当前任务。

主要缺口是运行状态难观察、调参或复现时，优先用可用的`feedback-loop`及其宿主方法；确需新增工具时在此处理制作，观察/复现规则继续由原方法拥有。需要设计人用交互、长期模块接口或尚未确定的原型时，按具体缺口选对应能力，不默认串跑一组Skill。

## 把意图接到实际结果

先选一个代表任务，确定输入、目标对象和应交回哪个现有消费者。明确工具产物是临时预览、待审候选、数据补丁还是已应用结果，沿宿主原数据源保存。

人用控件、直接操作或表格，Agent用结构化输入、CLI或现有API；两者复用同一操作、校验和结果合同。现成编辑器缺程序接口时，可薄适配它的正式文件格式并验证导入；界面自动化的实际限制单列，不假称已实现无人值守调用。没有人用需求时可只做命令，不为“双入口”强造网页；游戏开发表现工具要求兼容人和Agent时，两条实际路径都验。

工具使用者按当前任务读取与修改获准数据。参数保留单位、范围和生效时点；操作绑定必要的对象身份、输入/数据版本。把结果、错误与未处理项返回给调用方，预览、人工裁决和正式应用沿宿主边界分别处理。Skill不扩大安装、费用、外发、正式决定或删除数据的权限；只暂停依赖缺失授权的动作。

制作涉及参数/空间编辑、内容审阅、批处理或人机双入口时，按需读[制作配方](references/building-tools.md)对应部分；不用先搭通用平台。先让一条操作被实际消费者读到，再增加功能。

## 验证后决定去留

用代表输入完成一次操作→实际消费→结果检查，按副作用核对必要的取消、失败和恢复。保存范围、界面显示、运行状态分别检查；昂贵调用按实际需要限频/取消。只改变显示、下载文件或关闭窗口，均按它实际完成的范围报告。

沿原任务记录比较准备、执行、返修、人工判断和维护成本；未测项保留未知。结果有用且维护合算才保留入口。一次研究样例留实验位置，项目专用工具由宿主维护，跨任务稳定共用后再提取到工具目录；退出时按owner保留必要数据和恢复依据。

交付工具位置、执行/人用方式、实际产物落点、验证范围与收益判断。已有能力足够时交付原任务结果及复用方式，不为证明触发了Skill而另造工具。

# 按问题制作小工具

读与当前缺口有关的部分。它是`task-tooling`的按需实现参考，不规定框架、控件数量或所有任务都要具备的后台设施。

## 选原版、薄适配还是自行制作

先看当前栈和产物：能否直接用、数据能否导入导出、程序是否能调用、许可是否适配，再比较整体投入。初次采用固定实际版本与许可，保留本地修改和恢复方式；研究登记或网页演示不等于已经安装。

| 具体工作 | 原版起点 | 需要自己接的部分 |
|---|---|---|
| 少量数值/颜色/开关控制 | [lil-gui](https://lil-gui.georgealways.com/)、[Tweakpane](https://tweakpane.github.io/docs/quick-tour/) | 实际生效、外部变更刷新、业务保存/恢复；按固定版本用API |
| 参数外还需只读监测与近期趋势 | [Tweakpane Monitor bindings](https://tweakpane.github.io/docs/monitor-bindings/) | 绑定实际消费者的只读值，按观察需求选采样间隔和缓存长度；已有读数已足够时不为换库重建 |
| 引擎内轨迹、范围、场景编辑 | [Godot编辑器脚本](https://docs.godotengine.org/en/stable/tutorials/plugins/running_code_in_the_editor.html) | 原场景/资源身份和编辑事务；直接`@tool`脚本不自动提供撤销 |
| Three场景的对象变换 | [TransformControls](https://threejs.org/docs/pages/TransformControls.html) | 局部/世界坐标、相机输入冲突、导出与重新载入 |
| 反复检查组件状态/操作 | [Storybook](https://storybook.js.org/docs/writing-stories/play-function) | 真实组件、代表数据、操作和断言；一次性页面可用现有QA |
| 分支文本或2D关卡编创 | [Inky/ink](https://www.inklestudios.com/ink/)、[LDtk](https://ldtk.io/docs/game-dev/json-overview/) | 实际运行时导入、数据版本、条件和存档 |
| 持续批量审阅/标注 | [Label Studio](https://labelstud.io/guide/predictions) | 源素材、提案/裁决分离及正式消费；少量任务可用薄页面 |
| 稳定重复的内部数据操作 | [Appsmith](https://docs.appsmith.com/)或现有脚本 | 现有数据/API与权限；把部署、学习、维护计入成本 |

以上是选路实例，能力/许可/资源在具体采用时核查，不默认下载整套。小脚本、引擎内工具和完整编辑器的成本不同；工具列表不能替代当前任务判断。

## 人和Agent共用操作

先复用或提取一个领域操作，例如`applyLayout(patch)`，让GUI与CLI/API调用同一实现。只在适用时包含：

- 输入：目标ID、基础版本、操作及参数；有单位或重建/下一回合才生效的字段明确表达。
- 校验：宿主允许的字段、值及对象依赖；批次需要整体成功时先校验再应用，允许部分成功时逐项返回结果。
- 输出：实际有效值、变更/拒绝理由、产物位置和未处理项；试运行与正式修改明确标识。
- 保存：沿原配置/资源源保存；GUI布局或预设不承担业务数据权威。

Agent可以先生成候选，人再做审美/语义选择；确定性规则由程序校验。用户批准、来源可信程度和工具执行状态分别保留，工具不能用“确认”按钮代替宿主真实审核。是否需要MCP取决于调用宿主，已有命令或API足够就复用。

## 参数、空间和时间编辑

让输入对应可观察结果：轨迹、波形、碰撞范围、锚点、差异或当前有效配置。对昂贵重建，可在拖动结束应用，或提供取消与任务状态，不必每次输入都重算。

空间数据按实际对象和坐标空间绑定；改显示名不应静默指向另一对象。形体/拓扑变化使旧锚点失效时说明重绑需要，不声称坐标可以通用恢复。

代码/API改值后，控件也要反映当前有效值。比如lil-gui需按用途显式刷新或监听；其`save/load`保存的是已添加到GUI的属性，不能据此承诺完整运行快照。运行计时、随机条件、缓存和异步资源按问题分别处理；销毁控件不等于撤销业务修改。

原生面板快照可能依赖控件结构及顺序。跨界面、控件重排或交给Agent时，用按字段名、对象身份和版本校验的业务预设；不要直接将UI状态当通用配置迁移。只读监测应采实际有效值而非回显输入，按需要限制间隔/历史长度，并验证退出后采样确实停止。

尺寸或场景重建会重算参数时，把当前配置重施到宿主的新基准上。例如镜头倍率在resize后先由原场景计算适配窗口的基准zoom，再乘当前倍率，不能反复在上一次结果上累乘。退出时移除本工具增加的监听并恢复声明的表现参数，保留游戏时钟与规则状态；原宿主生命周期回调继续由它拥有。

性能观察也有开销。必要时比较开关工具的影响；预览结果回真实宿主复核，避免用另一套时钟/规则形成假反馈。

## 内容编创、审阅和批处理

内容编辑以领域对象组织，例如“道具表面→扫描文本→触发条件”，让使用者能并排看到相关信息。不要只把内部字段全部堆成表单。

审阅工具保留原件/提案，裁决带对象ID和必要版本。支持实际需要的保留、修正、无法判断与未审状态；一次只处理部分时，未审项仍保持未审。图像、音频和视频判断保留必要原素材入口，标签/摘要不能冒充完整材料。

批处理先选真实样本核对，明确输入选择、重复处理、部分失败和续接含义。需要幂等或防止旧补丁覆盖新数据时落实相应合同；不是每个一次性脚本都要上数据库、队列和账户系统。

## 判断是否值得保留

优先观察它改变了哪个决定、减少了哪段准备/返修，或避免了什么可证实错误。首次搭建与后续使用分别计入；单次运行很快不等于总成本节省，技术PASS也不等于审美或体验合格。

价值不明时先做窄、可撤回的代表任务。无增量就用原路径，记录原因；目标尚未稳定时保留实验身份。已有多位实际消费者、操作合同稳定时再抽取共用实现，不先建设“万能工具平台”。

## WHY的原始参考

- Blackwell/Green，[注意力投资与认知维度](https://www.cl.cam.ac.uk/~afb21/publications/PPIG99.html)，1999：把创建辅助表示的打断/学习成本与未来收益一起考虑。
- Bret Victor，[Learnable Programming](https://worrydream.com/LearnableProgramming/)，2012：让词语、过程和状态可理解，单有实时刷新不足以达成目的。

两者提供分析与设计视角；具体小工具是否省工，仍由实际任务和成本证据决定。

# 角色逐帧动画：生产、配准与动作验收

用于角色形体确需逐帧变化、已有条带提帧后抖动/比例突变，或需要多动作/方向交接时。先复用已接受静态图与现有sprite-pipeline；单体平移、缩放、粒子已足够的切片沿宿主实现，不为普通反馈生成整套动作。

## 固定身份和动作含义

在现有资源规格确定真实显示尺寸、朝向、镜头、动作关键阶段、loop/once、时长/事件点、地面/根节点和恢复姿势。区分动作姿势、图内位移与引擎root motion/物理位移；由哪个消费者负责高度和移动，决定资源应保留哪些位移，不重复施加。

以一张已接受的角色基准图和必要身份参考作为后续生成输入；已确认的造型直接复用，不重新审批静态形象。先做最能暴露风险的动作，再扩展需要的动作集。按动作生成完整条带，减少独立逐帧漂移；整套精确图集用确定性工具组装，不靠生图模型猜每个格子的最终位置。使用当前已授权图像生产者，不因此外发私人参考或启动新付费服务。

把动作写成可观察阶段，例如蓄力→离地→顶点→落地→恢复，以及支撑腿/摆动腿与对侧摆臂。同一角色的脸、服装、左右手和道具身份要能跨阶段追踪。游戏允许的尾迹、落尘等效果按宿主分层和用途处理，不照搬桌宠禁特效的规则。

## 提帧与配准不应改掉动作

先核源是严格等距格、间距浮动的条带，还是带离体组件的构图。只有等距格确实成立才等宽切；连通域提取要把同一姿势的合法部件归组，避免头发/武器被当成下一帧或相邻角色被粘成一组。

全条带使用共同尺度与稳定坐标，保留每帧相对共同参考的偏移。逐帧紧裁后统一贴底，可能消掉原本的跳跃；独立缩到满格会把姿态变成忽大忽小。要保留图内垂直位移时，可使用跨帧共同垂直视口/源坐标，再映射同一变换。若引擎本来负责跳跃高度，资源可做原地动作，但这是明确的宿主约定，不能由提帧器悄悄决定。

按当前安装环境发现可用的sprite-pipeline和create-pet所带原版脚本：格式匹配时复用其稳定提帧、逐状态预览或检查组件；先核脚本实际算法与输入限制。部分通用归一化器固定逐帧贴底，部分Pets工具固定动作名/帧数/192×208格，均不可假定适配任意游戏。保留生成原件，只在派生副本加工；缺脚本时按本方法使用宿主已有处理，不虚报工具已调用。

可复用原件包括`extract_strip_frames.py --method stable-slots`的共同视口提帧、`inspect_frames.py`的空帧/组件/边缘检查和`render_animation_previews.py`的帧时长预览。后两者及Pets布局验证器有固定状态/帧数合同，只有输入确实匹配时原样调用；游戏任务只复用处理组件，不启动create-pet创建流程。任意帧数/尺寸沿宿主元数据适配并核对偏移，不能改名伪装成Pets状态以绕过检查。

## 比例和动作语义须独立检查

外接框、总高度一致不证明头身比、躯干或肢体比例一致。至少在本切片的基准与动作关键帧间对照头部相对身体、肩腰/髋位置、肢体长度和透视，区分合理侧身/屈膝与造型漂移。alpha包围盒可能含头发、披风、武器或特效，作为诊断量使用，必要时改看真实脚/根节点标记；不设通用人体比值或像素阈值。

左右动作只在发型、光照、服装和道具含义仍正确时逐帧镜像，保持时间顺序；否则分别制作。方向按宿主约定区分屏幕左右、角色朝向、行进方向和视线。需要多方向时先定清晰基准方向，再做过渡及闭环接缝；桌宠的16个视线方向不是游戏16朝向行走库。

实际播放本轮动作循环，并检查基准→动作→基准、动作取消/切换和正常用途尺寸。先看动作是否可辨、交替是否成立、接触/离地是否正确，再看裁切、闪烁、配准和循环缝。结构检查、像素连续性、语义自审、制作人接受与实际引擎运行分别保留证据；已知比例或语义失败不能用格式PASS覆盖。

## 像素角色与受光动画分支

先按生产者选路：已有认可的绘制风格沿参考图/完整条带或分层骨骼；风格允许几何体转像素、且需要多姿势/方向复用时，可小试程序化骨架/SDF渲染；专用云生成器沿其动画接口，不让单图接口猜图集。程序化路线要计入角色建模与风格调整，不能把渲染耗时当总制作成本。宿主登记了Tools/sprite-animation时，可沿GamePresentation/adapters/sprite-animation/README.md按需调用同一CLI或画室执行器；未安装或画风不适配时回原生成/编辑路线。查当前工具登记与具体示例许可，展示角色和代码可能不同许可。

**主体占比。** 把基准的主体高度/根节点放进共享变换，目标画布尺寸与主体占比独立约束。若基准在64格中只占44像素，归一化器把其他帧撑满格后再锁回首帧，会造成尺寸跳变；先核实际算法，按共同视口和基准占比加工，再核跨帧形体。外接框含武器/特效时改用身体或根节点标记，不能把44像素变成通用常数。提示要求固定尺寸/首帧，仍需核实际导出字节、尺寸、调色板与循环姿势。

**法线同步。** 彩色、法线与发光层共享帧序、格子和偏移；沿动画生产者保存逐帧时长、loop/once、事件和socket，法线PNG中的默认延迟只作加工元数据。逐帧比较平面、轮廓估计、默认细节，若源有真实几何法线可另作对照；原画明暗推法线会受换色/纹理影响，几何法线也不能消除彩色图里的烘焙高光。以原生尺寸和目标灯光看完整动作及关键阶段，单张受光图不证明跨帧稳定。

**验收口径。** 核QA每个指标的计算对象：只比较方向均值不能证明同方向逐帧稳定；ok可与贴边警告同时存在。目标播放器需实测非等长节拍、末帧保持、循环接缝和取消后不再发送过期事件；记录原生尺寸、实际引擎/渲染与覆盖动作/方向。动画hit信号只供表现同步，伤害等规则由宿主判定。

## 返修与引擎交付

先区分原图身份/姿势错误、提帧/色键/配准错误、播放时序错误和消费者坐标错误。确定性错误先改加工，生成姿势错误才重做受影响动作，保留已通过素材。重复同根失败时按预算换策略，不持续只改同一提示词。

分层切片＋关节/仿射变换可作为已授权风格和素材允许时的修正路线；保持部件长度、关节连接、遮挡层级和左右身份，验证跨动作比例。它可能产生纸片感和关节接缝；源像素分层合成不等于已交付Spine、Godot骨骼或3D动画。没有采用许可或当前切片不适合时继续原路线。

输出沿现有资源catalog/导入合同保存帧序、单格/裁切偏移、原点、每帧时长、循环和事件；导出后核实际编码文件与目标引擎。动画事件消费游戏规则结果，伤害/判定和跳跃物理仍归玩法owner。预览正确不代替实际包验证。

## 来源与适配边界

独立归纳自当前安装的OpenAI work-pets 0.1.6之create-pet、sprite-sheet-contract及稳定提帧/预览/质量脚本，和game-studio 0.1.2的sprite-pipeline；对真实冻结资产的有限原版脚本对照发现了逐帧贴底消除图内位移的反例。方法可独立阅读，原脚本按安装版本发现和调用，不在此复制插件代码、承诺再分发权或保存私人角色案例。

Pets特定行列、九个状态、工作状态名称、16视线、尺寸、Library与上传/激活是其宿主合同，不成为游戏默认布局或新增账号/MCP前置。[官方Pets说明](https://learn.chatgpt.com/docs/pets)说明产品使用；游戏素材权利、角色采用与引擎能力仍分别核实。

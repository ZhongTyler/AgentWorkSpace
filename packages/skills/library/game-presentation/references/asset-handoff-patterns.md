# 素材成套、动画与3D交接配方

生成或接收成套素材、做视频转图集、贴图/GLB接入存在具体缺口时读命中节。复用项目catalog、用途规格、现有生成工具与交付器，不另造资产清单/制作平台或要求所有项目运行完整流水线。

## 成套风格与用途合同

在现有用途规格明确：消费者/角色、目标画面尺寸与锚点、透视/朝向、相对尺度、必要动作/循环、来源与权利、实际交付格式。新素材补缺口，已有用户资源与已接受的艺术方向保持；不把每项都变成生图。

共享风格描述可包括渲染手法、形状/线条、按角色分工的颜色、光照/氛围与可读性。环境、主角、危险和奖励用色承担不同识别职责；不是给所有素材套同一个颜色列表。供应商提示词长度不够时从同一来源派生短版并标记版本，避免两套当前风格；逐字相同不保证生成一致，实际画面优先。不强制固定英文词数、每次重新审批或风格变化就全套重生成。

按实际相对尺度在环境底图上做小型接触表，核对主体是否突出、透视与比例是否一致、状态是否可辨；变化角色/画面再检查受影响部分。2D资产朝向对应实际镜头；3D概念图应提供足够形状信息，但不把等距概念视角强加给游戏镜头。3D改风格时分别看几何、材质和引擎灯光/雾，不用换贴图冒充完整风格转换。

## 人物、姿势与服装参考组合

换装或换姿势会连带改变身份、构图或画风时，把输入职责分开：人物提供身份与比例，姿势提供关节、支撑点与镜头，服装提供版型、层次和材质；先明确哪些特征要保持。人物只有文字时按描述新建角色，不能声称锁定既有身份。

实际提交顺序对应提示中的图号，逐张查看并描述可见关键点；只给两张图就只写两张。姿势参考中的人偶线条、服装参考中的原站姿不应迁入成图。衣服随目标姿态产生遮挡与褶皱，参考图有内容冲突时按各自职责处理，实质设计冲突回原规格。

按工具返回的动态容量选路，不默认塞满参考。本工作区画室FLUX上限4张，Qwen研究配方仍2张；可用“人物身份＋服装＋姿势”，第四张只在细节／风格有独立缺口时加入。两图仍可配文字补充。更多图片可能争夺条件、漏配件或带偏画风；先核资源、实际有序输入及输出，不把张数当作质量。分两轮编辑另查身份和细节漂移，拼接参考板也不等于独立多路控制；普通图片参考不是骨骼、ControlNet深度输入或动画绑定。

选图可按需查[原姿势库](https://ai-pose-gallery.pages.dev/)与[原服装库](https://ai-costume-gallery.pages.dev/)，核来源、具体ID、已有视角和当天条款，再只取本次所需单图；已有合法参考就直接用。两站当前允许单张创作参考（含商用作品），限制批量获取及素材数据本身再分发，并限制实人／未成年用途；素材与代码许可分开核验。聚合库的自建条目可能有不同许可，按条目source/provenance回原作者，不因代码MIT或整库README就批量采用。原参考保留本机制作用途与出处／哈希，不混入可分发资源包。

按需还可查[人像库](https://ai-portrait-gallery.pages.dev/)：正脸用于身份，造型图可能夹带服装／氛围；已有角色优先用自己的角色图。原站声明CC0并请求不要原样转载，分别记录许可与请求，不能把图库声明当作具体成图的权利保证。有宿主Tools时，从参考组合入口（沿接收方维护入口）按明确图号导入／上传，与既有画室和CLI共用；只显式预览、确认职责说明，不自动改写主提示、少传图或失败退纯文字。确认说明后改变图片、图序或职责必须重新核对／确认；历史恢复也保留绑定及来源哈希。未安装此工具时仍按本节手动组织合法参考。

看实际结果逐项核身份／画风、支撑与四肢、视角／裁切、衣物层次／纹样、裤长／鞋袜及必要配件。姿势更准也可能漏手包；一项改善不抵销其他明确要求的丢失。候选不足时沿宿主有界返修和保留原版规则，合格后再按实际用途加工、接入引擎；人物插画通过不能代替棋子、动作连续性或真实尺寸验收。

参考方法：[HongyeMain原版pose-costume-character Skill](https://github.com/hongye007/open-pose-costume-skill/tree/5004fbdb42487cdfe95351b6a41ee11938b33a23/skills/pose-costume-character)，MIT；本节为工作区多参考路径的独立归纳，不附第三方图库、凭据或指定云端生成服务。

## 图集与循环

逐帧角色生成、提帧位移或跨动作比例有具体缺口时，读[角色动画生产](sprite-animation-production.md)；该页拥有完整配准与语义验收方法，本节保留一般图集交接边界。

沿现有sprite-pipeline或宿主制作方法：固定身份、朝向与主体尺度，按动作分开制作。若选择视频取帧，明确镜头/背景与非目标道具是否应保持不动；模型可能仍转身、越界或自行加动作，提示词不是验收证据。原生透明输出可用时优先按实际工具能力选择；色键路线才选主体未占用的颜色，封闭孔洞也要处理，同时防止误删主体同色区域。

跨帧共享裁切/缩放和锚点，不能逐帧自动紧裁导致抖动。非零alpha包围盒可能包含噪点、拖尾或离手物，需对照真实主体、脚底和用途尺寸。循环与单次动作分开；只有确认首尾确实重复时才删末帧，不因生成输入start=end就推定输出逐像素相同。抽帧要保留动作关键阶段，帧数、时长、播放速率与引擎事件节拍一起核对。

图集行列、有效帧数、单格尺寸、锚点、fps/时长和loop/once沿宿主元数据保存；文件名可以辅助识别，不替代已有可靠导入合同。纹理大小按目标设备限制选择，网格/条带各有用途；不能为塞进固定4096而静默改变用途尺寸或丢关键动作。先实际小尺寸播放，再决定是否扩大生成批次。

## 贴图与派生材质

已无缝则跳过接缝修复；只需派生图时保留原底色与尺寸。对新处理同时看：2×2重复、接缝1:1裁片、中心区域、色彩与结构变化。边缘差异/内部差异的比值只是诊断量，平坦图会出现零分母，低比值不证明视觉无缝或材料保真。

按通道直方图匹配不能保证联合RGB调色板精确相同；需要有限调色板就另用明确的色表约束并检查。FFT/亮度平坦化、裁边或最小误差接缝可能改变整图/尺寸，不能承诺只改边缘。由亮度推导normal/height/roughness是风格化近似，不是测得物理材质；与手绘高光、阴影、凹凸方向和引擎约定一起验。法线通道朝向、色彩空间与纹理打包沿目标引擎，不把PNG文件可打开当作可直接交付所有引擎。

有限区域返修时，模型“保持其他位置不变”不够；保留原图，在实际蒙版内合成，再测范围外差异和接缝。使用已审工具前检查尺寸、alpha/颜色模式、处理参数、输出冲突与恢复方式；旧示例脚本没有这些保护时只在副本小试，不默认批量加工已有资产。

## GLB动画与材料

先列本资产需要的骨架/动画/材质语义，再比较导出结果。静态道具不要求skin；角色要核对有效权重、期望clip、持续时间、真实播放和尺度。Blender版本/导出器行为不同，使用NLA等策略前核对实际API，导出后逐项复核，不从“导出成功”推定全部动作保留。

合并动画先确认同一骨架或显式映射：节点显示名可能重复，名字相同也不证明层级、绑定姿态和单位兼容；漏掉目标channel应成为不完整结果，而非成功交付。需支持的插值、变形权重、sparse/扩展与外部资源按实际文件核对，不能把简单读取器当完整glTF验证器。

对疑似导出器的恒定根缩放，先对照基准/绑定姿态，确认是异常常量后才考虑成比例修复相关位移；有意的生长/压缩、非均匀缩放和带切线插值不能按均值归一到1。材质MASK、BLEND、OPAQUE与单双面都有合法用途；只改已诊断错误的材质，不全局强制OPAQUE/doubleSided以“修反法线”。改后保留需要的透明/裁切、深度和阴影语义，并在目标渲染器实际看。

不匹配/脚本退出零/警告/未支持/尚未渲染分别报告。平台输出地址要转为本地可恢复源，账号、服务费用、素材许可和捐赠骨架授权分别核对；不上云或公开部署不能从Skill调用自动获得授权。

## 音频与其他来源边界

现有声音工作台拥有身份、触发/停止、混音和实际听音。可借用“按主要动作、反馈、奖励、环境分层”和短SFX单意图、人物声线一致的提示原则；不固定必须两首BGM/五个SFX。数值dBFS不是实际耳边声压或响度标准，具体电平/压缩/循环缝隙由用途、设备与真实听感决定。循环加淡化可能破坏节拍，不自动认定修复更好。

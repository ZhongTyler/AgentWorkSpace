# 游戏运行时配方

从宿主实际代码、引擎版本与本次问题进入；只补当前缺口，优先用现有引擎的调度、加载、输入和物理能力。此Skill可直接点名，也可由问题触发，不是每次游戏开发的必跑清单。

## 选择本次配方

- 并发加载、失败重试、取消/释放与迟到完成：读[异步资源](references/runtime-recipes.md#异步资源)。
- 快速切场景、旧加载完成覆盖新状态或重复进入：读[场景与清理](references/runtime-recipes.md#场景与清理)。
- 暂停恢复、补算卡顿、刷新率改变速度或循环叠加：读[时间与循环](references/runtime-recipes.md#时间与循环)。
- 多来源同绑动作、失焦后仍移动、按键边沿重复消费：读[动作输入](references/runtime-recipes.md#动作输入)。
- CSS/DPR/相机缩放导致点位偏差、高速漏碰撞、翻面假命中或接触锚点漂移：读[坐标与碰撞](references/runtime-recipes.md#坐标与碰撞)。

- 规则重放不一致、非法客户端动作或隐藏信息发送边界有缺口：读[规则与玩家视图](references/rule-boundaries.md)。

- 匹配分配、重连身份、旧连接迟到或预留席位清理有缺口：读[联机会话与房间生命周期](references/multiplayer-sessions.md)。

- 帧耗时/分配峰值或池化串状态：读[性能与复用](references/performance-and-reuse.md)。
- 浏览器游戏难以复现操作、时间或截图与实际状态不符：读[操作与画面联查](references/browser-replay-verification.md)。

## 使用与验证

先核对宿主已实现的机制和被破坏的条件，再按命中分支修改。Godot的处理/物理回调、InputMap及节点生命周期，Phaser的场景/输入/加载器，Three.js或原生canvas的应用循环分别适配；已有等效能力就补遗漏，不再叠一套循环、缓存、物理系统或ECS。

验证本次对象与真实结果：例如同路径两次调用只加载一次、失败后可重试、释放后迟到结果不再生效、后发场景拥有当前状态、释放一个键仍保留另一来源、缩放后指针落在正确逻辑位置。成功路径、关键失败边界与原有玩法分别检查；重复测试次数由实际异步/输入不确定性决定，不把这些例子变成所有任务的固定验收矩阵。

能修改实验副本时保留原件与差异，正式采用仍沿宿主owner和授权。记录实际选用了哪个配方、改变了什么行为和剩余限制；结构校验不证明触发率，控制状态注入不冒充自然游玩，单题修复不证明跨引擎净收益。纯UI控件状态连续用可用的interaction-design；原因尚不清楚时可先用systematic-debugging；引擎选型回现有game-studio或宿主入口，不强制串行加载。

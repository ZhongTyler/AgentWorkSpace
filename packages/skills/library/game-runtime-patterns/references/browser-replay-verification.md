# 浏览器游戏：操作、状态与画面联查

需要重现一段多步操作、排查错状态截图或比较同一局面时使用。复用宿主已有QA/Playwright/截图器，缺什么补什么；不为一次明确修改建立整套调试平台。

## 一段操作如何形成证据

绑定实际URL/标题、构建输入与目标画布；从真实开始/重置入口进入，执行短输入段，释放输入，停下读当前状态、截图与错误。每段写实际完成数，输出已有时新建runId，不以启动命令或退出0判完成。失败应保留本次错误和产物，修复后新输出恢复。

`render_game_to_text`是可选只读投影：说明坐标系、模式、玩家可见实体、资源/分数和必要时序，不暴露隐藏信息或允许观察者改规则。它必须从当前权威状态生成，不能回显测试请求。文本、画面和实际输入互相核对，任何一项都不单独证明完整可玩。

## 时间只由一个入口推进

需要确定重放时，测试步进调用同一个真实update，测试模式停用并行RAF/计时器；校验暂停、余数、步数上限与非法时间，测试钩子不进正式玩家包。仅等待若干RAF/毫秒不是虚拟时间，按帧等待也不保证不同机器得到相同模拟步数。更改时间策略会影响物理/异步行为，合成时间证据与真实调度检查分开。

相同页面上连续迭代是一次轨迹，不是独立重复样本；独立场景从相同入口重置。测试桥接可驱动实际时间/输入，但直接设置胜利或资源不算自然玩出的结果。比较策略质量才按需使用既有盲评/稳定性方法，不把三个截图当三次A/B。

## 截图与失败门

Canvas的toDataURL可能遗漏CSS背景、DOM HUD或叠层；WebGL保留缓冲、透明像素和空画面也需核。按本题保留实际页面/目标画布截图，实看最新结果；非空像素与PNG可解码不证明内容正确。多画布明确选择目标，不以面积最大猜测。鼠标坐标区分CSS像素与逻辑/相机坐标，键盘先确认焦点；异常时释放按键并关闭本次浏览器。

读错误文件、捕获数、状态断言与最终运行终态；有错误而退出0只能算脚本运行结束。错误去重不能丢掉本次再次出现的重要问题，网络资源失败与游戏逻辑错误分别判断。截图、短片段自动操作和真实人玩/听音/整段体验各有范围。

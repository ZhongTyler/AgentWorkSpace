# 可重放规则与玩家视图

规则与渲染/传输混写导致重放不一致、客户端能提交非法动作或隐藏信息被发出时使用。不是给每个小游戏建立联机后端；若现有宿主已有同等边界，验证本次变化即可。

## 规则核心与外层职责

把配置、初始状态、动作是否合法、状态转换、结束判定与玩家可见视图分别定位。Higgsfield当前资料用meta/setup/validateAction/applyAction/isGameOver/viewFor六个导出表达这组职责，其中meta可为配置；名称和实际签名属于生成项目合同，不是通用API。沿宿主现有文件与接口实现，不要求强制六文件/六函数、无import或改成另一架构。

规则核心接收确定输入，返回新状态/事件；渲染、音效、网络、持久化与时钟在外层。种子/随机状态、合法命令序列、配置和规则版本足以还原时才宣称可重放；禁止Date.now/Math.random只是部分检查，外部可变依赖、别名、迭代顺序等仍可能破坏确定性。JSON可序列化也不证明输入/输出没有共享引用；核对调用前状态和已给消费者的快照不被后续改变。

需要随机时按玩法选择确定性随机流与保密边界；视觉随机与规则随机分开，增加粒子不改变下一次抽牌。可重放PRNG不等于密码学安全，公开seed可能泄露整副牌。重试/联网重放还需外层命令ID、去重、状态版本与顺序政策，不能只依靠纯函数。

## 非法动作与权限

服务器/可信宿主重新核验动作形状、范围、当前阶段、回合、资源与目标可达性；不要相信按钮禁用或客户端给出的最终分数。player身份来自已验证的连接/会话，由外层传入，不接受客户端自行冒充的playerId。限流、认证、房间归属和重放防护仍归外层，不能把validateAction称为唯一防线。

拒绝动作要保留明确原因且不推进状态/消耗资源；apply是否内部再校验或只由可信调度调用按宿主合同决定，不能存在无验证的旁路。纯规则通过不证明WebSocket断线/重连、数据库持久化或多人并发顺序已正确。

## 可见信息是发送边界

按接收者显式投影可见字段，不先广播完整状态再在UI隐藏。卡牌对局通常只给本方手牌、对手数量和公开局面；具体公开范围沿玩法决定。日志、错误、观战/回放、缓存和调试入口也要遵守各自访问范围，避免另一条出口泄露隐私。

投影最好使用白名单；维护内部状态新增字段时不会自动发给所有客户端。返回独立可序列化值，避免渲染/UI误改权威状态。投影中的计数/派生值同样可能泄露信息，按具体游戏的规则和威胁模型判断，不把“没有hand字段”当完整安全证明。

## 核验选择

按本次缺口选择：相同种子/版本/命令序列得到相同终局；增加视觉效果不改变规则随机；非法动作不变更输入状态；多次读取/消费投影不污染原状态；本方/对手/未知身份视图符合约定；结束后拒绝后续命令。只做本地合成合同小样时明确标注，不当作实际联机、真实鉴权或正式游戏验收。

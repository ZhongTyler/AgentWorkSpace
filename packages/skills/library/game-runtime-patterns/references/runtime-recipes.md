# 运行时边界配方

按入口命中节阅读。这些是条件与实现选择，不是跨引擎通用运行库；先找宿主已有对应能力，再选最小补丁。不要为套用示例重写已工作的引擎系统。

## 异步资源

区分已完成缓存与进行中请求。同一身份的并发请求可以共享加载；身份至少包含会改变资源内容的版本/选项，不能只拿展示名称当key。

进行中Promise在成功或失败后都要退出pending，才允许失败重试。清理前确认pending仍指向本次请求，避免旧请求的finally删除新请求。只把仍属于当前代次/owner的成功结果放入缓存；卸载缓存不等于取消网络、解码或消费者。

释放或取消时使对应代次失效，迟到完成只能销毁本次拥有的产物或返回明确的过期结果，不再挂入场景。共享消费者要按引用/所有权保留资源，不能因一方卸载破坏另一方；拒绝的Promise应由调用方实际处理。AbortController等可辅助取消，仍需处理取消前后已完成的竞态。

核验例：同key并发成功只进行一次底层加载；第一次失败后第二次能重试；释放后旧请求完成不复活缓存；旧请求清理不删新请求；其他消费者仍能使用共享资源。只验证本次承诺的所有权模型，不为了测试引入引用计数平台。

## 场景与清理

先决定宿主语义：后发请求优先、串行排队，还是可同时存在的场景。不要把“最后请求获胜”强加给所有游戏。

后发优先时，在await前固定目标与请求代次，完成后同时检查代次及当前owner。过期结果不进入，清理自己拥有的加载产物；不能在await之后只读可变activeScene然后对另一个场景enter。何时退出旧场景按宿主的加载画面/失败恢复需求选择；新场景失败不应无记录地遗留半初始化状态。

清理覆盖本次创建的事件订阅、定时器、动画/循环、音频节点与异步消费者；支持幂等退出和重入，避免旧回调引用已销毁对象。Godot节点/信号与Phaser场景自身会管理部分资源，先核对其实际生命周期，不再对共享对象重复destroy。

核验例：让B先于A完成，只有承诺的赢家进入一次；加载失败仍有可用恢复入口；连续打开/关闭预览后回调数不增长。状态读回与资源计数是工程证据，不替代实际画面和输入验证。

## 时间与循环

先区分渲染刷新、模拟步、动画时间和真实时间。浏览器requestAnimationFrame回调次数随显示刷新率变化，用秒为单位的时间差更新速度；用时间戳前确认与宿主现有单位一致。固定模拟可以用累积器，渲染按需插值，不把每个固定步都另启一条RAF。

首次启动、暂停恢复和失焦时重置/冻结时间基准。选明确政策处理长间隔：暂停丢弃、限量追赶并报告、或权威状态重同步。最大delta/子步数要按玩法决定并暴露丢弃时间，不能静默把回合、经济或联网时间改慢。顿帧、慢动作与表现时间缩放归玩法/表现owner协调。

循环保存request ID/运行代次；停止后取消尚未执行的回调，并使正在执行或旧代次的回调不能续排。start/stop幂等，重复预览不会叠循环，销毁时解除本实例监听。已有引擎拥有主循环时只适配其生命周期。

核验例：相同模拟时长下不同渲染回调密度位移一致；一次长暂停不会无上限补算；stop后状态不再更新；重复start只有一个活动调度链。合成时间驱动只证明算法，至少在目标宿主核验相关真实运行行为，不宣称测得显示器帧率。

## 动作输入

用稳定动作表达意图，保留物理来源集合。Space和J都映射Jump时，释放Space只移除Space；Jump仍由J保持。键盘、手柄、触摸可以汇总到同一动作，但“最大值、求和、最后来源”等模拟轴策略按玩法明确，不能一律OR。

按住状态与pressed/released边沿分离。一次物理事件只产生相应状态转换；固定模拟一帧补多步时，边沿只由规定的一个tick消费，不能每步重放。需要时间戳/队列或缓冲窗口时沿宿主方案；组合键、按住蓄力、coyote time等是玩法规格，不由通用Skill自行添加。

blur、visibilitychange、pointercancel、失去捕获与设备断开按命中输入渠道清理。暂停和恢复明确是否重新采样，避免幽灵按住。只在游戏输入拥有焦点/交互权时拦默认行为；保留DOM表单、菜单、无障碍和浏览器操作。手柄按当前API取新状态，处理断开、deadzone与映射差异，未接真设备不称已验证。

核验例：双键同绑逐个释放；按住切走后恢复；单次确认在多子步不重复；菜单聚焦时游戏不抢输入。合成blur和实际窗口/设备切换区分记录。

## 坐标与碰撞

先标记坐标域：client CSS像素、显示矩形、canvas backing/逻辑像素、世界/相机坐标。原生canvas常用`(clientX - rect.left) * canvas.width / rect.width`映射到backing坐标；若游戏另有逻辑分辨率或ctx按DPR缩放，再转换到该域，不能二次乘DPR。宽高为零、边框、CSS transform、旋转/透视、letterbox需按实际布局单独处理；引擎提供转换API时优先用它。

输入坐标正确后再按对象尺寸/锚点夹取合法位置；球拍中心落在边界不等于整个球拍在场内。缩放和resize后重新取实际rect，pointer lock的相对移动另用对应转换，不能套绝对点位公式。

碰撞区分形状、检测、响应与触发。球心在矩形内是教学简化，不是圆矩形重叠；边界接触是否算命中明确约定。格子整数+比例归一只能处理坐标溢出，不能自动检查所有跨过的墙；高速运动用宿主连续检测、扫掠或有预算的子步。斜坡、单向平台与踩踏要保留方向和前一位置条件。

扫掠前区分真实运动和离散姿态变化。装饰性镜像、换帧造成的锚点跳变、传送或重挂父节点，不能直接把前后点连成物理轨迹；按宿主语义重置该段历史，或在已知事件时刻分段，同时保留真正的位移与当前重叠。整帧跳过“转身时的碰撞”会漏掉同帧真实命中。真实旋转攻击若本来就有连续打击轨迹，应按该轨迹检测；事件时点未知时先确定更新顺序，不猜一条扫掠路径。

嘴、手或挂点需要贴住目标时，以语义锚点解对象位置：先把目标转到父节点局部域，再减去当前旋转/缩放作用后的局部锚点偏移；反向、摆动或父变换改变后重新求解。对象中心放到目标处会让接触点绕目标漂移。优先使用引擎现有变换API，并检查零缩放等不可逆情况；单张图不能验证整个动作。

Bresenham平局选格不保证双向LOS一致；需要对称视线时定义超覆盖/端点/角落政策。零向量角度、静态/零质量、阻尼的大步长也先定义有效域；线性因子`1 - friction * dt`变负会反向，不自动等于想要的减速。

核验例：不同CSS尺寸/DPR下同一视觉点映射到同一逻辑点；四边夹取合法；低速原行为不变，高速不跳过目标碰撞；静止翻面不假命中、翻面同帧真实移动仍能命中；接触点在左右朝向、摆动相位及父变换后仍贴住目标；对称LOS只在宿主承诺时验证双向。没有当前碰撞缺口时保留原引擎，不自行更换物理算法。

# 联机会话与房间生命周期

匹配后接不上、重连串号、旧连接覆盖新连接、预留席位不释放或私有事件误广播时使用。规则合法性与玩家视图沿[规则边界](rule-boundaries.md)，本页补传输会话外层，不要求改用RivetKit或给单机游戏建立后端。

## 先选状态与调度

| 问题形态 | 可借结构 | 适用条件 |
|---|---|---|
| 回合制/私房/准备大厅 | 匹配或邀请入口管理分配，对局管理成员、阶段和规则 | 动作驱动状态，不为“联机”强加高频tick |
| IO/竞技场/大逃杀 | 房间容量与预留席位分开；服务端模拟或校验，快照有版本 | 客户端预测不等于最终权威；混合移动要核速度、时间差、边界和非有限数 |
| 排位 | 排队、对局、玩家档案、榜单职责分离 | 结果写回须可信且幂等；等待越久扩大匹配窗口是产品取舍 |
| 大世界 | 坐标到分区，局部兴趣窗口与跨区交接 | 只有规模需要才分区；两区连接成功不证明跨区唯一归属 |
| 放置/离线推进 | 每玩家状态、粗粒度调度与可信时间补算 | 区分补算、重复调度与存储恢复；不为演示照搬定时频率 |

上游10/20Hz是示例参数，不是统一推荐。全量广播先量实体数、字节/秒与订阅者；按需做差量/兴趣过滤。减少带宽与防止信息泄露是两条不同要求；距离过滤未必符合隐藏信息规则。

## 身份、分配与连接不是同一件事

`conn.id`标识本次连接，`playerId`标识席位；二者都不自动证明账号身份。服务端从已认证会话决定玩家，再验证对局分配或入房票据的房间、玩家、有效期和使用政策。玩家ID可出现在公开快照中，不能同时当秘密凭据。票据应通过该玩家的响应或私有事件发送，不广播后让前端筛选。

匹配器中的分配查询带`playerId + connId`只能约束该查询；对局入口若只认裸`playerId`，仍存在旁路。房间内只读入口、动作、队列发布、事件订阅及内部建人/结算入口分别核权限。不要因为动作主要由另一个Actor调用，就假定外部客户端不能调用；可信服务调用身份与权限沿当前SDK/宿主验证，不以命名代替隔离。

## 把重连拆成可验证的状态迁移

先明确断线政策：保留席位多久、重连是否替换活连接、超时后如何退出或认输。替换时为玩家绑定当前连接/世代；旧连接动作拒绝，旧连接稍后触发的断开不得清除新会话。断线后按玩法中和持续输入，不能让最后一次方向一直驱动角色；重连发当前可见快照和版本，过期命令按既定顺序/去重政策处理。

容量至少区分等待、已预留、已连接、断线宽限与已退出，避免并发请求都看到最后一个空位。预留席位即使从未成功连接也要到期回收；清理仅挂在`onDisconnect`上会漏掉这条路径。房间销毁后还需同步删除匹配索引/分配；在多个对象间写入时考虑超时、部分成功、幂等与补偿，不能把一个队列串行执行当作跨对象事务。

## 用当前缺口选反例

成功入房之外，按本题选：他人ID/错误票据、重复连接、旧连接迟到动作/断开、预留后不连接、断线宽限到期、重复结算、非成员调用内部入口、私有分配事件被另一玩家订阅。异步动作在`await`处仍可能交错，按共享资源和副作用决定串行化/版本控制，不照搬“对局动作无需队列”。

直接回调与模拟时钟只证明局部状态转换；真实SDK测试、本机传输、多端网络、持久化恢复、生产鉴权、规模与真人体验分别保留证据。前一层成功不能晋升后一层。

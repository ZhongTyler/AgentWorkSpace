# 检查回归测试能否拦住这个错误

当新增检查只证明“不报错”、复述被测实现、只验证内部调用，或绿灯与真实失败不一致时使用；不是每次修复都启动变异测试平台。

## 从独立预期观察真实行为

明确用户/调用方可见的失败和测试边界，沿实际接口验证结果；不要只断言某个内部函数被调用。预期来自已知例子、规格、独立参考或有效不变量，不按同一算法重算一次就当独立依据。文字和API名称不同，也可能仍在复制同一错误假设。

外部服务、时间/随机、文件或进程边界可替代；内部真实协作链尽量保留。替身能检查本模块的合同，但不能证明真实SDK、传输或数据库行为。数据库本身就是本次合同对象时可以直接测存储，不把“只测公共接口”变成禁止必要底层测试的教条。

## 有疑问时做一次有界反查

保留原件，在隔离副本选一两个与检查声称能力相关的坏变体，例如删掉最终产物、错版本、破坏关键结果。检查必须因预期原因失败；语法错误、依赖缺失、权限或环境启动失败不能证明测试捕捉了目标。已知正确副本应通过；停止后恢复/丢弃坏副本，保留结果，不污染正式样本或改阈值追绿。

若坏变体仍通过，先核是否该错误属于检查范围：范围内补观察点，范围外缩小声明或选择更合适边界。拒绝合法输入则核误报。选定变体能拦住只证明这些例子，不是全域完备性、正式评测效果或整个修复成功。

修复后的最小例子通过，再回最初未缩减的场景及受影响正常路径；只在新变化或失败理由需要时扩大。需要整个输入域的不变量时按需用可用的property-based-testing；需要策略生成质量比较时沿原盲评/分析方法，不混成单元测试分数。

# 双层解释

## 触发与预期结果

用户需要理解概念为什么存在、如何运作及怎样使用时使用。按已有背景与用途调整深度，使直观认识能够对应准确术语并支持实际判断。

## 硬边界

- 类比用于帮助理解，不是机制证据；明确类比失效处，不为通俗而抹掉关键限制。
- 时效、版本或高风险事实按所需准确度核查；无法确认的前提明确标注，不伪装成定论。
- 尊重用户请求的深度与节奏，不强制自测、先答题或扩展成课程。

## 方法选择

从用户熟悉的具体问题解释运作，再补足机制、术语与适用条件；已有专业基础时可从术语切入。示例、图示或对应表只在能澄清关系时采用，不必拆成固定两栏。

用户想检验掌握程度，或存在会影响应用的误解时，可给辨析题、反例或最小练习；按需要给答案或反馈，数量随用途决定。缺少背景不自动阻断解释，可先用说明过的合理假设展开。

## 按需交互解释

帮助当前用户理解时，若空间关系、状态变化或动手探索能补足文字/简图，可选宿主已配置Tools home中的 `integrations/anatomy/README.md`；未配置则继续原方式，不强制安装。技术用法、版本与恢复由工具维护，不在此复制；可参考[固定公开工具说明](https://github.com/ZhongTyler/AgentWorkSpace/blob/v1.20.0/packages/tools/integrations/anatomy/README.md)。

按本题选择最小表达，不强制机械风格或部件数量。核对类比、简化、条件与读数；需要声音或顺序讲解时再考虑视频。工具/Skills均为可选，安装不自动恢复运行环境、启用客户端Skill、付费、外传、发布或修改项目；动画运行不代表用户已理解。

## 完成标准

解释覆盖用户关心的机制与边界，直观说法和专业术语相容，常见误用可被识别。自测完成与否不作为普通解释交付的门槛。

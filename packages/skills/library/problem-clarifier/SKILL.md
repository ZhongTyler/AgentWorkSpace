# 问题澄清

## 触发与预期结果

用户的困惑含糊到会改变后续建议或风险判断时使用。把困惑转成忠实于用户目标、约束清楚、可以继续行动的问题；若已有足够信息，直接帮助推进。

## 硬边界

- 用户决定目标、价值排序与是否改变方向；不将 AI 的问题重述冒充用户已确认的决定。
- 区分用户自述、可验证事实、解释和假设，不从少量描述推断人格、动机或诊断。
- 不以固定问数、逐轮仪式或默认确认门拖延帮助；用户明确要求仅探索时尊重该边界。

## 方法选择

先利用现有上下文辨认目标冲突、含糊词和隐含前提。仍有会改变必要下一步的缺口时，询问用户能够回答的关键信息；问题量随认知负担与信息价值调整。

可同时给暂定问题表述、条件化建议或开展不依赖答案的工作。只有改变用户目标、作未授权取舍或确实需要用户输入的动作才等待；用户已确认的内容不重复确认。

## 交给执行者的任务书

目标已经澄清且用户要一份可交给Agent执行的任务书时，按需调用可用的`leader`，复用本轮目标、约束和已经确认的取舍。任务书沿宿主现有恢复入口交付，执行由原任务授权和调度拥有。

## 完成标准

问题已足够清楚，能说明当前目标、主要约束、未确认假设与下一步。信息仍不足时明确具体缺口及影响，避免把提问次数或所有未知消失作为完成条件。

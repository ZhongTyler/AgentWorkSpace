# 上下文边界与迁移对照

只有本次问题涉及Agent分工、交接失真、重复读取或可定位的协作成本时读取。以一条实际调用链为单位，先找需要改变的判断或动作；当前单Agent已能完成且无具体缺口时维持现状，不为测试人为造出低效基线。

## 选择职责去向

从真实任务/轨迹记录读取什么、传递什么、谁作下一必要决定以及谁拥有写入和验收，再选择：

| 选择 | 适用依据 |
| --- | --- |
| 保留独立上下文 | 独立盲审或权限隔离有实际目的；长材料独立探索后只需返回少量可核结果；或存在可测的工具/指令冲突 |
| 合并 | 工作高度耦合，反复读相同资料、依赖中间细节，交接没有补足独立性或权限价值 |
| 转为Skill/确定工具 | 独有价值是可复用方法或固定机械步骤，调用方持有原资料即可执行；方法按需加载，硬约束仍在工具/宿主 |
| 作为工具调用 | 专家需要独立上下文，但可从有界输入返回证据、结果、失败与限制；主owner保留综合与交付责任 |

连续出现和高调用频率只产生候选，不证明可合并。先保留正在履行的独立审查、隔离授权与正式终审；角色名、模型自报或多个赞同不能代替独立性。先考虑过滤、检索和分页能否解决返回量，再新增上下文。

## 对照与采用

迁移旧专家提示时检查“局部完成”的停点：哪些内容只是原代理间转交约定，哪些是必须保留的专业条件、权限或独立性。例如“只查订单，物流由另一专家负责”不能原样成为合并后的最终完成条件；明确主循环何时继续取物流、最终必须交付哪些事实，再验证相邻正常题。原卡作为Skill加载和最终信息完整是两件事，不直接拼接旧提示，也不为消除停点删掉真实权限限制。

有真实候选及安全复放入口时，一次只改变一个职责/上下文边界，保留原代码、输入、权限与恢复版本。来源是作者示例、工作区真实任务还是合成变体必须标明；公开真实轨迹的本地投影不等于原运行或本工作区生产验证。

比较实际方案需要匿名独立评测时，复用当前可用的[agent-blind-eval](../../agent-blind-eval/SKILL.md)；已有结果在环境提供时沿`eval-result-analysis`分析，否则按[现有实施与验证细则](delivery-and-validation.md)核对逐题结果和成本，不新增评分体系。是否重复、同次数、至少3次及隔离/预算均由原评测协议拥有，不在此复制另一份规则。可确定性核验的事实/模拟动作直接检查，语义判断与机器检查分别说明。

覆盖由被改链路的风险决定，至少追查会改变本次采用判断的项目：

- 目标问题与相邻原本正常的任务；同一主提示/工具列表改变可能影响邻域。
- 单次运行内的关键身份、版本、否定条件和事实如何穿过必要交接，最终结果/动作是否正确。
- 禁止写入、失败和恢复；低频关键路径不能仅因样本少而排除。
- 每题关键退化、路由漂移、实际调用/查阅/等待/复核/返修与人工；未知token、费用和人时仍为unknown。

集合包含了相同Agent，不证明必要顺序、信息传递或最终结果；不能把不同重复各走一半拼成一次完整覆盖。先读真实任务及写入，不用总体平均分或检查器退出0覆盖关键回归。

关键回归未解决时先修复、限用或撤回；无增益时保留原路径或收窄用途，不持续改题/增评委直到获胜。收益限定于所测输入、模型和投影范围；上下文/调用减少不自动等于总费用、端到端时延或人工减少。授权内的采用按宿主执行，权限、正式决定和发布门不由评测改写。

## 可复用上游

[Anthropic single-agent-loop-kit](https://github.com/anthropics/single-agent-loop-kit/tree/c43796287b83bec847db923f07131d1cc8de750d)，Apache-2.0参考实现，无持续维护承诺。盘点模板、coupling_map、compare和estimate有直接复用价值；采用时按宿主字段薄适配、固定来源并保留许可，不从零重建整套平台。chain_coverage仅作辅助盘点，需核对单次运行、顺序和罕见关键路径。它的Claude命令、固定停问和目录约定不直接成为本宿主合同；不因引用而自动安装、调用模型或授权委派。

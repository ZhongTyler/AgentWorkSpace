# 游戏界面配方：信息、行动与状态证据

当游戏HUD拥挤、重要信息出现时机不对、提示与真实输入不一致，或需要选择径向菜单、冷却、小地图等具体形式时读取对应节。缩放/焦点/菜单流的实现沿可用game-ui-ux，通用连续性沿[交互方法](interaction-method.md)；世界美术、音画素材和引擎交付沿宿主或GamePresentation。一次小修只选命中配方。

## 按玩家决策选形式

| 问题 | 可选配方 | 判断与失败条件 |
|---|---|---|
| 想让信息属于世界，又不能难读 | 世界内UI、空间标记、屏幕叠层 | 看镜头、遮挡、距离与读取频率；关键数值可保留清晰叠层替代，不把沉浸感等同可达性。 |
| HUD一直挡场地，偶尔又找不到状态 | 情境HUD | 区分hidden/peek/persistent/expanded；当前决策、危险和持续比较需要的信息常驻，其余由事件/用户展开，不默认满血就隐藏。 |
| 屏幕边缘或黑边吞掉控件 | 关键UI安全区与布局重排 | 用OS安全区及实际内容变换；关键内容与可出血装饰分层。按显示器保存校准时保留恢复，不能把统一百分比当平台标准。 |
| 键鼠/手柄找不到位置、返回后迷路 | 初始焦点、动作导航与位置恢复 | 用真实支持的输入，恢复有效控件及原滚动/选中身份；简单page controller够用时不强建菜单栈。 |
| 世界在动、效果密集时难读 | 稳定锚点与有层次的文字衬托 | 用衬底/描边/阴影中有效的一种或组合；在真实最差背景与目标尺寸看，不因有描边就判可读。颜色外保留形状/标签。 |
| 既要快速扫读又要精确比较 | glance→focus/hover→inspect | 概览、比较、完整履历分层；键盘/手柄/触控有等价入口，关键数据不只藏在hover或长按。 |
| 高频伤害文字挡住目标 | 伤害数字分型、限并发与聚合 | 保留目标、类型、次数或结算单位中真正影响判断的字段；需要逐次推理时不能只留总数。 |
| 常用行动多，列表往返慢 | 径向菜单 | 按住释放、开关后确认、熟练方向选择分别选型；验证取消/空区/禁用项/方向误选，槽数与慢放不是默认规则。 |
| 不知道为什么技能不能用 | 冷却、资源、目标合法性分态 | ready/active/cooldown/disabled分别表达；进度扫面与精确数字按任务组合，显示真实秒/回合/AP单位，不能把全部禁用原因画成冷却。 |
| 需要方向与目标摘要 | 小地图、局部地图或棋盘概览 | 选择朝向/范围/缩放，分地形与目标层级；只显示玩家按规则可知的对象。已有棋盘足够时不加第二张地图。 |
| 改绑或换设备后按键提示错了 | 动作ID→当前绑定→当前设备glyph | 从实际输入源生成，重绑同步；设备切换防摇杆漂移造成闪烁，不显示尚未支持的手柄入口。 |
| 奖励、警告和成就刷屏 | 分级通知、合并、召回 | 区分必须即时处理与可稍后查看，限并发、按语义聚合；关键事件不能被普通队列饿死，必要信息有稳定历史/详情入口。 |

以上都是可选形式。主信息按该游戏的下一决策排序，不机械将生命值放第一；卡牌、经营中的卡片与表格可以是正确形态。既有艺术方向、输入承诺及正式规则优先。

## 信息职责与必要重复

游戏HUD、菜单、配置与确认界面的标签／提示精简，按[界面文案与信息显露](interface-copy.md)判断删、保留、展开或按状态出现。对费用、单位、冷却和规则例外保留当前决策所需信息，按实际输入提供帮助入口。

当界面靠长说明补足理解、同一内容散在多处时，从当前玩家判断出发，为信息指定主要载体与出现时机：空间位置和作用后果通常由世界/棋盘表达，对象清单用于定位，规则与例外在选中详情展开，当前费用与确认条件在执行处可达。审查删除项时说明它是无决策价值、已由其他载体承担，还是仍需在操作现场重复；精简不等于只剩图标或隐藏必要条件。

比较“玩家不知道规则”“知道规则但找不到对象/后果”“模式冲突导致输入意外”三种解释，再选说明、定位/预览或状态修正。图标承担熟悉对象的快速识别，文字保留准确名称、条件和例外；复杂新符号需要等价的悬停/聚焦说明。全局判断与局部确认按任务归组，确认/取消用稳定锚点，内容变长时不挤走操作。

状态图中的禁用条件须来自最新产品决定；当前实现可能落后于目标设计，二者冲突要记录迁移差异，不能把旧限制或常见游戏惯例直接画成新规则。规则模型与可见状态分开，选择齐全不等于动作一定合法；反过来，规则已允许也不应保留过期禁用。

先用必要的未选中、部分完成、可确认、不可确认和长内容检查这一信息分工，不固定截图数量。交互图只确认结构和行为意图；正式视觉资源按宿主制作、采用、输出、接入流程走。同状态的真实操作、阅读与美术效果另验；图稿获认可不证明少误触、图标易学或跨项目收益。

## 信息披露与高频反馈

先写清某信息何时必须看见、何时可折叠、用什么动作召回。peek由相关事件短时显露，persistent由真实状态或用户固定，expanded用于检查/比较；退出检查后恢复原状态。危险、未知、资源不足和0分别表达。开发工具可见的隐藏信息不能自动给玩家。

通知或伤害合并先定义稳定语义键，例如目标ID＋事件类型＋结算单位；同名但不同目标/结果不混合。聚合保留原事件消费与必要详情，短动画不拖延真实结果。重要程度决定呈现/插队方式，不意味着一律弹模态、配声或抢焦点；频率、并发、停留时间按真实密度调，不固化来源示例值。

在宿主已有通知/日志能力上补缺口，避免同时造第二份事件队列。失败、离开场景、重新开始与资源更新时，清理本轮显示状态；重新进入时从当前权威快照恢复，不能重播所有历史奖励。

## 输入、布局与状态接线

- UI读取宿主权威状态并发送动作意图；状态机、伤害、冷却和权限不在UI重算。初次绑定有快照，离开时解绑，重开后不留旧值。
- 变化数值预留可容纳目标范围的槽位，图标与数字分开；按宿主本地化格式检查多位计时、负值、未知及最长标签。等宽数字有用，整段正文无需等宽。内容变长时优先重排/分层，不靠无限缩字。
- 对齐世界对象的提示处理遮挡、视野外、缩放与密集对象；保护玩家、威胁、拾取物和下一行动所需区域。HUD区域示例不是所有镜头通用的四角模板。
- 触控发与键鼠相同的意图，处理松开、取消、捕获丢失、失焦和页面隐藏；触达尺寸、间隔及安全区按设备验证。需要指针捕获时沿通用方法检查真实坐标与取消，目标不是一张“看起来能按”的图。
- 动作提示采用当前绑定与设备语法。恢复选择/焦点时按稳定对象ID找仍有效的控件；字体、对比和非颜色编码沿实际平台要求，不把来源混杂的字号/比例当合规门。

动画服务于变化因果，快速操作与减少运动仍表达相同信息。径向菜单中的慢放、输入锁定以及世界信息披露会改变玩法，交宿主owner判断；表现请求本身不授予这些改变。

## 把状态清单接到现有QA

从本次变化选择状态×目标视口，而非固定所有平台全跑。HUD可选普通/极值/密集状态，菜单可选打开/返回/禁用；异步资源确有加载/空/失败时纳入。桌面游戏不为凑表增加手机支持。

先用真实输入证明所改动作及返回，再用可复现状态采集布局。命名测试钩子读取已完成的真实状态，不能只回显请求；冻结快照和默认连续运动分别观察。截图实际读图，看文字、遮挡、世界与DOM各层；脚本标签、文件存在、nonblank均不能代替这些检查。

证据绑定当前输入/构建、实际运行页面/实例、状态与截图哈希。旧图不改runId冒充新图；已有验证输入未变且覆盖仍有效时明确复用。未知性能指标显示unknown，不因顶层budget ok就升级为测量通过。结果回宿主原任务，区分工程、真实输入、真人体验和总成本。

重复采集确有成本时，可在接收方工作区按需使用`Tools/integrations/game-ui-capture/README.md`的原版工具与薄适配；不可用时手动采集同一清单，当前设计/QA继续。该工具面向浏览器canvas，不是Godot截图器。实际试玩、声音和连续运动仍沿原宿主方法。

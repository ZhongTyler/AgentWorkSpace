# 界面文案与信息显露

网页、App、工具面板、游戏HUD和菜单出现重复说明、理解依赖长文字，或精简后难以判断下一动作时，读取本页。沿当前视觉风格、业务规则、游戏信息权限与输入承诺做局部调整。

## 先判断一句话的工作

从用户下一动作判断每条标签、说明、提示的用途，再决定呈现方式。

| 用途 | 处理方式 | 例子与边界 |
|---|---|---|
| 重复已经清楚的名称或动作 | 删除或合并，用分组、邻近、间距和动词表达主次 | “重试”旁的“点击即可重试”通常可删；异步重试会重复扣费时，费用后果仍有独立作用 |
| 影响选择或执行的必要条件 | 在决策点可见，关联对应控件 | 必填／可选、单位、格式／大小、默认行为、费用、目标合法性和不可逆后果按实际任务保留 |
| 额外概念、原因或操作教程 | 按需展开，选择合适帮助容器 | 简短补充可用tooltip；有链接、输入或多步内容时用可交互提示层、disclosure或帮助页 |
| 只在特定状态有用 | 随真实状态出现，提供原因与下一动作 | 失败、权限不足、冷却、未满足前置条件分别说明，状态恢复后移除过期提示 |

同一信息在概览与确认处可能各自支撑判断。按任务保留必要重复，不以字数、标签数量或“看起来像AI”定验收。产品介绍、游戏叙事、学习界面等承诺的表达目的继续有效。

## 布局与文字共同表达

先检查层级、分组、对齐、控件选型和动作名称能否解决理解问题，再添加说明。使用当前宿主的视觉体系。保留持续可识别的表单label与可访问名称，placeholder仅补示例或空输入时的帮助；语义不清的图标需要可达的名称和解释。已有共识的符号也要按目标用户核对。

文件限制、价格、单位、默认值来源、执行前提和危险后果往往无法单靠布局表达。把这些信息放在用户需要作决定的位置；禁用按钮的原因与补救路径应能发现。先指出要删改的具体冗余及依据，再调整受影响部分。

## 提示层按实际输入选型

完成任务必需的信息放在操作流程可见处。tooltip用于补充解释，支持实际键盘聚焦及关闭；hover触发时，内容应可移入且持续到用户离开或关闭。触屏提供点击／触摸可达的等价入口，游戏按实际支持的手柄焦点／详情操作实现。短提示承载不了交互内容时换容器。不要给每一条说明机械添加info图标，也不要只凭title属性判可访问性通过。

## 游戏界面的对应判断

规则名称、费用、回合／秒／AP单位、冷却、目标、作用范围、选择后果及例外，只要支撑当前玩家决策就保留在相应载体。概览、选中详情与执行确认按问题分工。不能把所有禁用画成冷却，不能用精简文案泄露玩家按规则未知的信息。按键提示跟随真实动作绑定与当前设备。

## 验证当前改动

复用同一代表内容和业务状态，对照改前后是否仍能判断对象、下一动作、必要输入、结果与失败恢复。按实际受影响范围检查默认、空／失败／禁用、长名称／数值、窄屏及承诺的键盘／触屏／手柄路径。真实状态改变须核是否同步更新。截图可核信息和视觉，运行操作核可达与状态，真人完成率与求助成本另有实测才报告。

最小采用记录回宿主原任务，说明删／保留／展开的关键取舍、验证及未测范围。普通明确的小修直接执行，不要求全页文案盘点、多方案、固定数量截图或新增审核门。

参考包括[W3C表单说明](https://www.w3.org/WAI/tutorials/forms/instructions/)、[W3C hover／focus说明](https://www.w3.org/WAI/WCAG22/Understanding/content-on-hover-or-focus.html)及[NN/g tooltip指南](https://www.nngroup.com/articles/tooltip-guidelines/)。平台能力与实现按当前版本核对，局部验证不等于全站可访问性验收。

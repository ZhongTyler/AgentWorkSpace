# 界面交互设计

当前任务涉及界面状态变化、操作反馈或交互控制时，读取[交互方法](references/interaction-method.md)，只采用与真实问题相关的部分。先确定动作、实际状态和要解决的定位／理解／控制问题，再选择效果；不要求集齐效果或建立工作台。

需要选择控件或具体做法时，按问题读取[交互配方](references/interaction-patterns.md)的对应主题：反馈状态、选择/输入、导航/弹层、对象转场、手势控制、就地操作、可操作图表或动效表达。先比较任务适配和操作成本，再选配方；已有“连续性”等原则不能代替具体选型。普通单处修复只读命中部分，不遍历全部案例。

沿宿主已有规格与QA实现，核对同一对象的身份、选择与焦点，快速重复／反向操作、取消与恢复，以及实际支持的输入和减少运动。方法说明不能代替真实运行；复用输入未变且覆盖仍有效的验证，新增行为验证受影响部分。

网页视觉方向由frontend-design或宿主设计规范负责；游戏资产、音画及引擎交付由GamePresentation或宿主流程负责，不因调用本Skill反向加载整套流程。业务规则、合法落点、存档与体验接受仍由宿主拥有。

结果回宿主已有记录，区分实现、操作验证、用户体验与长期成本。只有观察／调参／复现本身形成瓶颈时，才组合可用的feedback-loop或现有诊断入口；普通静态排版不强制加载本Skill。Skill不可发现时，调用方可读取本目录入口，不猜测另一份方法或自动启动其他Agent、MCP和服务。

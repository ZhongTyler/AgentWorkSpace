# 让图承担解释

先写“读者要从图里看出什么”，再选编码。空间用位置／分层，过程用有时点的状态序列，数量用共同基准的长度或标记，关系用带含义的连线，对比用相同问题下的并列，具体操作用原画面的局部标注。图像没有可解释的工作时，简短精确文字可以更好。

## 完整不等于逐字搬运

把原研究中的独立认识、具体案例、关键数据、反例和未知对应到新解释；重复段落可以合并，重要条件就地保留。历史执行日志、逐帧账目和完整来源身份可放可读补证，不能让读者为理解核心关系重读长篇底本。把图解正文和全文存档分别验收，不能用后者的覆盖率替代前者。

“能用图像解释就不用文字”是本次读者的明确偏好，落实为图优先承担机制，而非删掉条件或禁止文字。标题可给认识，图给过程／关系，短文补归因、限制或判断。避免同一信息先用长文讲一遍、再在图里重复一遍。

## 避免看似图解的文字墙

- 长段拆进卡片、并排很多说明框、贴未经标注的装饰截图，都可能继续把解释工作交给读者。
- 区别在哪里，就把视觉差异放在哪里：生命变化画同一尺度的余额，分裂画对象一变二，随机作用画重复落点，姿态画转换前后预算和风险。
- 图必须有共同基准和明确对象。不要用面积、颜色或箭头偷偷增加原来源没有的主张。
- 图解中的标签在目标尺寸要直接读。网页可为窄屏重排同一关系；放大只辅助查证原画面，不承担主解释的救场。

## 保真检查

视觉符号同样承担论断。并列来源/类别用分组、对齐或项目符号；只有材料支持先后、依赖或因果时才画相应箭头，不让比较列表默认带顺序。箭头与编号/文字之间留出实际空隙；核SVG文字包围盒、连接线和卡片边界，不能只查图是否溢出页面。中英混排中，宽度允许的完整术语保留在一行，长词必须折行时再拆；卡片高度按实际各字号的换行结果计算，并回浏览器检查字体实际尺寸。

箭头究竟表示因果、允许转移、时间顺序，还是阅读顺序？就地说明。离散检查点不能画成已连续观察的曲线；经过重试的一局不能用一条无缺口时间线暗示一次成功。规则推演、观察帧、作者自述、研究者综合和真人反馈分别标明。

先检查不同类型的代表段，如逐步资源变化、非连续成长／机会成本、来源归属与未知。再扩全部范围。审阅时先问图实际解释了什么，再按原机制的输入、作用、收益、代价、反例和未知逐项反查，最后检查目标尺寸与实际读者反馈。只保留“10真言→神性”却删掉“＋3能量、攻击三倍”，即使标题和结论编号都映射到了，解释仍然不完整。图数、字数比例、页数和模型评分不是效果门。

## 可选制作辅助

仅交付HTML时，优先用`scripts/render_visual_html.py story.json --out reader`；不加载PDF依赖。它保留原SVG图形，并支持原画面局部观察、对象标记和空间/余额检查点，输入与约束见rendering。局部观察不改原图字节，关键说明仍直接可读，放大只用于核原件。下面的旧入口适用于确实选择了HTML＋PDF的制作分支。

`scripts/render_visual.py`消费人工编写的story，支持流程／时间节点、余额条、概率条、对象分裂、重复落点、姿态、信息分区、关系和对比等静态形式；宽屏和窄屏来自同一数据。它不自动摘要，不决定研究结论，也不保证排版或读者效果。

输入包含title、short_title、edition、intro、source_hashes、reference_titles、evidence_reader、scenes。每节有id、group、title、lead、visual、takeaway、limits、refs、claims，可选已核image_path／image_sha256／image_caption。原件哈希变更会拒绝；PDF字体需显式传入，输出后实际渲染核对。

长篇的章总览、图解分项和小结，连同分层目录按hierarchy编排；制作输入可用chapters及scene.role表达归属。图的局部解释与整篇连贯性分别检查。

```text
python render_visual.py story.json --out reader --font /local/chinese-font.ttc --symbol-font /local/symbol-font.ttf
```

当前辅助是静态图解报告分支；不替代原研究取证，也不证明演示、动画、交互模型或跨读者收益。方法依据仍见methods中的实际成品与阅读边界。

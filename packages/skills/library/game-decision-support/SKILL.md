# 游戏决策支持

先确认当前要改变的判断。项目行为、约束与已作决定从宿主实际资料核对；经验、定义、案例和来源证词从可用知识库或公开原始材料取得；系统关系、替代解释和投入取舍需要针对当前问题建模。

若有 Knowledge，按其当前 Query 协议发现并读取正文；若有 GameAnalysisDecision，按其 analysis 协议直接分析；若资料或案例仍不足，按可用 Research 协议定向取证。通过宿主 README、模块目录或已审阅的替代能力定位，不假定相邻私有仓存在，也不要求安装全部包。缺少模块时，仍使用项目事实、用户材料、可用公开来源、计算或获准的有界复现，交付条件性判断；缺少来源只收窄依赖结论。

## 发行产物调查

参考游戏的具体机制、开发工具实现或源码/发行版差异，只有必须查看产物才能回答时才转 `rea-investigate`。完整源码足以回答时直接读；仅收到仓库或安装包不自动逆向。Research 可选包的 `game-research/development-support.md` 和 `integrations/rea/README.md` 提供支持路径与接线；按宿主实际安装位置定位，例如 `modules/research`。仅安装本 Skill 不安装 Research、REA runtime、MCP 或其原生分析引擎。

先明确问题、目标来源/版本/哈希和本轮预算。优先静态摘要后精查，复用 Evidence；MCP适合交互追查，CLI适合批处理、复现或连接回退。工具缺失、不支持、预算耗尽或无信息增量时保留 partial/unknown，继续可独立完成的源码或资料分析，不自动安装后端。只调用本轮命中的能力，不把 Knowledge、GAD、Research、REA 串成固定步骤。

把产物身份、工具版本、证据位置、覆盖与未知写回项目已有记录；通用结论和试验保存在宿主指定的包外研究目录。有迁移价值的知识按宿主 Knowledge 入库和终审合同处理。REA静态缺失不等于功能不存在，查到规则不证明设计意图、平衡或玩家体验；本机JS/Electron验证不等于原生游戏已验证。

候选、来源清单、hash 和 prepared 不等于读过材料；专家选择或 request 不等于完成分析。把实际使用的材料、对判断的支持/挑战/改变、适用条件和剩余未知写回宿主已有记录，不新增同义台账。证据足够、信息重复、预算到达或下一证据需要外部条件时停止。

Query 保持只读，不自动入库、改知识正文、执行实验或接受决定。运行目标、注入、账户访问、额外安装和外发沿用宿主对应授权。重要产品取舍、真实 Play 与新增授权仍归用户。方法出现实质反例时交实际 owner 修正或收窄；项目偏好留在项目。

# 从体验目标提出可区分的设计假设

当“无聊/太难/没反馈”等评价不能解释该改什么，或新增玩法与体验目标脱节时，按需用本页；不是给每个游戏套四种玩家类型或新增评分器。已有证据充分就沿宿主执行，复杂因果仍由现有GAD分析承接。

## 三种镜头的不同用途

- **MDA**：从希望产生的体验，追到可观察的行为互动，再追规则/资源约束；也反查规则变化会产生什么动态和非预期体验。Aesthetics指体验取向，不只是美术。它是解释/设计框架，没有公式保证“好玩”。只列机制而不写动态路径，或从奖励数直接跳到情绪，因果仍缺一层。
- **动机需要**：自主看可理解且有后果的选择；胜任看学习、掌握与可归因反馈；关联看共同活动、角色/他人联系。选项多、强制聊天、堆成就不自动满足这些需要。将它们当待验证的解释，不替玩家声称感受，也不从相关研究推出某机制必然提高留存。
- **Bartle**：原讨论针对MUD中的行动/互动、世界/玩家取向。可提醒团队漏看探索、成就、社交、竞争需求，但不是所有游戏通用人格分箱；不能据一个行为给玩家贴永久标签。

## 把模糊评价拆成竞争解释

“太难”可能是挑战过高，也可能是输入迟滞、信息不清、随机性或失败恢复成本；“无聊”可能是重复无决策、目标不明、等待、过易，也可能是不符合目标人群。先看当前代码/事件/原材料，保留能改变行动的反例。不要先加奖励、提难度或动态降难度，再寻找理由。

即时动作确认、结果反馈、长期回报分开；100ms不是谜题、回合思考或叙事回报的统一时限。固定/变化比率与固定/变化时间间隔不同，不能把“随机时刻”直接叫变化比率；随机奖励不自动增加内在动机，也要考虑用户目标与体验代价。

需要落地时，复用宿主已有记录写最少信息：当前目标/材料 → 一个主要因果假设与竞争解释 → 一个能区分它们的观察/可回退改动 → 适用条件/失败信号。已有Issue/ExperimentPlan就补其中，不另造卡片表；真实体验与正式决定仍归宿主/制作人。设计分析、机械检查、真人感受和产品收益分别判断。

## 一手底本与本地验证范围

本页是独立归纳，未复制自定义许可Skill。理论分别追到[MDA原论文](https://www.cs.northwestern.edu/~hunicke/MDA.pdf)、[Bartle原文](https://mud.co.uk/richard/hcds.htm)与[Ryan等2006游戏动机研究](https://selfdeterminationtheory.org/SDT/documents/2006_RyanRigbyPrzybylski_MandE.pdf)。后者研究中的关联/预测不等于本项目机制因果效果。

研究线索为[game-design-theory固定来源](https://github.com/pluginagentmarketplace/custom-plugin-game-developer/tree/aa7edfe267b34eac63d888f60b13e08aca7850ed/skills/game-design-theory)。其design_analyzer.py只返回常量清单，不读取设计输入，也没有实际质量评分或重试系统。六个不同输入的本地运行确认了这一点；本页假设区分案例为作者分析，未做独立盲评或真人验证。

# 反向拆解范例

## 触发与预期结果

用户希望从成品、页面、方案或流程中学习可迁移做法时使用。交付能解释可观察成果的机制、迁移条件，以及对用户目标有用的借鉴方式。

## 硬边界

- 区分材料直接证据、机制推断与作者自述；不臆测内部数据、真实动机或尚未验证的效果。
- 全成品、局部截图与二手描述支持的结论不同；材料不足就限定判断范围。
- 仅分析公开可见或用户有权提供的材料，遵守版权、保密与访问边界；学习机制不自动授权复制受保护内容或对外传播。

## 方法选择

围绕用户想学的内容观察结构、流程、取舍和质量差异。把可迁移机制与案例特有条件分清，解释迁移到用户的目标、资源与约束后哪些部分仍成立。

只有对应用有帮助时才补检查清单、反例、练习或小实验；规律数量和输出形式由证据与用途决定，不为凑条目放大猜测。

用户要求沉淀或复用时，把案例事实和候选方法分开：事实保留原成果/分支/版本引用，方法说明触发问题、改变哪个决定、适用和失效条件。按授权把短指针接到未来任务会读取的现有入口，具体方法交已有Skill或流程owner；不复制完整案例到多个规则文件。后续相似真实任务沿原记录核查实际作用和成本，单次正反馈不提升为普遍有效，也不新增每次任务必填台账。

## 完成标准

借鉴建议能回指具体观察，说明机制为何可能有效、何时不适用以及如何验证；用户能据此采取自己的做法。仅有表面模仿或无证据的作者意图推测不算完成。

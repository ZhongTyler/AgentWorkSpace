# 通用搜集与专业取证的接缝

通用层负责问题拆分、路线、跨材料去重、结束判断和成本观察。专业层负责特定对象的发现思路、身份、获取／阅读步骤与陷阱。研究结论、正式审核、业务决定和知识库维护仍归宿主。

调用传本题对象／版本、用途范围、当前缺口、已取／已读材料与原件、允许动作／来源及投入停点；无需复制全聊天、全部协议或内部数据。

返回要能决定下一步：取得什么、读到哪里、身份是否匹配、支持什么／不支持什么、是否同链、阻塞／替代路径、实际投入与未知。沿宿主原格式，不强制新JSON或登记表。主层不把“工具完成”升级成“问题已答”；专业层不另开全题、不自动入库、不绕暂停来源。

特定官网不必一站一个Skill。优先沉淀“核主体→找规则／补丁／原作资料→关联版本”的思路；只有某平台反复使用、接口稳定且有专门操作时才做适配。新增分支应有实际使用、不同于通用层的约束、清楚返回和实际验证，避免只有名称与清单。

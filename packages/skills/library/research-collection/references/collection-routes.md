# 按缺口选获取路径

优先用宿主已连接能力，不绑定新服务。提供商Skill说明接口，是否需要执行及材料是否充分由本题决定。

| 输入／缺口 | 最小路径 | 加强与边界 |
|---|---|---|
| 已给原文／URL | 读有关正文和必要上下文，保留原位置 | 不完整或重要冲突时回原版／找反例；摘要不替正文 |
| 只有问题 | 用对象、版本、术语与关系检索，从命中取得候选再查原件 | 空结果先核用语、身份和过滤，不推断不存在 |
| 知道官网／机构，不知页面 | 核主体，沿导航、站内搜索或索引找手册／FAQ／公告／原文 | 换域先核归属；宣传、代理、粉丝材料保持性质，不因同标题认同一对象 |
| 仓库／软件／模型 | 固定维护者、commit／release，按依赖读相关源码、官方文档和issue／PR | branch会漂移；源码、发行产物和实际运行分别匹配；不执行未审网络脚本 |
| 论文／统计数据 | 追原论文／数据及样本、方法、日期，必要时核标识和版本 | 摘要／综述不替必要正文；假设和适用范围同行 |
| PDF／截图／音视频 | 实际看有关页／片段及前后过程，保留媒体身份与定位 | OCR／字幕作定位；抽帧不冒充看完，声音需实际听 |
| 多页数据确需完整取得 | 先核分页、字段、版本与允许范围，再有界批量获取 | 本批上限与全集分开；下载全文不等于已读 |

可靠性按主张判断：官方文档说明其声明的规则，作者自述说明意图／经历，实测说明该条件下行为；不能独自证明普遍因果或玩家效果。只有一份关键一手材料时保留单源身份，不用转载凑高置信度，也不因数量不足丢掉关键反例。

需要互补时说明各来源补什么，例如实现与发行配置、规则与操作、意图与观察。分歧先核定义、对象、时间和版本。获取结果已含正文就复用；本地原件先核身份，不顺手镜像整站。

一批结束问：新增支持了什么？还缺哪项重要判断？下次获取能否改变它？说不出增量就停同一路线或换更直接来源，不把“更多材料”当质量指标。

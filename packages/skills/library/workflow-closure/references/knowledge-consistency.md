# 受影响知识面的一致性

本次改变涉及路径、字段、接口、服务名、环境变量、退役符号或交付状态时读取。沿当前diff和已知调用关系选择实际受影响面。

对一个变化串起四件事。

- 哪个现行来源拥有这个事实，以及当前版本是什么。
- 哪些文档、规则、调用方或获准维护的记忆仍引用旧事实。
- 每处应修改、保留历史说明、交原owner处理或等待什么条件。
- 用哪个实际产物、读取入口或已有检查验证接续已成立。

先查已知消费者，再对具体旧符号作定向搜索。历史记录按其版本保留，现役指南应与当前实际一致。仅改一个子项目入口时，继续核它已知的上级摘要和直接消费者。

按真实任务记录代码、运行态、文档、规则、获准记忆与工作区适用面的状态。无部署或无记忆的任务只核其适用面。原报告或恢复入口已经记录状态时就地补足，复用宿主已有状态词。

出现矛盾时先核对象身份、时间和权威归属。源码实现、运行中的版本和对外展示分别取证，保留pending及具体下一动作。机器生成记忆沿平台的现行控制面处理，写入权限由宿主拥有。

完成本段后回到workflow-closure原闭合路径，继续处理实际提交、父仓、远端及发布判断。新发现对原要求的影响和规范符合度仍沿reviewable-change核对。

# 工作流收尾

这是现有收尾合同的薄触发层，不拥有第二套规则。触发后先定位宿主当前权威的 `COMMAND_MANUAL.md`，并按目标项目合同补足项目专属门；worktree中的旧合同快照不能覆盖现行主干合同与当前用户约定。若入口不存在或互相冲突，明确报告，不能凭本 Skill 猜测放行。

## 判断是否执行

- 用户明确要求“收尾”“提交”“完成并提交”“暂停并交接”时执行；同义的明确行动请求等同处理。
- 已授权任务自然到达最终闭合阶段时，可用本 Skill 判断 Gate B 和完成面；合入、推送与清理沿权威合同中的用户持续授权及本次例外执行，不扩张到无关仓库、产品发布或用户数据删除。
- 用户只询问流程、进度或审计历史时不执行写入式收尾；只按事实回答。普通实现、测试和中间 checkpoint 也不因涉及 Git 自动触发本 Skill。

## 闭合路径

准备暂停交接、换会话或上下文重置时，若有需保全的任务状态，读取可用的`session-handoff`（不可发现时见宿主Tools/skills/hero/README.md），用prepare更新原恢复入口；接续指定交接时用continue核对当前产物再行动。它负责上下文与停点，本Skill继续负责Git和完成面；普通进度询问或无状态损失的简单继续不新建交接文件。

1. 读取当前权威入口和目标项目合同，确认本次 scope、owner、现有 dirty/index、并行工作及授权边界。无关改动保持原状。
2. 根据实际产物与风险判断 Gate A 和 W0-W3；标签不能替代事实。先完成受影响行为的必要验证，检查真实退出码，失败只阻断依赖动作。

   涉及异步构建、部署或后台服务时，先用必要的提交／产物版本、任务ID或实例标识核对本次对象，再有界等待终态并验证实际结果；启动成功、最近一次成功或旧进程不能代替本次完成。超时保留未知、停点与恢复入口；输入未变且仍覆盖目标的有效证据可复用。
3. 按 `COMMAND_MANUAL.md` 的“W2 · 只处理真实命中的需求”分别核对项目事实/已知状态消费者与制作人/AI观察候选。回看本次交互中的目标与取舍、验收口径、原则表达和纠正，沿宿主根 `collaboration/support-and-learning.md` 的“交互学习与沉淀归属”判断增量及实际owner，在授权内落地，并在后续真实消费命中时回看使用、效果与反例。项目有记录不能代替信号判断，子项目已更新不能代替相关摘要核对；同类候选只补真正的新证据，无合适信号直接略过。具体落点、状态和边界由原合同与owner拥有，Skill不另设逐轮总结或观察要求。项目人工门、正式决定和真实 Play 仍由原 owner 判定。
   路径、字段、接口、服务名、环境变量、退役符号或交付状态变化时，按[受影响知识面核对](references/knowledge-consistency.md)追踪权威来源、过期说明和实际消费者，在原记录保留处理与验证结果。

4. 对本次变更做下述“对外内容影响检查”，先判断 AgentWorkSpace，再基于其实际结果判断个人网站；只沿实际关联读取，不全仓扫描或自动同步。
5. 需要提交时，每个改动仓形成范围明确的结果提交。提交前用 `WorkspaceOrchestration/scripts/execution-check.py message` 校验完整消息，提交后回读实际消息；检查器不可用时按 `COMMAND_MANUAL.md` 人工核验并标为未机器验证。
6. 工作已完成且位于分支/worktree时，按 `COMMAND_MANUAL.md` 的“Git交付：合入、推送与清理”合入项目实际主干并核对最终集成结果；冲突或结果变化按影响复验。暂停/checkpoint保留工作分支，不冒充主干完成。
7. 子仓结果提交不是终点。逐级提交每个直接父仓中匹配子仓最终主干结果的 `160000` gitlink，直到最外层目标仓；用 `execution-check.py closure` 核对实际结果提交与所有父边。父指针只暂存、指向不匹配或未提交都不能报告 Git 闭合。
8. 按同一Git交付合同，在提交/集成后由子仓到父仓推送任务结果，独立读回确认远端可达；沿用已有授权，不停在“已提交”。显式不推送或缺远端等例外据实保留，不以打包完成或启动成功替代送达。
9. 集成、验证、父边和远端确认后，判断本任务临时worktree/分支是否需要清理，按合同检查owner、数据和恢复点后回收；不再需要的清理，仍占用、未合入或有恢复依赖的保留并说明原因。
10. 暂停交接时保全 owner、scope、停点、恢复入口和下一动作，不把 checkpoint 说成完成。最终分别报告实现、主干合入、父仓闭合、推送、清理/保留、状态迁移、对外同步、产品发布和人工验收，未执行项保持未执行。

当交付跨多个要求/消费者、审查曾漏项、多仓验证前提不明、发布中断，或工具通过却不能证明任务完成时，按需读[可审查的变更](references/reviewable-change.md)，核对任务要求、实际输入和完成阶段，再组织必要的前后证据/恢复说明；明确小改不增加固定评审或审批。

## 对外内容影响检查

这里的 **AWS 指 AgentWorkSpace 发布仓**。个人网站也会展示 AWS，处理顺序是“来源结果 → AWS 更新判断与授权范围内的交付 → 个人网站最终更新判断”。AWS 的发布版本、能力说明、链接与验证边界确定后，网站才据此更新相应展示；AWS 尚未发布时，网站不得把本地结果写成已公开可用。与 AWS 无关的网站内容按自身来源处理，无需等待无关的 AWS 动作。

收尾时先用本次实际 diff、结果与已有消费关系判断关联；无关联时简述无需更新即可，不为检查而打开全部包、网站模块或联网查询。

| 目标 | 何时需要进一步核对 | 按需入口 |
|---|---|---|
| AgentWorkSpace | 变更涉及已发布的框架、Skill、工具或业务包，可能影响公开能力、用法、依赖、兼容、许可或缺陷；或形成值得公开复用的新能力 | `AgentWorkSpace/AGENTS.md`、`README.md`，对应来源的 `release-input/manifest.json`、`curated/` 与目标包、发布标记 |
| 个人网站 | AWS 的实际对外结果影响网站展示；已展示项目的介绍、状态、链接、截图或演示因本次结果失真；已接入模块消费的源内容或行为发生相关变化；或出现值得新增展示的成果 | `PersonalSite/AGENTS.md`、`maintenance/README.md`，对应 `modules/*/module.json`、页面或源同步契约；实际命中网站时读展示核对与交付路由（沿接收方维护入口） |

网站的 AWS 展示已有正式入口：`PersonalSite/modules/home/site/index.html#tools` 与 `agent-workspace.html`。核对首页概述、包入口与详情页的版本和能力说明；实际版本、包数量、公开文件集合及上线状态每次从网站与来源契约读取，不在本 Skill 固化。缺少对应入口或证据时保留待接续及下一条件，不把未知写成无需更新。

**先判断内容，再判断动作。** 对实际关联项核对“来源变化 → 当前对外版本 → 受影响内容”，给出更新或无需更新的具体理由。来源 HEAD 更晚、内部记录增加不等于发布内容过期；版本化快照和历史验收保留原语境。新能力或新成果若尚未选定为公开内容，列为候选并说明受众价值与证据，不自动加入包或网站。展示结论不得超出已验证事实，工程 PASS 不升级为真实使用、体验或长期收益。

**遵守目标自身的维护方式。** AWS 正文先在来源维护，经公开边界审阅进入便携输入，再按现行发布工具生成；不直接修补发布副本，也不刷新旧 `released/` 或 tag。网站公开主页与私人模块分别按契约处理：公开素材只取已允许公开的内容，私人数据仍留在原 owner 与授权访问范围内，不复制成新的事实源。既有 owner 分工有效；未经用户授权，不向其他聊天发送交接消息。

**复用已有授权，明确剩余阶段。** 对外内容检查不扩张跨仓编辑、产品发布或部署权限；任务Git推送沿上述持续授权，其他已有覆盖目标和动作的授权继续执行，不重复询问。需要更新时，先完成已授权的来源修正、可审阅方案或本地改动及验证；只有下一必要动作确实缺授权才请求确认。缺少目标仓或当前版本证据时明确待核对，不能推断无需更新。

最终按 AWS、个人网站的顺序各给出简短结论：无需更新及理由，或需更新的具体来源/目标、已完成阶段、剩余动作及原因。网站依赖未发布的 AWS 结果或未建好的展示入口时明确待接续，不把检查完成说成同步完成。命中 W2 时沿 `COMMAND_MANUAL.md` 使用既有状态，待办保全到所属项目已有恢复入口并给出 `review_when`，不新增第二份流水。未授权的对外阶段不阻断独立的本地收尾，但本地已提交、AWS 已生成、远端已推送、网站已部署和线上已复核必须分别据实报告。

## 完成条件

完成声明只覆盖本次授权范围，并且与实际文件、检查结果和 Git 历史一致。必要验证和结果提交、已完成工作的主干合入、各级父边及远端送达均有实际证据；临时worktree/分支已按需清理或说明保留原因。显式例外、失败、并行dirty、待接续、未推送/未发布及项目专属验收边界分别保留，不把本地提交说成整条交付完成。

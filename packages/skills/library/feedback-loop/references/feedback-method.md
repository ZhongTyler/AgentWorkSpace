# 观察、调参与复现

当当前行为难以观察、同一问题难以复现，或反复调整却无法比较结果时，把缩短反馈循环作为本次交付的一部分。适用于玩法、经济与成长、AI行为、输入、关卡生成、性能、表现和音频，也可用于其他开发任务；不是只有视觉变化才需要。已有证据足够或一次明确修改可直接验证时，不额外造工具。

- **先确定问题与观察量**：要判断什么、当前版本/有效配置是什么、什么输出能支持或推翻判断。按问题使用状态、事件日志、数值轨迹、输入记录、统计/性能指标、声音或画面；不把可见变化直接等同改善。
- **复用再补缺口**：先找现有Inspector、控制台、CLI、固定场景、测试与预览。只有它们不能回答当前问题或准备成本明显过高时，才补最小入口；可以是脚本、参数文件、模拟器或面板，不固定滑块数，不要求每个项目一套工作台，也不要求增加Skill/MCP。
- **参数与对照相符**：参数保留单位、范围、约束和生效时机（即时、下一回合、重建对象或重开）；实际消费者必须读到新值。固定与问题有关的输入、场景、版本及必要随机条件，记录真实差异；多系统必须联动时保留依赖，不机械要求一次只能改一个参数。无法保证同输入复现时说明随机/外部条件与样本限制。
- **分开恢复状态和配置**：重开一局未必恢复参数默认值，恢复参数也未必重置计时器、缓存、监听器或随机状态。预设、基线恢复与重放按真实需要提供；有异步/缓存时验证重复运行及退出后的清理，不能只复原一个显示值就宣称重置完成。
- **隔离实验与正式采用**：在原授权范围实现和验证。表现调参保持规则不变；玩法/数值试验可调整已授权实验配置，但不自动改正式决定、原存档、冻结包或其他owner数据。测试/GM状态和正常玩家路径分别标明，开发入口不泄露隐藏信息或混入正式玩家包。
- **以净反馈决定保留**：用一次实际调整→观察→复现/比较→恢复验证入口可用，结论沿宿主原验证记录保存；再观察准备、返工、人工判断与维护成本。结构检查、面板存在和局部指标改善不等于体验成立、全局最优或长期提效。没有增量、维护抵消收益或越界就收窄/撤回，产品取舍仍由原owner决定。

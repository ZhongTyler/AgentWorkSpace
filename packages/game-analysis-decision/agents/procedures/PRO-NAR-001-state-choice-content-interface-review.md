## 适用与输入

用于叙事信息、选择与状态接口相关的重复分析任务。从宿主当前目标、规则、状态和已有决定开始；缺输入时按[分析协议](../../protocols/analysis.md)继续可做部分。

## 可回跳的处理路径

1. 固定当前叙事目标与玩家选择，分别记录世界事实、角色知情和玩家知情。
2. 将信息对应到实际载体、出现时机、触发条件及玩家可执行行动；环境、系统和文本不能互相假定已传达。
3. 检查分支前置、即时反馈、状态回写、后续后果和中断重入，验证未选择路线不会泄漏信息。
4. 区分文案表达、状态逻辑与生产接口问题；有确定性漏判时先复现再修，不靠润色覆盖。
5. 给可用的条件／状态规则和内容依赖；主题、玩家自由与重要角色走向取舍由用户决定，实际情绪由真实体验验证。

可选操作方法：[causal-system-map](../methods/causal-system-map.method.md)、[experience-hypothesis-chain](../methods/experience-hypothesis-chain.method.md)。

## 展开例与反例

合成例：角色称不知道某秘密，却在玩家未读可选信件时直接讨论它。先区分世界事实、角色知情与玩家知情三个状态；修条件或补传达，不单纯润色台词。线性悬疑可能允许玩家知道得更少，但应有意保留差异，不能把接口漏判当叙事留白。

## 适用与输入

用于面向玩家的信息、媒体与交互路径审查；有交互时继续检查任务的输入、反馈与恢复。从用户消息及宿主材料取得当前目标、相关规则／状态／证据和已定约束，不要求预填字段。具体信息不足仅阻断依赖判断，已有授权内继续取证与验算；没有本类问题可直接跳过。

## 可回跳的处理路径

1. 固定一项面向玩家的信息、媒体或交互路径、平台与已定业务规则；页面数量不代表任务闭环。
2. 先检查关键信息是否依赖单一感官；FMV、过场及其他脚本化媒体按内容核对字幕／说明文字、音频描述或等效替代，不因“不可交互”跳过。
3. 存在交互时，按状态列玩家能知道的信息、允许输入、实际响应和下一状态，观察信息时限及注意力竞争；没有输入或可恢复状态时明确跳过相应检查，不虚构任务闭环。
4. 对交互路径检查错误预防、中断、撤销／返回、焦点、输入冲突和替代输入；规则已对但状态没暴露时，先补可归因反馈。
5. 在实际渲染／输入中复现关键路径；静态截图、单设备、自动点击成功与仅核对媒体清单分别保留覆盖限制。
6. 授权内局部修正与回归自主执行；需要真人体验时给可用版本和具体观察，不能以Agent填写体验结果代替。

### 信息竞争的归因补充（按题使用）

信息密度或冗余是本题缺口时，先比较：规则未被理解、对象/后果不易定位、模式/输入冲突。前者可能需要准确说明；后两者不应只靠追加教程解决。围绕当前判断核对每类信息的主要载体、显露时机和执行处必要重复；删掉文字后，原本承担的判断应仍有可达依据。

用必要的空/部分/完成/不可执行状态及长内容反查建议；禁用条件追溯最新产品决定，区分当前实现与目标规则的迁移差异。界面草图只能支持结构取舍，不能证明操作正确、图标易懂、正式资源已制作或真实体验改善。具体坐标、左右布局、图标和游戏专属规则由宿主拥有。

本增量来自单项目UI共创反思，按候选方法解释；既有路径和无障碍/恢复检查保留。下一次真实任务检查是否更早区分原因、保住必要信息及减少返工；无此缺口不附加字段表或固定多稿流程。

可选操作方法：[experience-hypothesis-chain](../methods/experience-hypothesis-chain.method.md)。方法按实际缺口加载，不复述整张卡；无需因专业边界改派另一个Agent才能完成计算。

## 展开例与反例

合成例：玩家在箭头提示下都点对按钮，只说明可跟随。下一次去掉箭头仍能解释并完成，才为独立应用提供证据；换布局检验迁移。无提示失败也可能由按钮隐藏或输入冲突引起，不能直接加更长教程。操作已认可的无障碍辅助不应为测试学习而全部撤去。不可交互过场没有替代输入或中断恢复义务，但仍需检查字幕、说明文字、音频描述或等效替代；用“没有按钮”跳过整项无障碍审查是误用。

# 结果消费与必要用户决定

默认一份供人阅读的正文，机器工件只为实际消费者导出。宿主呈现该正文和稳定引用，不再按自己的模板重写整份报告。短问题只给所需结论。

## 普通分析

开头给结论或可采取的下一步，随后给决定它的依据和实质限制。确定性公式修复、授权内实现判断和普通专业解释由Agent直接消费。没有真实选择就不生成DecisionPacket，没有实际实验需要就不生成ExperimentPlan。

## 需要用户决定时

让用户能够看清：
- 当前究竟要决定什么，以及为什么现在需要这个决定。
- 推荐方案和关键依据，区分事实、假设及偏好。
- 少量有实质差异的替代方案、各自代价及不可兼得项。
- 最大未知，继续查证可能改变什么，以及现有预算下的推荐。
- 选择后的行动与改判条件。

相关取舍合并，阻断项及时提出，独立工作继续。不把可自主选择的参数、目录、普通学习修订逐项转交。已有决定不重复确认。

## 权限来自实际动作

重要产品方向、真实体验认可、超范围费用或外部行动由用户决定。GameAnalysisDecision建议保持proposed；宿主写accepted等正式状态。只读查证、验算及已有授权内验证无需因输出叫“实验”就新增人工门；相反，叫“建议”也不能替外发或生产修改获得授权。

新版机器交付须明确区分直接消费、重要决定和验证动作，并保留来源、版本、正文引用与局限。旧v1继续按其原始human_review合同解释；新结果不能伪装旧版本绕过其约束，未知版本应明确拒绝。

## 质量不靠排版代替

正文的每项关键依据应支持对应主张；引用存在仅证明可定位。工具实际渲染与消费者检查负责可读性，格式QA不交给用户。结构PASS不证明分析正确，用户同意也不证明游戏效果改善。证据不足时给条件和可做的检查，不把整份结果交回用户重新分析。

专业支持对重要判断有影响时，正文简短交代“什么缺口触发 → 实际用了什么 → 哪个判断受影响 → 剩余未知”。没有读取具体专家正文就只称直接分析；读取角色配置不代表独立专家Agent已经运行。普通小问题不强制附此说明，长期效果仍依赖宿主后续实际反馈。

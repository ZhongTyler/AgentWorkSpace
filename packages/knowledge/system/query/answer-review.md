# 回答形成后的证据利用核查

本方法属于Query；不改变BM25默认、混合开关、原Query回退、正文或终审。研究、游戏支持及未来网站使用同一方法。只在已用资料形成回答、建议或宿主证据结论后执行；短事实可就地核对，不强制另起模型、表格或持久报告。

## 对照实际答案，而非检索结果

先从已读正文提取**会改变本题判断**的少量要点，再看草稿：

把必要前提及并列校准维度拆成可核查的独立要求，逐项比较；不能把多个前提合为一项后，仅覆盖其中部分就判为全部覆盖。“按项目校准”等泛称不能代替证据中会影响本题的具体维度。只保留与本题有关的要求，不扩成逐句搬运来源。

责任Agent先对照来源确认这份要点清单，再判断答案覆盖；若使用模型辅助清单或核查，不能直接把辅助模型自报的`covered`当放行结论。机械工具能拦住缺类、无效引文和陈旧答案，不能识别根本没被列入清单的必要条件。

- **条件**：对象、阶段、版本、阈值前提、约束及可推广范围，是否在相关判断旁保留？
- **反例**：已发现的例外、替代解释或冲突是否仍足以限制建议？没有相关反例时说明查过什么及为何不适用，不制造反例来凑项。
- **来源性质**：原始证词、作者主张、Wiki综合／工程重组、演示、推断、历史数据和本项目实测，是否被正确区分？来源种类或引用ID不能代替对正文性质的理解；未核实就明说。

可概括、合并和改写；保留意义即可，不要求逐字复述。不要把与本题无关的来源说明全塞进答案。引用可追溯不等于语义已经支持，拿到了完整证据也不等于条件已经写入回答。

发现缺项，优先利用已读证据补齐或收窄对应结论；只有关键依据确实缺失时才有界补查。不为每个问题默认两路检索、自动父块、Rerank或新增模型复核。没有实质缺项时保留原草稿，不为展示核查重写。缺口无法闭合时说明未知及影响，不将其标为已解决。修改答案后重新核对变化部分；来源、问题、范围发生变化时重新验证依赖证据。

## 可选的只读机械绑定

普通回答可直接完成上述核对，不额外生成JSON。已有程序／网站问答宿主需要可核验交付时，用同一`query-evidence.mjs review`；它不调用LLM，只验证责任Agent填入的语义核查与当前答案、读取回执、引文和预算是否一致。它不能发现Agent未列出的条件，也不证明任意`covered`声明正确。

输入沿用本轮`request`、真实`receipts`，加`answer`和三个`answer_checks`。每类说明`applicability: applicable|not_applicable`及`reason`；适用时给非空`items`，不适用时给空数组。

```json
{
  "kind": "condition",
  "applicability": "applicable",
  "reason": "该限制会改变建议",
  "items": [{
    "id": "condition-1",
    "requirement": "说明只适用于当前测试版本",
    "evidence": [{"ref": "knowledge:wiki:实际页", "quote": "仅适用于测试版本"}],
    "status": "covered",
    "answer_quote": "这只是测试版的观察",
    "rationale": "改写仍保留版本限制"
  }]
}
```

另外两类`kind`为`counterexample`与`provenance`。`status`为`covered|missing|uncertain`，覆盖时必须复制当前答案中的真实短句，并说明为何在语义上覆盖；不能用省略号拼接多处内容冒充原有连续短句。工具不要求答案逐字包含原证据。缺失或不确定返回`answer_revision_required`，不能拿陈旧`ready`回执套用新答案。

`review`默认stdout、无写入；`answer_review_ready`仅为调用者语义判断与当前输入的机械一致状态，`claim_support`仍为`not_verified`。结果记录当前答案、任务及核查清单SHA，重新交付以实际当前输入重算，不信任客户端声称的旧通过结果。

`assemble`带`answer/answer_checks`时重新执行同一核查，未就绪拒绝组装；不接收一份外部`ready`作为放行凭证。只组装已有来源／claims的旧调用保持兼容，但不代表回答核查已执行。未来网站provider在生成草稿后完成同一语义核对再交付，不能只把HTTP成功或检索命中当作回答完整性；本次没有部署网站服务。

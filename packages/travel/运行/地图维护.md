# 地点与地图固定流程

## 输入分工

人/模型确认采用顺序、交通方式、入口与私址授权；脚本固定ID、URL、分段、自驾全览、截图和变更指纹。未经地图核实的地址不得写“已核门口”。

1. places分清店铺实体、住宿门口、车库车辆入口、步行出口、上下缆车站、轮渡方向。官网地址与地图实体交叉核对；同一楼不等于同一家店。
2. 默认timeline列齐实际地点转场，含采购、停车后步行、回住处；条件分支单列branch。山体/湖面中心、道路中点不可作为可停车点。
3. routes命令只补默认相邻点脚手架，要求显式mode；混合方式由模型逐段设置，不能给整天误套驾车。公交只两端点；航空/船/未收录步道用official运营方入口。执行[转场与通道核验](转场与通道核验.md)，用route-access筛出需要专门核对的段；室内/混合通道用official及短步骤，不能误生成街道步行路线。
4. 每段2—5点；长线拆段。days.routeIds按执行顺序引用；相邻连续驾车段派生当日全览，遇公交/步行/不连续或超5点拆开。不增加历史路线图库。
5. route-info查看URL与指纹，打开实际地图检查返回端点/交通方式/绕路/不可达；地图ETA不能包含你尚未安排的排队/停车/停留。
6. capture抓当前路线全览。私址发送Google前确认授权，用--allow-private仅表示该范围已获许可。截图不自动接受：出现Cookie弹窗、错误页或错路线时修复/重试。
7. 模型/人实际看图后填写复核JSON，通过route-review绑定routeHash、dayHash、captureHash。未核截图不嵌入网页，缺图状态保留。
8. validate→build→浏览器打开每日路线和地图页；确认共用同一集合，实际地图点到正确实体。

## 变更传播

改地址/入口/方式/节点 → 旧截图与routeHash不匹配 → 重新地图核实、截图、复核。
改当天时间线/餐次/住宿/routeIds → dayHash变化 → 重新检查路线是否仍覆盖真实转场；未影响的截图可以复用，但不能自动刷新复核。
自驾全览由当前路线派生，旧全览指纹不匹配会阻断构建。路线删除后不再被消费的历史截图留档，未经人授权不删除用户资料。

## 验证能力边界

能自动查：缺ID、重复别名、缺相邻转场、引用错日期、旧图、图文件改动、方向参数、超过API点数限制。
必须语义查：未知地点未入字典、入口可否开车、禁停/营业/施工、地图地理上错店、疲劳与现场安全。用routeHash并不能“证明合法停车”。

完整地点卡的照片/介绍/营业来自places/catalog；预订来自orders。所有登记名称和别名在阅读文案中自动链接到卡，不登记的新专名仍需要人工审阅。

临时选点与正式行程分开，见[阅读与地图交互原则](旅后复盘与阅读优先级.md)。共享模块`temporary-route.mjs`只生成Google Maps方向链接并恢复临时草稿，不计算地理线、ETA或停车许可；手机每段最多3个途经点，公交只两端，超长URL拆段而非截断。草稿绑定地点和正式分段指纹，输入变更即失效；不改正式事实，也不取代室内通道或景观道路锚点。

便携网页直接内嵌此共享模块，无外部运行依赖。先选一个正式分段，再设起终点、增删或重排；全部正式分段和通道说明仍可展开。official段不提供地面重排，缺精确Google地点时不生成临时导航。草稿存在sessionStorage，关闭会话后可能消失；浏览器禁用存储时仍可操作，不能当作已保存。单HTML用file://时存储隔离依浏览器；采用新顺序须另改trip.json、复核、构建。

官方接口依据：[Maps URLs参数与手机限制](https://developers.google.com/maps/documentation/urls/get-started)、[JavaScript API密钥](https://developers.google.com/maps/documentation/javascript/get-api-key)、[Embed参数](https://developers.google.com/maps/documentation/embed/embedding-map)。核对日期2026-10-09；是否启用正式服务另按账号、费用及外发授权决定。

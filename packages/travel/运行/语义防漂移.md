# 语义防漂移

同一时间、价格和订单不在多段文字里手工维护。事实留在 trip.json，介绍和 Wiki 按需引用；只有可确定的错误阻断，疑似冲突交编辑者判断。

## 写内容时

在手册、项目说明、餐次备注、当天短摘要和 Wiki 中使用 `{{fact:orders/订单ID/start}}` 等引用。构建时替换为当前事实，不改源文，也不刷新核验日期。例如：

```text
按 {{fact:orders/lunch/start}} 的预约到店；菜单预算 {{fact:catalog/cafe/price}}。
```

可引用字段由 scripts/lib/narrative.mjs 的 fields 拥有：订单的日期/起止/人数/金额，餐厅的名称/价格/营业/核验日，地点名称/地址、当天城市/人数及旅行起止。订单原件、凭据和取消链接不属于可引用字段。金额仍保留币种和计价单位，不凭空换汇。字段缺失、ID 无效或引用另一引用时阻断；不能把未知价格补成零。

不用把每句话写成模板。稳定的体验介绍照常写；会变的时间、价格、人数优先引用。使用引用后，机器组件合同里对应的加工字段标 derived，不再要求它与原始模板文字逐字相同。

## 检查与判断

`node scripts/travel.mjs semantic-audit --project <项目>` 只读检查已登记正文和 Wiki。加 `--strict` 可让未处理的疑似冲突也阻断交付。

|结果|怎么处理|
|---|---|
|错误|失效、缺值或越权字段引用；修源或改引用，重新 build|
|复查线索|同地点同日的预约时间文字不同于订单，或标币种的价格超出关联目录范围；核对语境、旧价/套餐/另一活动，不自动替换|
|检查无错误|仅表示引用和上述定域规则未发现错误；不是“全文语义正确”|

固定预约可在时间线填 orderId，validate 要求日期、地点和时间窗覆盖预约；未显式关联但同日同地点所有游玩窗口都覆盖不到预约时，报告 booking-window 复查线索。不自动移动活动或更改预约。

validate/build 会检查引用；CLI 保留更具体的复查上下文。扫描不认识全部自然语言、未关联地点、所有币种写法或真实世界营业规则。编辑者仍要读：默认与备选是否互相矛盾、前后日衔接、门到门时间、实体是否对应、取消和安全条件是否保留。

内容改动后重建，核对总表、手册、信息卡和实际页面。复查记录绑定当前输入，不能批量更新“已读”指纹消除提示。测试保留错时刻、错价格、未知 ID 和私密字段等反例。

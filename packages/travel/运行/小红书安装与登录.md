# 小红书MCP：从零到可研究

本包带接入脚本，不带账号/Cookie或第三方二进制。经验渠道可选；平台不可用时继续官方研究，登记缺口。

## 1. 安装前

人确认允许连接GitHub、小红书及图片CDN，拥有自己的小红书账号。Node环境先跑doctor；原生发布包解包需要tar（Windows现代系统通常具备，其他平台按系统安装）。不要求Docker。

上游：[xpzouying/xiaohongshu-mcp](https://github.com/xpzouying/xiaohongshu-mcp)、[发布页](https://github.com/xpzouying/xiaohongshu-mcp/releases)。本版接入依据核验于2026-09-24；上游变化时重新核帮助/源码，不假设旧字段永久稳定。

## 2. 安装与后台启动

在本包根目录：

~~~sh
node scripts/travel.mjs mcp-install --network
node scripts/travel.mjs mcp-start --network
node scripts/travel.mjs mcp-status
~~~

安装器选择当前OS/CPU发布资产，记精确版本/URL/SHA256；上游给出digest则比对，否则明确publisherChecksumVerified=false（自算摘要不是独立供应链签名）。需要复现时使用--tag准确发布标签。未知资产结构拒绝猜测。安装不执行；启动是下一步。

默认私密运行目录是包内.runtime/xhs，已忽略Git和分发。也可每条命令统一指定--runtime自己的私密目录。版本安装目录不可覆盖；重试先检查安装记录，不批量删除。

服务只监听127.0.0.1，随机本机Bearer鉴权，Cookie隔离保存在该运行目录。后台启动隐藏窗口，端口冲突不杀进程。首次启动可能下载上游管理的浏览器，需要网络和额外磁盘；不依赖原作者的浏览器补丁/用户配置。

如果已有服务，使用mcp-status --endpoint http://127.0.0.1:实际端口/mcp，并将鉴权放TRAVEL_MCP_TOKEN环境变量（不要输出或写到共享文件）。已有服务必须确认受信任和只读用途；脚本拒绝非本机端点。不必把服务装进模型客户端，CLI自己实现标准MCP连接。

## 3. 绑定账号

~~~sh
node scripts/travel.mjs mcp-login --network
~~~

命令返回本地login.png/jpeg路径；打开它，由使用者用自己的小红书App扫码并完成平台确认。模型不代扫码、不索取密码、不绕过风控。之后：

~~~sh
node scripts/travel.mjs mcp-status
~~~

必须看到connected:true和loggedIn:true。二维码过期可以重新生成；已登录不反复生成。截图/QR本身是私密临时数据，不提交也不发给其他人。连接成功但loggedIn:false不是可以提取的状态。

## 4. 搜索与提取

mcp-search返回去掉访问令牌的候选并按ID登记；mcp-extract按同一查询重新获得瞬时令牌，仅存内存。精确ID不在当前搜索结果时改变窄搜词或用人提供的原文导入，不冒用别帖token。

详情核对ID、两次图片顺序/尺寸/资源名；全部图片下载成功才写raw指针。只支持当前返回的imageList图文，视频、评论深挖、相册追加等未适配能力不能声称完整。正文/图清单为空或响应schema改变即失败。批次串行最多10篇，建议3—5篇。

CLI只允许check_login_status、get_login_qrcode、search_feeds、get_feed_detail。不给任意tools/call透传，不调用发布/评论/点赞/收藏/删除。拿到raw后另走digest流程，不能把抓取叫消化。

## 5. 故障与恢复

|表现|先检查|允许动作|
|---|---|---|
|连不上|运行目录/端口/服务日志/进程|确认未启动才start；不反复起服务|
|端口占用|connection.json对应进程、endpoint|用原连接检查；不杀不明服务|
|health正常但未登录|mcp-status|人重新扫码|
|工具超时|具体ID、查询词、日志和网络|同ID有限重试，保留失败；独立官方研究继续|
|图片失败/清单漂移|图数顺序和CDN响应|保留下载；重新提取完整版本，不标完整消化|
|平台风控/访问拒绝|平台提示|停止自动重试，人处理或换合法来源|
|要换账号/停止服务|确认这是本包启动的PID及可执行文件|人通过系统进程管理结束自己这一个服务；不提供按端口盲杀|

connection.json含鉴权，service.log可能含平台信息，只在本机检查。文件权限随操作系统，不宣称已加密；多人共用机器应选择受限目录。升级前关闭自己的服务并保留账号数据恢复点，别覆盖Cookie。

停止服务未做跨平台自动杀进程：PID可能被复用，盲目脚本化不安全。若宿主已有进程管理器，可以提供绑定实例生命周期的适配器；不得借本流程杀其他会话。

协议依据：[MCP Streamable HTTP](https://modelcontextprotocol.io/specification/2025-06-18/basic/transports)；上游启动参数与本机监听依据：[main.go](https://github.com/xpzouying/xiaohongshu-mcp/blob/main/main.go)、[app_server.go](https://github.com/xpzouying/xiaohongshu-mcp/blob/main/app_server.go)。这些外链用于上游溯源，本地流程不依赖作者工作区。

# 从陌生工作区开始

## 必需与可选

- 必需：Node.js 22或以上（从[Node官网](https://nodejs.org/en/download)安装）、本文件夹、可读写的新旅行目录。
- 模型需具备文件编辑/运行命令能力。研究需要联网与读图能力；没有时由人提供材料，不影响离线整理。
- 小红书是可选经验渠道：需要联网安装原生MCP、服务自带浏览器初始化、使用者自己的账号扫码。
- 地图截图/浏览器验收选装Playwright和浏览器。无截图也能先生成网站，缺口会明确显示。
- 不需要原作者账号、服务器、全局skill、原旅行源码、Python、Docker、数据库或API密钥。

**自包含指不依赖作者工作区，不是捆绑操作系统、Node、第三方浏览器和别人的登录态。** 首次安装联网，之后网站本体完全离线。

## 五分钟启动

将已导出的工作流包复制到任意位置，终端进入包根目录。不要直接复制含私人旅行和偏好的整个Travel工作目录。目录有空格时用引号；以下PowerShell与常见shell均可用。

~~~sh
node scripts/travel.mjs doctor
node scripts/travel.mjs package-check
node scripts/travel.mjs init --project "./my-trip" --title "我的旅行" --start 2027-05-01 --end 2027-05-03
node scripts/travel.mjs validate --project "./my-trip"
node scripts/travel.mjs build --project "./my-trip"
~~~

打开新项目build/index.html即可。第一次是空白规划框架，缺安排提示不是“已规划完成”。不必先启动网页服务器。

> 使用这个旅行工作流，为./my-trip规划旅行。先整理日期、各段人数、偏好、已有订单和城市覆盖矩阵；走双轨研究并保留来源，先提方案，不替我预订。复用脚本完成登记、校验和离线网页，不读取其他旅行或原作者文件。

## 体验完整虚构样例

~~~sh
node scripts/make-demo.mjs --project "./demo-trip"
node scripts/travel.mjs build --project "./demo-trip"
~~~

样例仅检验字段和网站，不提供真实营业、路线、订单或旅游建议。不要把示例数据并入实际旅行。

## 修改后最短闭环

安装可选Playwright之后，可在包根执行真实离线浏览器验收：

~~~sh
node scripts/browser-smoke.mjs --project "./my-trip"
~~~

已有浏览器时追加 `--browser "浏览器可执行文件完整路径"`。缺依赖会明确失败，不能把网站构建成功当作浏览器验收通过。init创建的数据项目与本工具包分开存放；换机器继续编辑时同时保留二者，新项目README提供相对链接，单独的离线HTML只用于阅读。

编辑trip.json/knowledge → validate → 有地图/手册变化则实际复核 → build → status → 浏览器查看。build包含sync，不需重复手动改总表。

默认不自动Git提交、不上传、不部署。若人明确开启自动提交，遵循当前仓库约定，每次只提交本轮范围。换机器复制项目时，private与登录态不要混进普通共享包；已有订单证据如缺失，先安全迁移原件或恢复证据，不能绕过检查。

# 离线默认、分发可验、服务器可选

宿主工作区将工作流源、发布快照、旅行、私有资料和归档分开，不能直接复制整个工作区公开。正式发布目标是 AgentWorkSpace 的 packages/travel；来源仓只维护工作流源码，不保留第二份 released 副本。pack/release 可按需生成独立副本，不作为新的维护源。偏好、旅行、复盘、工具缓存与账号目录从遍历入口就排除。

## 两种包别混淆

**工作流分发包**：脚本、方法、模板、skill、离线界面、虚构样例和测试，不带任何人的旅行。

~~~sh
node scripts/travel.mjs package-check
node --test tests/*.test.mjs
node scripts/travel.mjs release
node scripts/travel.mjs release --apply
node scripts/travel.mjs verify-package --root "./released"
node scripts/travel.mjs pack --out "../travel-workflow-export"
node scripts/travel.mjs verify-package --root "../travel-workflow-export"
~~~

白名单复制，排除.runtime、node_modules、.git、dist、临时测试输出及包外文件。MANIFEST记录每文件SHA256。它检验完整性，不是作者签名。安装到新Agent工作区也用同一pack逻辑，拒绝覆盖现有目录。

release 默认只列增改删；加 --apply 才更新。默认输出包内 released，可用 --out 指定同级发布目录，例如源目录中执行 `release --out ../released`；禁止输出覆盖源目录、其祖先或源内其他目录。已有快照必须与清单一致，额外文件、手工修改和链接目录都会阻止覆盖。更新时先生成并核对候选，再切换目录；上一份保留在源目录 .runtime/release-backups。失败不删除旧版。修改工作流后重新测试、预览差异并生成快照，不直接编辑 released。

分发文本统一LF换行，并携带.gitattributes，避免Git在不同系统转换换行后导致清单失效；图片等二进制保持原字节。

拿走released整个文件夹即可；不用带Travel根或真实旅行。包内快速开始、虚构样例、测试、工具和离线网页自包含。基础网页采用项目/地图每日双主入口和折叠当天工具；天气、订单、餐厅、购物、实用指南、Wiki与手册在全局导航直接展示。会话内临时选点不写正式事实；不附带原生Google地图接口。自己的旅行和偏好另建目录。首次试用先走虚构样例，再换真实资料；分发包版本以MANIFEST为准。

**旅行离线文件**：build/index.html，包含采用的行程、私密住宿位置和订餐执行信息。CSS/JS/图片/天气/Wiki都内嵌；断网可看，主动点地图、订位或原文才需要联网。该文件不是公开版，不要放公开Git仓或公开网页。

## 源和输出

raw、private、MCP运行目录不被网站拷贝。orders只导出执行字段白名单；任何secret字段/带token的URL必须移出共享事实。Wiki正文、说明和照片也可能带隐私，脚本扫描不能代替人工审查。

源码Git、工作流包、行程项目、同行离线文件是不同分享边界；本包不自动commit/push。确需自动提交由用户明确设置，先看diff和secret，再按宿主范围规则执行。

## 可选服务器

无服务器就停在离线文件，不降级成“没完成网站”。有服务器且人授权后，选择其实际部署方式，不硬编码作者服务器或要求某一家云。

部署前必须由人/模型决定：接收者、私密/公开、域名、身份验证、成本、备份与回滚方式。私密版须服务端保护整份HTML和所有资产；不能靠隐藏入口、前端密码或搜索引擎不收录。

标准步骤：

1. validate、build、status确认源与产物一致，浏览器实际验收。
2. 生成此次候选版本目录与产物摘要，保留当前版本恢复点。
3. 按目标平台上传到候选目录（不覆盖正在使用的旧版），先验证权限和实际页面。
4. 使用平台的版本切换/链接切换能力发布，读回页面核对摘要或明确版本标识。
5. 失败先查是否已经切换，必要时回指已验证版本；最后记录线上URL、版本、权限检查和未完成项。

服务器命令依实际平台由适配器提供，不在通用包里虚构万能ssh/scp命令或保存密码。未有平台/授权则不安装部署工具、不探测机器、不上传。

## 分发维护与验证范围

- 本机自动化/迁移/真实浏览器证据齐全；不同OS仅标实际测过的平台。
- 新使用者验证优先走无MCP的真实采集、导入、消化、规划与离线阅读；不要求为了试用绑定平台账号。独立陌生人实测、执行者自测与合成测试分别报告。
- MCP与页面保存工具按选用情况另做真实兼容性测试；安装、模拟协议和合成HTML不替代真实登录/保存文件测试，未验证模块不进入默认依赖。
- 选择最终开源/分发许可；核第三方二进制、图片、平台条款与模型工具依赖。权利人已于2026-10-11选择原创代码与文档的MIT许可；LICENSE-NOTICE说明边界，第三方内容保留自己的条款。
- 保持版本和依赖来源可追溯，跑干净目录测试；需要分发副本时生成清单。签名、公开发布渠道或对外许可证必须有实际选择，不由脚本代批。
- 外链检查、平台变化适配和安全问题有可执行维护入口。遇响应schema变化先失败，不继续写成功记录。

“可移植工程验证”“第三方工具实测”“跨平台实测”“公开发布”和“真实旅游验收”是不同证据，不互相替代。私有偏好只按指定档案参与规划，采用快照由本次旅行拥有，永不自动加入工作流分发。

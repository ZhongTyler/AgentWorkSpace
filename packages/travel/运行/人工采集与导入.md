# 不依赖平台MCP的资料路径

默认先用已有收藏、人工分享资料和公开网页；官方检索与经验资料仍双轨进行。小红书MCP是可选连接，不是开始规划或验收的前提；平台限流、登录或连接失败时不绕过访问限制。

## 最少人工动作

使用者提供稳定原文链接、展开的正文、按原顺序保存的图片或截图；尽量告诉模型原帖共有几张图，哪些没取得。网页/PDF原件可一并提供。人工不必写JSON或手填阅读声明。

模型确认是否同一篇、正文是否展开、图中文字是否可读，再整理UTF-8正文文件与采集清单。页面保存工具只是取得材料的一种方法，不等于采集完整、内容已读或有转载权。

模型复制[清单示例](../examples/intake.json)，改实际ID、URL和正文文件路径；images按顺序填 `{ "file": "01.png", "position": 1 }`。路径相对清单目录，不允许跳出目录或经符号链接访问。

`capture`记录实际采集者、时间、方式，以及原文覆盖声明：

- `scope: complete`：实际核对展开正文，已知原图/截图总数，全部按1至N顺序取得。纯文字帖确认无图时expectedImages为0。
- `scope: partial`：已知漏页、只保存部分内容或没展开正文；可继续消化，但不能记完整消化。
- `scope: unknown`：不知道原图总数或正文是否完整；不猜，不用已下载数量冒充原帖数量。
- `expectedImages`是原图/人工截图页数，**不是网页中logo、装饰图和缩略图的数量**。网页完整HTML仍需模型实际识别正文和信息图片。

可选 `archive: { "file": "saved.html" }` 或PDF，按原字节存入项目private/source-archives，记录摘要，不执行HTML、不抓取其中链接、不导出到网站。保存页面可能含账号、分享令牌和取消链接；私密原件不能提交或公开。文字/图片副本进入raw前由模型审查隐私和用途。

## 脚本链

~~~sh
node scripts/travel.mjs intake --project "../my-trip" --file "../incoming/intake.json"
node scripts/travel.mjs source-audit --project "../my-trip"
node scripts/travel.mjs gallery --project "../my-trip" --id "实际ID"
~~~

脚本拒绝缺失文件、重复图、越界位置和错误的完整声明；保留原顺序、每图摘要、不可变版本与原链接。旧版本不覆盖；确需更新用--refresh，重新消化当前版本。

之后模型实际读正文和每张图→核实官方当前规则→写主题Wiki并保留URL→生成review→digest。采集完整性、实际阅读和旅行事实准确性是三件事。旧资料未声明原文覆盖时，source-audit显示unknown；不改旧hash或伪造历史采集声明。

## 页面保存工具的接入条件

某工具必须先通过**真实保存文件**测试，再写成受支持的操作指南：正文展开、图片可读、原URL留存、文件断网可读、敏感内容不外泄。合成HTML、安装成功、HTTP200都不代替这一步。

先用 `node scripts/travel.mjs archive-info --file "实际保存的.html"` 只读提取摘要和资源提示，再实际核对内容/离线表现。外链只作为静态检查线索；脚本不回显访问令牌，也不会把“存在内嵌图片”当成所有图已完整保存。

浏览器连接失败时由人保存、模型接收本地文件，不反复要求重装、不读取浏览器Cookie、不强制换账号。尚未通过真实文件测试的工具不写成已验证支持，具体测试结论单独记录，通用导入不绑定某个扩展。

## 已实测的人工路径：SingleFile保存图文笔记

2026-10-10用两份人工保存的小红书图文笔记实测：保存正文与原帖URL可提取，9张和14张图集均能离线取得。支持边界是**人工正常访问后保存、模型检查并整理、再走既有导入链**，不是自动搜索、批量抓取或绕过平台限制。详见[实测记录](验证记录/SingleFile-2026-10-10.md)。

1. **人操作浏览器**：正常打开目标笔记，展开正文，逐张浏览图集并等图片加载；记下页面显示的图集总数。需要评论时另行展开和加载，不能默认保存了全部评论。
2. **人保存并交付**：用SingleFile保存当前页为HTML/HTM，放入私人待导入目录。尽量一篇一个文件，并提供原帖链接和总图数；不用交出Cookie或账号密码。
3. **脚本初检**：运行上面的archive-info，记录来源和文件摘要。网页图片总数不等于笔记图集数量，不能据此自动声明完整。
4. **模型检查与整理**：核对正文、来源、图序、每张信息图片及缺页；必要的浏览器检查须隔离、断网、禁用页面脚本。SingleFile可能把图片保存在CSS背景中，透明SVG占位图加载成功不代表取得了实际图；轮播首尾副本也不能重复计数。提取已有内嵌资源，不因缺图自动访问外链。无法安全解析时改由人补截图。
5. **接回既有流程**：整理UTF-8正文、按原顺序编号的图片和intake清单，私有archive保留原字节，执行intake→source-audit→gallery。之后实际阅读每张图、补官方来源、写Wiki和digest；测试通过不等于内容已消化。

原始存档还可能带有推荐流、头像、账号页面和分享令牌，应留私密目录，不提交Git、不打进分发包或网站。提取的文本和图片也须先审查隐私及使用范围。两份样本通过不保证其他页面、视频、长图或未加载内容同样完整；每次仍核对覆盖情况。现有CLI尚无通用SingleFile一键提取命令，不把一次性诊断脚本冒充正式功能。

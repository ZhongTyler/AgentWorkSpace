# trip.json与证据合同

可选呈现字段：`presentation`含kicker/headline/subtitle/journeyTitle文字；`days[].highlights`为短要点；`journal[].visit`含duration、steps文字数组和tip；地点/目录/手册的`wikiIds`引用主题ID；目录的dishes、recommendation和priceNote存点单线索、采用原因及价格性质。介绍与步骤按读者用途编写，不能借新增字段把未知变成已核。字段不另拥有订单时刻，页面仍从orders关联。没有图片就不生成photo占位；CSS装饰不是照片。渲染器输入指纹覆盖两份样式与脚本，改设计后旧构建必须失效。

schemaVersion=1。初始化给出所有必需数组；日期为YYYY-MM-DD，当天窗口HH:mm，跨午夜拆到两天；timezone使用IANA名称。所有ID使用小写字母/数字/连字符/下划线（最长96），禁止路径与Windows保留设备名。相对路径用/；不允许跳出项目或经符号链接写出。

Travel根下的私有偏好档案与trip.json.preferences分工见[偏好机制](../模板/偏好记录.md)：前者是指定旅行者的长期倾向，后者是本次采用快照与覆盖。CLI不扫描或自动合并偏好；通用模板没有任何人的默认排序。

跨时区当天选一个明确的时间轴时区，在各交通节点note另列出发/到达当地时间及时区。不要把不同地区钟面时刻直接相减；本版不自动计算跨国际日期变更线的航班耗时。跨夜订单可将次日结束信息写instructions，逐日时间线仍按日期拆开。

这是字段权威说明；[schema](../schemas/trip.schema.json)用于编辑器基本形状提示，CLI validate执行更严格的引用、文件、时窗、证据和漂移检查。

## 结构化字段

|集合|最小字段|可选字段|
|---|---|---|
|顶层|schemaVersion,title,start,end,referenceCurrency,rates,preferences及所有集合|preferences只保留规划需要，不放敏感证件|
|days|date,timezone,party,city,summary,stayId,timeline,meals,routeIds,weatherIds,notes|stayId可null|
|timeline条目|start,end,title|placeId,routeId,branch(default或明确备选名),note|
|meals条目|meal(breakfast/lunch/coffee/dinner/grocery),role(default/alternative)|catalogId,orderId,note,cost；自炊无catalogId，note写采购；每餐至多一个默认|
|places|id,name,address,kind|aliases,private,mapUrl,googlePlaceId,description,review,photo,accessGroup|
|catalog|id,name,placeId,city,kind|cuisine,description,price,openingHours,verifiedAt,url,bookingUrl|
|routes|id,date,mode,stops（2—5个place ID）,branch|officialUrl,access；review/capture由命令维护|
|orders|id,title,category,date,status|booked必须evidence/start/party；end,placeId,amount,instructions,cancelRule|
|todos|id,dates,kind,when,action,status(open/done)|orderId；when必须写清“现在/开票日/活动前一天/当天现场”等参照|
|knowledge|id,title,summary,path|city；文件在knowledge/，按主题而非按日|
|shopping/guides|id,region,title,summary|wikiId,url|
|journal|id,date,title,text|kind（intro地区开篇 / experience具体体验；省略仍为普通手册段落）,placeIds,photo,reviewedBasis（当前dayHash，读过变化才填）|

experience正文同时用于手册与每日项目；项目时间、预订分别从同日timeline和orders按placeIds关联，不另写一份。未标experience的旧段落不自动计入项目，日常转场也不自动生成体验。正文可写现场怎么看、怎么吃及必要条件，营业/价格仍由地点与目录拥有。
|expenses|id,date,label,category,currency,min,max|只放未被餐次/订单重复计算的费用|
|weatherLocations|id,name,latitude,longitude,timezone|days.weatherIds选当天长停点；不自动猜相邻城市合并|
|researchCoverage|id,city,topic,question,noteIds,officialUrls,gaps|target,notApplicable；数量不是充分性证明|

places.kind：entrance/parking/restaurant/cafe/supermarket/hotel/attraction/station/airport/activity。
catalog.kind：restaurant/cafe/supermarket/activity。

todos.kind：`booking`专指“完成订位/购票”动作；已订订单仍未完成的到店、集合、带票提醒用`reminder`，条件复查用`recheck`，其余可用`other`。关联orderId不代表待办完成；脚本从不自动关闭。只有kind=booking且关联订单已订时，才提示人工核对是否关闭。不要把订位和到店揉成同一条动作。

预算只统计已编码的默认餐食、有价订单及expenses；`unknown`只表示这些条目中缺价的数量，**不是全旅程遗漏费用数量**。没有录入的早餐、交通、住宿或购物不会凭空估价。输出固定带`completeTripBudget:false`及scope，是否已覆盖全程仍需人工检查费用类别。
routes.mode：driving/walking/bicycling/transit/official；transit仅2端点；游船/航空/未收录步道用official＋运营方URL，不能假造驾车线。

`places.accessGroup`为同一机场/车站/建筑群的稳定名称，不证明室内相通。同组walking/official转场必须有`routes.access`：`kind`（indoor/mixed/outdoor）、`steps`（非空短步骤数组）、`constraints`（条件及未知边界）、`sources`（每项url与claim）、`checkedAt`（YYYY-MM-DD）。indoor/mixed必须用official和可打开的到达说明/平面图，室外可导航段另拆。route-access负责筛选和字段检查；详情见[转场与通道核验](转场与通道核验.md)。字段变化纳入routeHash，旧审阅不能自动沿用。

review：by、at、evidence，记录实际核验依据，不填假完成。
photo：file、caption、source（公开URL）、license（使用权说明），可选作者写caption。仅本地PNG/JPEG/WebP/GIF可内嵌，示意图明确标注；官网/地图可读不代表可转载。
price/cost：currency（ISO三字母）、min、max、basis(person/total)。orders.amount为整单合计，不能再乘人数。rates以原币为键，rate表示1原币折参考币数量，asOf为汇率日期，source保留来源。未知价格不填0。

订单evidence指向private原件，网页只输出白名单执行字段，不输出原件路径/取消令牌。网页仍含行程、住宿等私人事实，只适合同伴私下分享；这不是公开脱敏导出器。

## 候选与raw

candidates文件为数组，条目id,url,title,author,query,topics。source文件见[输入样例](../examples/source.json)：id,title,url,text,images（每项file相对source.json所在目录），可选author,publishedAt,topics。官网网页、人工截图也可同样导入；不得复制无权限取得的正文。

import保存原文与图片顺序、每图hash、来源和时间；registry记录raw/rawHash/imageCount。访问令牌不进入URL，原始小红书链接规范为公开explore地址，原帖需要登录时仍可能打不开。

人工入口用intake清单：id/title/url/textFile/images/capture；可选author/publishedAt/topics/archive。正文与图片相对清单目录，字段及[示例](../examples/intake.json)见[人工导入](人工采集与导入.md)。images可附原图position；capture为method/by/at/scope/bodyExpanded/expectedImages，按真实采集情况声明，不根据下载数量自动填完整。source同样接受capture与archive。HTML/PDF原字节保存在private/source-archives，raw只记私密路径及hash；网站不输出归档原件。

source-audit逐项检查原文manifest、图片和归档摘要，单列complete/partial/unknown采集范围。历史raw无capture时unknown，不改原字节。完整性字段是读者声明，不证明原帖不存在未展开内容或额外图片。

## 消化声明

~~~json
{
  "id": "source-id",
  "rawHash": "从registry取得的当前完整指纹",
  "reviewer": "实际阅读者",
  "reviewedAt": "2027-04-01T10:00:00Z",
  "status": "complete",
  "bodyRead": true,
  "images": [{"hash": "raw中的图片指纹", "read": true}],
  "outcomes": [{"topic": "交通", "reason": "采用的独立信息", "file": "knowledge/transport.md"}]
}
~~~

complete和not-used必须读完正文及每图。partial可只声明已读部分。not-used的outcome用decision:"not-used"和reason，不写file。采纳Wiki必须保留该raw.url，命令记录目标文件hash；Wiki后续编辑会提示核对保留覆盖，而非阻止正常综合更新。

新资料有capture且scope为partial/unknown时，即使保存的图全部读完，也只能记partial，不能把原帖算完整消化。旧资料的complete保留其历史含义（所保存正文及图全部读完），原帖覆盖仍由source-audit单列unknown；不把历史条目自动升级为完整采集。

## 路线复核声明

先route-info取当前routeHash/dayHash，真实检查地图端点、方向、交通方式、入口和路线；capture后实际看图。

~~~json
{
  "routeHash": "当前路线hash",
  "dayHash": "当前当天hash",
  "by": "实际复核者",
  "at": "2027-04-01T10:00:00Z",
  "evidence": "官网入口URL及地图观察记录",
  "endpointsAndModeChecked": true,
  "screenshotChecked": true,
  "captureHash": "实际看过的截图hash"
}
~~~

无截图时可不填后两项，但缺图警告保留。变更地点/路线后旧图失效；当天安排改变后旧复核失效。全览ID由overview-日期-序号派生，route-info/capture/route-review同样支持。

## 出发清单与阶段笔记

收拾清单是语义知识，写knowledge/packing.md并在guides引用；确需提醒的动作写todos，不建第二组打勾状态。研究阶段判断写独立讨论稿，generated/NOW只派生实际统计、警告和未完成行动。人工文件可以丰富说明，不再拥有与trip.json冲突的事实字段。

# 09 同步、验证与发布

> **便携版执行**：validate → build → status → 浏览器检查 → pack/verify-package；服务器可选。字段以[数据合同](../运行/数据合同.md)为准；总表/清单/NOW均为只读投影。脚本不代替本章语义判断。

输入：本轮实际改动与授权范围。输出：源数据和消费者一致，有可复核的交付状态。

## 变化驱动维护

| 变化 | 同步到哪里 | 核查重点 |
|---|---|---|
| 人数/日期/航班/住址 | 需求、订单、相关日卡、路线、预算、天气映射、手册 | 前后一天、跨午夜、按段人数 |
| 午餐/晚餐/项目采用变化 | 总表餐次/日卡、路线、待办、精选阅读、手册 | 已订的取消/改期、到达与采购窗口 |
| 新官方事实/新笔记 | Wiki/台账/目录；仅影响行动时改总表 | 来源、时效、冲突、全图阅读 |
| 店名/别名/地址 | 同一实体卡、引用与匹配；入口变化再改路线 | 地点专属实体、导航入口、漏链 |
| 路线节点/方式/入口 | 分段、全览、截图清单、日卡路线审阅记录 | 旧截图失效；先实际审阅再更新摘要 |
| 天气 | 新快照、当前指针、风险摘要和网页 | 日期/时区/地点/缺失值，不覆盖历史 |
| 订单确认/改期/取消 | 原件提取、订单表、同ID待办、相关日卡/卡片 | 真实凭证、人数、时间、取消条件 |
| Wiki更名/合并/退役 | Domain、台账、目录、精选阅读、资料链接 | 反向引用与历史可追溯 |
| UI改动 | 展示代码和受影响交互验证 | 不借UI改写旅行事实 |
| 研究阶段/阻塞改变 | NOW | 不复制已采用行程与完整订单 |
| 实际发布 | 发布收据和需要更新的入口 | 本地产物、提交、推送、线上版本分别判断 |

NOW只留当前阶段、尚需研究/决定的少量事项和下一步；已完成自动统计从登记/台账派生。正式待办只在trip.json.todos，NOW可链接。发现现有项目违反此规则时先判实际影响，不能把文档写了规则就当已经修复。

## 分层验收

全量内容审计使用[网站健康检查能力](../运行/网站健康检查.md)：先列完整展示清单，再区分机械错误、语义冲突、过期提醒与历史记录；已知漂移补定域反例，不批量刷新核验日期。

1. **资料**：URL、精确ID、图片清单、消化去向与统计；官方事实有核验范围。
2. **规划**：门到门可行、固定锚点、餐饮/补给/行李、前后日、分支与未决项。
3. **接线**：唯一编辑源、日期覆盖、引用、订单/路线/待办一致、旧图与旧生成物拒绝使用。
4. **展示**：真实点击、手机/平板/桌面、弹窗/搜索/导航、图片和离线阅读。
5. **发布**：具体输入与产物匹配成功收据、当前线上版本、私密访问边界和恢复点。
6. **体验**：用户是否看懂、旅中是否好用；前五项不能代替真人体验或未来开放事实。

测试选择跟随改动风险。改文档检查相关链接/结构；改解析器跑正反例；改页面再做实际浏览器检查。未改变的业务不因新写一篇工作流而全量回归。

## 自动化该做什么

适合脚本：原始ID去重、索引/统计、日期缺重、本地链接、实体别名冲突、漏链、餐饮目录关联、未完成待办按日投影、路线连续性与截图指纹、数据摘要、图片存在/加载、天气日期映射、生成物新鲜度。

需要语义审阅：经验是否独立、图片真的读过、某地是否值得去、时间是否留够、停车是否合法、实体是否对应、来源冲突、文案是否准确、选图许可与实体。不能通过自动更新「已复核」哈希来代替这些工作。

## 构建与发布

遵守宿主实际合同。常见步骤：读取当前源/dirty → 受影响检查 → 生成普通网页与所需离线包 → 在实际预览中核对 → 检查差异与凭证泄漏 → 范围内提交/父指针 → 按已有授权推送/部署 → 读回线上状态。

本包用sync/build/status固定源到产物摘要；默认离线交付。有服务器时按[发布与隐私](../运行/发布与隐私.md)选择适配器，不继承任何案例服务器或账号。

部署授权已覆盖必要步骤时自主执行，不逐文件索取许可；若还有真实的新外发目标、公开范围或付费动作，先完成可审阅产物再指出缺口。把源代码推送到仓库和把私人网页放上服务器分清，不能借一次授权任意扩张目的地。

本地构建不是上线。发布失败先查询实际状态，判断是否已切换；保留可恢复版本、失败日志和下一步，不凭命令超时猜成功或回退。最终报告线上URL/版本、验证范围、未完成事项；没有变化不空提交。

## 旅中与旅后

旅中调整优先保障可用默认线，同步最新页面/离线包并标时间。旅行后保存实际发生的路线、价格和体验日期，修正Wiki的适用边界；流程只吸收具体错误和有效增量，不把个人偏好升为通用定律。

使用[旅后复盘与阅读优先级](../运行/旅后复盘与阅读优先级.md)收集真实体验和网页实际使用方式。未完成的旧待办不自动改为完成，计划不回写成实游。旅行入口转为复盘阶段；网站冻结、停自动刷新、全站改版和部署分别按实际授权处理。

优先让正确的当天行动、精确地点和截止点可用。若图片只是辅助资料，后续可设计显式的缺图降级，而不是用错图或让用户无期限等待；失效定位、路线不通和安全缺口不得随之放行。现有[网站健康检查](../运行/网站健康检查.md)的截图门仍生效，本轮未实现降级开关，未来须同步合同、检查器、界面提示及反例后才能启用。

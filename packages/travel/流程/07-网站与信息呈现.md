# 07 网站与信息呈现

> **便携版执行**：validate → build（包含sync）→ status → browser-smoke；只修改web组件，不在生成物改事实。字段以[数据合同](../运行/数据合同.md)为准；总表/清单/NOW均为只读投影。脚本不代替本章语义判断。

输入：已建立事实源的行程。输出：可快速读、可深入查、与源文件同步的网站。本包提供无运行依赖的单HTML离线网站。可自行扩展技术栈，但不改变事实分工。

实施前完整读取[设计skill](../skills/travel-presentation/SKILL.md)，按[品质复现](../运行/品质复现与验收.md)完成简报、实现、中文审校和真实页面复核。模板是起点，不是成品质量的豁免；不可只填数据后把机械测试通过当作设计验收。

设计交付建立可维护的基线：页面同时交[设计规范](../模板/前端设计规范.md)、[机器组件合同](../模板/前端组件合同.json)和少量状态样例。规则不混入当前旅行状态；字段、令牌与事实各有唯一来源。按[前端设计与内容分工](../运行/前端设计与内容分工.md)区分内容更新、缺陷修复、基线内调整和重新设计，并执行绑定、长度、状态切换和响应式检查。不要只检查当前数据恰好呈现正确。

## 先验证一日，再扩展全程

选同时有转场、默认/备选餐饮、地图和待办的一天做样章；把还未规划城市的位置预留清楚。用户认可层级与卡片后再扩展所有日期。用真实资料，不以漂亮假数据代替缺口。

数据链：trip.json＋knowledge＋快照/受控素材 → validate → sync/build → 单HTML。页面组件只展示，禁止在组件和生成JSON里单独改行程。旧项目迁移前先匹配现有schema；新项目直接使用本包渲染器，不需要原旅行网页。

## 信息架构

按[旅后复盘与阅读优先级](../运行/旅后复盘与阅读优先级.md)组织，而不是为每种资料开一个平级入口。推荐让“项目”成为每日默认阅读面，地图可随手打开，时间提示跟随项目，资料按需展开。以下为目标信息职责，不要求每项都成为独立页签。

| 层 | 主要内容 | 阅读方式 |
|---|---|---|
| 首页总览 | 旅程主线、日期/地区、每天核心体验、真正未决项 | 短摘要与逐日入口；去掉已规划标签、完成进度、冗余筛选 |
| 天气 | 全程高低温折线＋日期横排＋城市详情 | 卡片纵向排列，详情可折叠 |
| 每日执行 | 日期与天气短行 → 必要集合/截止提醒 → 项目目录与卡片 | 时间表可展开；无提醒不显示空栏目；默认餐饮归入对应项目，住宿/采购用短卡 |
| 地图 | 按日标点、顺序与实际分段，临时起终点选择 | 与项目共用地点ID；正式路线与用户临时组合分开，不自动写回行程 |
| 订单待办 | 已订事实＋按日未完成动作 | 没有用途的状态筛选去掉 |
| 餐厅清单 | 城市→餐厅/咖啡/超市 | 与当天吃饭卡同源 |
| 购物 / 实用指南 | 分城市、短卡、必要详情 | 资料由相应清单和Wiki提供 |
| 延伸阅读 | 只选当前行程相关Wiki | 全文搜索、弹窗阅读、上下文入口 |
| 旅行手册 | 连续图文认识目的地 | 首页显眼主入口，见下一流程 |

首页与手册保留阅读入口，主导航默认直接展示各模块，手机横向滚动；进入每日后也能直接打开所选日期的地图路线，返回时保留当天。入口是否收起由实际使用反馈决定，不把折叠作为必选布局。手册复用项目正文，只另写地区开篇。

实施边界：便携渲染器以项目/地图为每日双主入口，时间线、吃饭、住宿、核对折叠在当天工具；全局模块导航直接展示，正式地图路线页与临时选点面并存。项目目录和折叠卡复用手册experience段落，时间与订单按当天地点关联。地图支持会话内临时选点，不写回事实。增强角色和条件计数仍由宿主扩展；正式第三方交互地图未接入，页面只提供按所在地选择的跳转入口。

切换当天工具写入URL（#day/日期/section），刷新恢复；切日期回到项目。跳往全程资料仍保留日期，地点/Wiki弹窗关闭不切阅读面。改变布局时一起更新browser-smoke入口及发布适配测试，旧截图不代表新布局已验收。

## 可读性规则

视觉规则与全量巡检见[视觉层级与全量巡检](../运行/视觉层级与全量巡检.md)。模板提供语义分层样式，不能仅用相近字号区分概览、正文、截止点和链接。样章认可后必须覆盖其余模块与全部每日页签，再生成发布快照；脚本截图与编辑者实际看图分别记录。

时间线先行动，再短要点；固定、弹性、触发条件和最晚时间可扫读。长背景、菜单全文、证据过程放详情。减少文字不能删掉延误阈值或安全边界。

吃饭按午餐/晚餐组织，默认卡直接可见、备选折叠，自炊给超市。餐厅已排除的历史结论不混入别的日期。实用指南一张卡对应一个问题，整篇Wiki完全适合才直接打开它，部分适合则定向引用/拆主题。

资料入口有层级：现场导航/已订集合优先，必要详情次之，原始溯源最后。不要同时保留侧栏捷径、侧栏来源、页底阅读三份同一链接。

新增可见内容要说明读者用途、唯一编辑源、维护触发和隐藏条件。没有独立用途就不展示；重复的同义段落即使共享基础数据，也会增加审阅负担。按[旅行文案审校](../运行/旅行文案审校.md)删套话，保留行动条件；不把系统内部验证提示反复放进游客主阅读面。

## 地点信息卡

所有已登记地点/项目在正文可打开同一张卡。稳定ID＋唯一别名匹配，长名称优先；已存在地图/来源链接和按钮保持原用途，不嵌套交互。区域概念、不可定位项目只给介绍/指南，不虚构导航点。

卡片顺序可采用：准确图片 → 简短介绍 → 我的预订 → 营业/价格 → 到达位置 → 延伸阅读与来源。订单来自订单表，价格/营业来自目录，介绍来自手册或专题，定位来自实体卡。

地图跳转要到具体店铺；同楼酒店不能冒充餐厅实体。驾车时另给车辆入口。未找到精确实体明确显示检索定位。营业为带核验日的参考，不能据旧资料显示实时「营业中」。

## 可访问性与验证

手机触控和长卡滚动、桌面焦点、键盘/ESC、弹窗关闭返回原位置、折叠语义、图片alt、明暗对比、减少动态效果、无横向溢出。中文地名、别名和换行特别检查。

脚本扫描全部日期、页签、资料弹窗的已知名称漏链/失效ID；人工补未知专名。字典检查不能识别世界上所有地点。实际点击地图、订单关联、Wiki来源与图片加载，并检查控制台和无结果搜索。

公开版要在生成数据阶段删敏感字段和附件；CSS隐藏、折叠或没有导航入口都不构成脱敏。私密网站对整个路径和静态资产服务端鉴权。

# 02 双轨收集与提取消化

> **便携版执行**：candidates → 人工intake / source → source-audit → gallery → 模型全图阅读 → digest → research-status。MCP搜索/提取为可选适配。字段以[数据合同](../运行/数据合同.md)为准；总表/清单/NOW均为只读投影。脚本不代替本章语义判断。

输入：具体研究问题和候选池。输出：可追溯raw、实际读过的图片、官方依据、可核对的批次统计。

## 两条证据线一起推进

先查登记候选、已有raw与Wiki；有合适候选先提取/消化。缺口仍在再用合法公开检索、人工分享/收藏或可选小红书MCP窄搜，同时保留官方及普通联网检索。默认人工入口见[采集与导入](../运行/人工采集与导入.md)。

- **经验线**：真实体验、菜品/份量、排队、口味分歧、步行感受、会车/停车困难、操作截图和踩坑。
- **官方线**：目标日期的营业、票价、班次、开放/停运、订位退改、行李、交通和安全规则。
- Google Maps适合识别实体和估算路线；搜索摘要用于发现页面。它们不能单独证明未来营业或合法停车。
- 凡联网结论改变、补强或限制了判断，同一轮写进相应Wiki，附稳定URL、核验日期和适用范围。

新城市检索覆盖面较广；逐日规划按决策缺口窄搜。近期笔记与前两年相近季节/假期经验搭配，历史内容始终标年份，不能把中国假期当作当地相同营业制度。

## 连接和后台工作

只有选用MCP时才读[小红书MCP手册](../运行/小红书安装与登录.md)，按包内安装器从零启动本机服务，确认端口、服务健康和使用者自己的登录。没有MCP不算阻塞；人工资料直接走intake。

已登录优先后台/无头检索；需要扫码才显示二维码。超时先区分服务、登录、单篇提取和图片下载，不为普通失败清除Cookie。凭证放宿主允许的私密运行目录，不进入资料Git或网页。

MCP不可用时继续已授权的官方研究，并记录查询词、错误和未提取ID。提取失败不能换一篇笔记却沿用原ID；空搜索不等于证实不存在。

## 状态与去重

```text
搜索命中 → 初筛候选 → raw已提取 → 正文已读＋全图已看
                                      ↓
                           写入Wiki / 有理由不采用
                                      ↓
                         台账与检索登记一致
```

每篇用原始笔记ID去重，标题只是辅助。相同图片指纹、近似标题是人工审查线索，不能直接删除：可能是同帖改标题、转载、合集复用或合法相似主题。核对ID/作者/正文/图集后再合并引用或注明来源关系；删除用户资料需要相应授权。

## 每批操作

默认3—5篇同主题；短且重复的材料可适度加量，复杂地图/票务图集拆小批。

1. 登记查询、日期、精确ID、标题、作者、选择理由。
2. 提取完整正文、元数据、所有图片及顺序清单，保存原链接的稳定公开形式。
3. 先看全部图片联系表，再以可读分辨率打开每张含信息的图片；正文点名P/图号、菜单、地图、流程图必须逐图精读。无法读清的图不记「已看完」。
4. 分开标作者经验、图中文字、官方当前事实、推断和未知，核实影响操作的内容。
5. 写入主题Wiki；逐条有去向，不采用也记录原因。raw保持原貌。
6. 同步台账、索引、检索登记及批次统计，运行宿主检查。

`已消化`要求正文、全图及行动信息去向都闭合；缺图/未读/关键提取失败是部分消化。全部内容不采用可记跳过，但与「没读过所以跳过」须区分。主题存在重要未知时仍明确待核验，不把篇目完成误读成旅行事实已确定。

## 报告数字要可解释

分别报：搜索命中、候选、成功提取、全图阅读、有效消化、部分消化、已审阅不采用、失败。按ID去重，一篇写入多个Wiki仍只算一篇；官方来源单列。

本轮新增与累计分开，列出本批ID、采用信息、写入页面、无增量/冲突及恢复入口。不要用总库历史累计量回答「这次新城市研究了多少」。

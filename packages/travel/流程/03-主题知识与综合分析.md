# 03 主题知识与综合分析

> 便携版以trip.json及knowledge为正式输入，sync/build派生总表与网页。本章负责模型/人的语义判断；确定性步骤见[角色与步骤](../运行/角色与步骤.md)。

输入：经验材料、官方链接和既有主题页。输出：能帮助做决定、可回溯的主题Wiki及必要的比较稿。

## Wiki按问题组织

适合的主题如「机场到市区与寄存」「某区域自驾与停车」「本地菜、咖啡与补给」「某季节追光与返回」。日期是适用条件，不是主题标题。某一天的时间线、行李分支和餐厅选择归总表或逐日讨论稿。

沿用[主题Wiki模板](../模板/主题Wiki.md)：快速结论 → 选择与操作 → 注意与复查 → 必要图示/相关资料 → 官方来源 → 原始笔记与阅读指引。短文删除空章节，不按「本轮新增」在文末堆旧结论。

一页只有一两个密切相关问题时不拆；出现独立决策、不同复查节奏或多篇细分证据时再拆。单店信息一般进入城市饮食Wiki和餐厅库。

## 从材料到判断

| 层次 | 应怎样写 |
|---|---|
| 作者经验 | 「这篇作者认为份量小」；注明日期、样本、可能口味差异 |
| 多源一致 | 说明独立来源的共同点，也记录反向样本 |
| 当前官方事实 | URL、核验日期、目标日期/时段、支持的具体规则 |
| 综合建议 | 根据本次路线、人数、偏好、成本给选择理由 |
| 未知或冲突 | 冲突双方、还缺什么、何时复查、当前可执行备选 |

官方实时公告与旧时刻表冲突时，比较发布日期、有效期、具体航线/方向/时段，保存可定位的原句或页面位置。不能仅凭当前停运就断言几天后永久停航，也不能仅凭全年PDF就保证当天有船。可因容错不足暂不采用，决定与运营事实分开写。

编辑整理不刷新事实核验日；另记编辑日期。历史价格、天气和照片不提升为当前状态。

新写或更新Wiki，完成证据综合后，按[旅行文案审校](../运行/旅行文案审校.md)读取包内Humanizer-zh并审校正文，再同步目录和网页。对照审校前后核对事实、归因、否定、条件、数字、时效、链接与锚点；不以禁词替换或AI检测分数作为通过依据。不自动重写本次未涉及的历史Wiki。

## 来源要真正可用

- 每条关键规则贴近对应结论给官网链接；篇末集中官方核验表。
- 原始小红书笔记统一放文末，用公开`/explore/<ID>`链接并附一句「想查什么看这篇」；保留本地raw索引用于审计。
- 删分享追踪/登录令牌，不能删掉真正识别页面所需的稳定参数；无法公开访问要说明登录要求。
- 图中关键信息附原图号与用途，图片许可与事实阅读许可分开处理。
- Domain仅导航Wiki；同一新事实优先更新现有页，不制造第二套主题资料。

## 比较必须具体到体验

使用[方案比较模板](../模板/方案比较.md)。至少列路线节点、交通方式、门到门与游玩时间、看见/体验什么、成本、轮渡或班次、季节限制、少看什么、当天失败代价。

比较长线/短线时按相同起终点与出发时间计算。截断可能取消一段船、减少山路，也可能增加原路返回；不按地图直线推算节省。混合线重新算完整成本，不能把两个半日最精华部分直接相加。

同类项目分析重复程度：例如两座缆车比较海拔、景观（峡湾/城市/群山）、日落/夜景、季节、步道和天气，不只看「都是缆车」。知名度与适合本次旅行分别讨论。

给有理由的默认建议，说明最大的未知与触发替换条件。用户已选后，总表只保留采用线；比较稿留研究层。

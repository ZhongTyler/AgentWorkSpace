# 总流程与事实分工

版本0.4.4：通用工作流自包含，每趟旅行独立保存。在宿主工作区中，工作流源、released 分发快照、旅行、私有资料和归档分开；经验采集默认人工导入，可选 MCP。独立发布包只由白名单 pack/release 生成，不分发含私人资料的整个工作区。

需求与固定订单 → 城市覆盖矩阵 → 候选筛选 → 原文及全图提取 → 模型逐图阅读与官方核实 → 主题Wiki → 方案比较 → 用户采用 → trip.json → 校验 → 总表/清单/预算/离线网站 → 浏览器验收 → 同行私下使用。线上部署是最后的可选分支。

## 唯一事实源

|事实|编辑入口|消费方式|
|---|---|---|
|日期、偏好、分段人数|trip.json 的 start/end/preferences/days|脚本算日期、人数和预算|
|地点与精确入口|places；稳定ID及唯一别名|地图、正文地点卡共用|
|地图服务|trip.json 的 mapProvider/mapCity；places.location为可选坐标|国内高德、境外Google；缺坐标时只给搜索入口，不伪造路线|
|餐厅/咖啡/超市/活动|catalog|日卡只存catalogId|
|正式安排、餐次、住宿、路线选择|days|总表、每日执行、手册复核依据|
|已订事实|orders；敏感原件在private|订单页、餐次、地点卡按ID引用|
|未完成行动|todos；一条可关联多个日期|全局待办与每日核对过滤同一个数组|
|分段路线|routes；days.routeIds选择|链接/自驾全览自动派生，截图绑定指纹|
|候选、提取、消化状态|research/registry.json及版本化raw/reviews|命令更新；NOW和数量自动汇总|
|主题知识|knowledge/*.md＋knowledge索引字段|模型聚合，离线搜索和弹窗读同一内容|
|购物/实用卡|shopping/guides|短结论＋wikiId打开详情|
|旅行手册|journal；关联placeIds、reviewedBasis|连续图文，不拥有第二份订单|
|天气|weatherLocations、days.weatherIds；weather快照|折线与卡片复用，不拿邻日填空|
|费用|默认餐次、orders.amount、expenses；rates换算|预算脚本；备选不相加|
|总表、清单、NOW、网页|generated/、build/|只读生成物，禁止手工改事实|

字段见[数据合同](运行/数据合同.md)，执行者见[角色与步骤](运行/角色与步骤.md)。

脚本负责格式、ID、引用、路径、指纹、统计、下载、投影和构建。模型负责读图、取舍、来源冲突、地理语义、缓冲和表达。人负责偏好、预算取舍、扫码、真实预订/付款/取消、授权及体验判断。脚本只能验证声明绑定哪份输入，不能证明声明真实。

候选不等于采用，采用不等于已订。未读完为partial，读完无增量为not-used，初筛排除为excluded。用户说“先研究”时只改研究层；授权落盘后才更新days。已完成todo退出默认视图，订单继续展示；已排除方案留研究记录，不在执行页堆“放弃结论”。

日期、入口或餐次变动后重新审阅受影响路线与手册，不机械重写hash。阻塞、需用户选择、临近复查、条件项目分开；不必先决定所有细节才推进下一天。

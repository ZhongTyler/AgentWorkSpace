# 私人偏好记录模板与使用方式

工作流只提供机制，不预置任何人的喜好。实际档案放Travel根下`偏好/<个人或小组>.md`，不随pack分发；新使用者自行创建。

## 一份档案记什么

记录主体、更新日期，以及“倾向 / 原始反馈来源与日期 / 下次用途 / 限制”。区分用户明确表达、亲历评价、执行者推断和已经失效的倾向。预算、节奏、体验类型及饮食按需要记录，不收证件和支付信息。

亲历原文留在旅行项目，偏好档案只保存跨旅行仍有意义的结论。针对具体店铺的推荐不升级为所有同类店铺的结论。

## 规划时怎样用

1. 只读使用者指定或本项目已经绑定的档案，不扫描目录猜测身份。
2. 本次明确要求与固定约束优先；冲突时标明本次覆盖，不静默改长期档案。
3. 在本次需求记录档案相对路径、读取日期、采用的条目和本次覆盖。新项目的trip.json.preferences保存本次采用快照；它不靠读取全局档案实时变化。不要把私人档案路径输出到公开包或普通网页。
4. 多人出游按实际成员合并，不假定个人偏好代表全队。无档案仍可正常规划。
5. 旅后只有用户允许时才更新长期档案；原始亲历和历史计划仍分别保留。

公开导出从白名单入口复制，不复制`偏好/`和旅行文件夹。通用方法只保留判断维度、操作和失败边界，不嵌入个人排序。

# 生图到正式项目 · v0.1

本文件是 [主工作流](workflow.md) 的资源制作分支，不是另一个完整开发流程。当前为可执行操作合同；首个已采用生成地图单体的真实接入/PCK/回退已验证，项目整体效果仍未验收，不能复用外部精选资产的24项测试冒充本分支效果证据。参考依据见 研究记录（沿接收方对应入口）。

## 进入与输出

进入：已有宿主 maintenance 任务、目标资源的用途、仍有效的风格决定、真实显示尺寸和不变的玩法语义。风格未定先做候选；风格已定不重开整场审美投票。

输出：被采用的位图、项目资源映射、来源/生成/加工收据、引擎与发布包证据。大图好看、背景透明、可加载、玩家认可分别验收。

## 制作步骤与门

1. **资源规格**：用 [制作卡](templates/generated-art-card.md) 固定 ID、用途、视角、轮廓、主体占画布比例、接地点、实际显示尺寸、透明/不透明、动画需要、禁区。画面文字、HP、意图、网格和判定仍由引擎绘制，不烘进角色图。
2. **代表性资产**：从一个最能检验当前问题的角色或物件开始。提示词包含用途、已选风格、主体、构图、约束；保留完整提示与参考的角色和哈希。先制作单体，不把整张棋盘效果图当可交付精灵图，不先量产全英雄。
3. **生成与迭代**：默认使用当前可用的内置生图能力；用户选择本地时按[本地生图与加工入口](local-image-workflow.md)选FLUX、Anima或Z-Image，性能检查和实验保留边界分别执行。本地 ComfyUI 是可选生产者，不是新增安装前置。每次版本保留原始结果，编辑指定参考并重述不可变项；服务不公开的模型版本/seed 写 unknown，不编造可复现性。两轮针对性修正仍不能在目标尺寸辨认，回到规格，不无限重抽。
4. **加工与小尺寸检验**：先真透明通道和黑/白/庭院底验边，再统一画布、接地点、缩放和裁剪。保留未加工原图、加工方法/工具版本与前后哈希。精灵需要四周余量，不裁掉武器、叶片或特效。不能把棋盘格背景当透明；RGBA 也不证明背景已去除。按当前可用生图 Skill 的工具约束执行修图，不自行以脚本重画替代生图。
   像素单体需要网格修复、原生尺寸定稿或动态受光时，按像素加工接线（沿接收方对应入口）选择<configured-tools>/pixel-art；干净像素跳过网格处理，固定光照可跳过法线。默认等比最近邻＋透明补边，保留原alpha；不是自动画笔精修或角色动画。
5. **采用门**：在真实盘面、真实最小尺寸和密集状态对照旧资源，由制作人决定新的角色身份/美术精度是否成立。记录 adopted/revise/rejected；技术通过不能改为 adopted。已有认可资产的无风格变化修正可沿用授权，但要记录范围。候选仅进隔离预览，不默认进入发行包。
6. **接入**：复制已选版本到项目运行资源区，用稳定 ID 映射 Texture2D / SpriteFrames / Theme；不要让规则代码引用生成输出路径。先 dry-run 核对源哈希、目标旧哈希、增加/替换/移除项与 owner，再显式应用；使用 [两段交付](adapters/godot/workbench.md) 的生成接收、seal/publish和恢复入口，未过权利门不能发布。外部精选仍走 [deliver.mjs](adapters/godot/README.md)，不得伪造 PrototypeAssets ID/许可来套用它。
7. **实机与交付**：Godot 实际导入，检查尺寸/透明、过滤、动画顺序、接地点、窗口缩放、命中预览与遮挡；跑受影响规则/输入回归。实际 PCK 不含原图、提示、参考、备份、生成服务、MCP 或测试；必要来源与许可保留。失败恢复旧映射，不删别人的文件。

## 资源图册与状态审阅

生成后的裁框、真实尺寸和状态组合按[资源图册流程](resource-review.md)实施，完整展示本次资源与必要场景。图册采用内嵌图片或明确的本地服务，先核对实际加载，再提交制作人审阅。

## 项目存放合同

按 [工作台合同](project-assets.md) 存放，由 assets.directory 配置，默认与 docs 平级的 assets。旧 art-source 建议退出默认；已有项目受控迁移，不静默移动其他项目。

- sources/generated/<asset-id>/<version>/：不覆盖的原图、完整提示/参考与生产记录。
- work/<asset-id>/<version>/：加工、小尺寸预览与采用；造型、用途、技术、权利独立。
- releases/：通过相应用途门的精选引擎交付版；通过 [seal/publish](adapters/godot/workbench.md) 封装与交付；实际生成地图图仍需真实采用闭环。
- catalog.json：项目用途/来源/工作版/参考/期望采用的唯一结构化清单；工程receipt拥有实际安装。
- 引擎内：只保存采用的运行图及精简收据，不依赖源/提示/参考；旧vendor直导仅作为精确登记的legacy保留。

原画认可不批准地图图。每个目录有README，局部探针归work，整场验证归docs/validation。未采用资产只在隔离预览使用。

运行收据至少含 asset_id、source_kind=generated、源图/交付图 SHA256、工具及可得版本、加工链、采用决定引用、目标路径与上一版本。完整提示、私有参考或服务元数据保留内部，不机械随包公开。

## 动画与 Godot 适配


单体图配合 Godot 位移、缩放、旋转和粒子已足够时，复用已验证事件回放。用户需要逐帧形体变化或现有动作不满足目标时，按GamePresentation Skill的角色动画生产（沿接收方对应入口）复用基准、原版sprite工具和动作检查；不把视频抽帧当默认路线。序列另加帧尺寸、每帧时长、循环、接地点、帧序与事件标记；图集压紧后必须保留偏移信息，避免抖动。

绘本风格默认测试线性过滤；像素风才测试 nearest，不因为参考仓是像素项目而改变宿主画风。UI/2D 先测试无损压缩，mipmap 按实际缩小需求决定。以上是起点，最终以实际目标窗口证据决定。

动画标记只驱动视听反馈，不重新造成伤害或改变技能末清理。未来换图、换动画或跳过回放，规则终态必须不变。Godot 编辑器导入成功之后还需实际包测试。

## 权利、安装与失败边界

代码许可、模型权重条款、参考图授权、生成服务条款与成品采用分别记录。GitHub 可见、模型可下载、工具 MIT 均不自动证明输出可商用；未知权利不默认放行。不得标 AI 图为 CC0 或保证独占版权。新服务、收费、账号、模型下载及执行第三方节点须符合现有授权，研究不等于安装许可。

可用边界：缺生图工具时可以完成规格和研究，但停在制作，不用程序临时图冒充生成结果；透明失败回加工；轮廓失败回规格；只有规模化成本证明需要才接新生产者。

以下来自同一项目，属于可复用检查方法，不是跨项目效果已通过，也不是固定美术标准：



5. 环境和UI应共享明确的参考构图；背景cover、UI等比fit、前景按整张透明画布缩放混用，会导致比例错位和空带。先检查可见主体、锚点和多宽高比合成，不立即要求重新生图。v28采用居中参考矩形与独立边缘处理，仅是本例方案，不固化为所有游戏布局。
6. 采用前后的实际媒体必须按ID和哈希对齐。此次catalog仍指向旧UI，不能直接封版；规范化历史原图接收、加工链另存，再seal/publish。批量编辑必须按稳定ID，重复文本可能误改另一项，发布预检应验证完整集合。
7. 候选迁移须检查全部脚本继承、临时媒体和启动器。只复制顶层HUD会遗漏基类，基类签名变化又可能使引擎拒绝编译。正式运行先隔离验证，再从空目录加载真实PCK；外置测试不应覆盖包内运行源码。
8. “阶段通过、先有再优”应成为明确采用记录，保留质量限制但解除同一视觉等待。不要反复要求认可已通过模块；未完成的包验证和流程审计继续独立推进。新旧测试按实际布局适配，保留交互/规则不变量，不能直接删除失败断言冒充通过。

## 地图用途与回退证据


本次消费者验证还覆盖：.import是可复现导入设置，不等同.godot缓存；选择性入库并让隔离回归保留它，实际包检查mipmap。回退有两类owner：项目先撤显示引用，资产事务再撤媒体；恢复顺序相反。通过当前实例后再推广，不把该图尺寸/锚点固化为其他资产标准。

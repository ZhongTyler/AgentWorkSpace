# Upgrade 1.11.0 → 1.12.0

Research adds optional pinned game-source references: eight recommendations, eighteen backup groups, exact revisions/archive and manifest hashes, original notices, scoped source lookup/recovery and external-home preparation. Tools adds the committed FLUX klein maintenance capability previously missing from the public file inventory.

```text
python scripts/workspace.py upgrade --target <workspace>
python scripts/workspace.py upgrade --target <workspace> --apply
```

Only selected packages update. Research remains usable from Markdown, URLs and questions without saving any game repository. The reference workflow selects one or two relevant implementations, reads actual modules, cites exact versions and returns evidence to the original research/project. It does not poll every repository, auto-update sources, replace real Play, or authorize Knowledge ingestion/final approval.

To use source references, run modules/research/reference-library/prepare_home.py with --home <external-reference-home>, then explicitly restore only selected references from that home; --download is required when no local archive exists. Preparation performs no network or target execution. Managed modules refuse source restoration. A full eight-source snapshot is approximately 201MiB compressed plus 263MiB expanded; dependencies, full history, remote assets and DDNet's build submodule are not bundled. Review each project's code/asset/dependency terms before reuse.

For FLUX, prepare a NEW external Tools home using modules/tools/prepare_home.py. Then follow integrations/flux-klein/README.md there: pin ComfyUI, create the Windows Python3.12/CUDA environment, explicitly obtain the three locked components and verify all hashes before starting. Active weights total approximately 8.255GB; no weights, GPU runtime, host trial images or installation receipts are included. Package installation does not load models, register MCP, create schedules or generate assets. Recipient installation, quality and stability require local validation.

Keep the upgrade transaction ID. Rollback restores managed package files to 1.11.0; existing external reference/tool homes, runtime, private notes, host rules, client configuration, research traces and project decisions remain owned by the recipient. Preparation refuses existing destinations; retain old versioned homes and switch only after validation. Package rollback does not undo independently installed dependencies or adopted host settings. Conflicts stop overwrite, and earlier tags remain immutable.

Tools also includes the now-committed CPU illustration cutout adapter, locked model identity and explicit preparation/verification. Weights, private comparison images and inference receipts remain outside the package; segmentation is a candidate-processing step and cannot certify holes, fine leaves or optical glass transparency.

Skills includes reviewed workflow-closure guidance for binding asynchronous work to the actual task/version and checking its terminal result. Installing/upgrading the workspace package does not upgrade selected client Skills. Selected-Skill catalog 1.12.0 follows 1.8.0: if your selected-Skill state is older, first use the old 1.11.0 package's modules/skills/scripts/skills.py upgrade command to reach its supported predecessor, then upgrade the workspace package and explicitly preview/apply the new selected-Skill upgrade. Preserve each transaction for reverse rollback; local conflicts remain protected.

Other packages retain their existing behavior. Private image comparisons and local host-governance adoption remain with their owners; this release publishes only the reviewed portable closure guidance, not private analyses or host authority. See [release verification](../docs/releases/1.12.0-validation.md).

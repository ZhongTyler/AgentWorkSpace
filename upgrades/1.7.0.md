# Upgrade 1.6.0 → 1.7.0

This release adds opt-in REA tooling to the existing Research package: pinned CLI/MCP setup, a portable `rea-investigate` skill with matching upstream references, and tool/evidence storage guidance. Existing package selections, paths and host authority stay intact. No new package dependency is required.

升级不会下载REA运行依赖、连接账号、修改Codex配置、启用skill/调度或授权Knowledge入库。没有安装Research的工作区仍不会自动加包。Research已有用户报告继续保存在包外，公开包不携带维护者连接状态、试跑输出或机器路径。

## Upgrade and optional setup

Use the unified installer from this distribution, separately from the target workspace:

```text
python scripts/workspace.py upgrade --target <workspace-path>
python scripts/workspace.py upgrade --target <workspace-path> --apply
```

Review existing research workflows before adding Research. For a host without it, use `audit --needs research` then explicit `add --packages research`; a compatible Research-only installation does not require meta or a profile.

Read `modules/research/integrations/rea/README.md` when a shipped artifact or missing-source question warrants REA. The optional tool installer needs Python 3.11+ and supported Node/npm. From the installed Research package root:

```text
python integrations/rea/scripts/install.py --runtime <external-rea-runtime> --install --configure-codex --skill
python integrations/rea/scripts/install.py --runtime <external-rea-runtime> --install --configure-codex --skill --apply
```

The first command only plans. Select operations independently if needed. Runtime must be outside `modules/research`; Node and native analysis engines are not installed by this tool. Existing different REA registrations or skill edits are refused for review. Client config is backed up locally and unrelated bytes remain intact; no maintainer configuration is inherited. Restart the client and test an approved small target to establish that client's connection.

## Recovery and limits

Keep the transaction ID and preview rollback before applying:

```text
python scripts/workspace.py rollback --target <workspace-path> --transaction <transaction-id>
python scripts/workspace.py rollback --target <workspace-path> --transaction <transaction-id> --apply
```

Package rollback restores installer-owned package files. It does not roll back external REA runtime, installed client skill, Codex configuration, accounts or private reports. Keep those separately; disable only the REA registration and review the installed skill when reverting tool setup. Never overwrite the whole current config with an old backup after unrelated settings changed. Version upgrades use a fresh runtime and an explicitly reviewed switch, not automatic `latest` or deletion of the old tool directory.

Windows verification covers actual 1.6.0 full/compatible Research upgrade and reverse rollback while preserving reports, external tools, client canaries and host rules. Optional REA restoration, CLI version, skill setup, configuration preservation, repeat setup and read-only stdio analysis were tested in isolated recipient directories. This does not certify other platforms, every native provider, implicit skill selection accuracy or research benefit; static unknowns and dynamic IPC gaps remain explicit. Historical release tags remain unchanged.

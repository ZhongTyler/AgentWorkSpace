# 1.28.0 → 1.29.0

This release updates meta, Skills, Research, Knowledge and GameAnalysisDecision. The other seven component file inventories are unchanged. Skills contains 35 optional methods; installing the package does not activate client methods, tools, services or models.

## Changes

- meta adds bounded progress review, stop conditions and outcome learning.
- Skills adds game-runtime-patterns, pixel-asset-production, session-handoff, game-feel and game-ui-ux, and updates existing presentation, decision, interaction, research, debugging and closure methods. Fixed upstream licenses and notices are retained.
- Research adds the v1.5 method, study compiler, stage controller and package-local report renderer. It works without the Skills or Knowledge package. External semantic review remains necessary; no real archives, media, acceptance or efficiency claim is included.
- Knowledge adds report relation navigation, completion-state checks, reviewed Group threshold assessment and exact approved source projection. Optional bindings remain explicit and disabled when absent. Experimental online query services are excluded.
- GameAnalysisDecision adds a bounded state/input/feedback/recovery audit candidate. Project evidence and usability acceptance are recipient-owned.

## Review and apply

Use a clean copy of this release outside the recipient workspace. Read `docs/compatible-workspace.md`, audit existing package/workflow overlaps, then run:

```text
python scripts/workspace.py upgrade --target <workspace>
python scripts/workspace.py upgrade --target <workspace> --apply
```

Review conflicts before applying; owner-edited managed files are refused rather than overwritten. Existing packages keep their registered destinations. Reports, accounts, user configuration, assets and runtime stay outside managed templates. No reinstall, ingestion, paid call or automatic source binding is needed.

Client Skills have a separate transaction. After package upgrade, review and apply `python <workspace>/modules/skills/scripts/skills.py upgrade --target <workspace> --apply`, then explicitly install desired new names using the same script's `install --names ... --apply`. Review the client's actual path and host rules. Package upgrade alone does not migrate installed client methods.

## Recovery

Record transaction IDs. Reverse new client installations first, then client upgrade, then package upgrade, each with the corresponding `rollback --transaction <id> --apply` command. Package rollback uses `scripts/workspace.py rollback --target <workspace> --transaction <id> --apply`. Review rollback plans and preserve owner changes; do not restore by deleting private directories or moving published tags.

Old research archives retain their original schema and review identity. New compiler/controller output does not retroactively accept old studies. Keep working reports outside package directories; use explicit local bindings for optional Research/Knowledge integration.

# 2.6.0 升级与恢复

上一正式组合为 2.5.0。本次仅更新独立 Tools 至 2.2.0；其余11个模块固定身份不变。公开内容、依赖、来源与验证范围以 Tools 本版说明为准。运行环境、模型、账号和私人结果不随模块升级迁移。

Tools 新增 git-scope、sprite-diagnostics、demo-support，合计17项工具/15条可选 workflow；原14项登记保持。Git工具需要可信仓库与Git，精灵工具需要Pillow/Node，音频另配NumPy/SoundFile；安装不准备这些环境。文档与来源见 [Tools 2.2.0](https://github.com/ZhongTyler/AWS-Tools/blob/v2.2.0/docs/release-2.2.0.md)。body-candidate的相对输入/输出现在按调用者cwd解释，保持原HTML及输出保全。

AWS 获取层对每次Git调用局部启用长文件路径，不修改全局或系统配置。验证覆盖实际279字符staging成员；Git元数据目录本身极深仍可能失败。保留失败staging，先选择较短仓库根目录，不覆盖原失败或移动已发布tag。

先按需获取 Tools，运行 `python scripts/workspace.py upgrade --target <workspace>` 审阅差异，确认后加 `--apply`。用户编辑的受影响文件拒绝覆盖；已有宿主规则、项目、私人材料及未改模块的用户编辑保持。保留 transaction，通过 `python scripts/workspace.py rollback --target <workspace> --transaction <id>` 预览并加 `--apply` 回退。

Tools 使用包外版本化 home。先在新外部目录显式 prepare_home，再自行准备所需依赖并验证，最后切换调用方；旧 home 作为恢复入口保留。安装或升级包不下载模型、不启动或注册服务、不变更账号，不替代使用者的实际运行验证。原有客户端 Skill 安装记录不因 Tools 更新而变化。

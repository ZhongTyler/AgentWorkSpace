# Upgrade to 1.16.0

From 1.15.0, this release changes Tools, Knowledge, Research and Skills. The other eight component inventories are unchanged. No recipient knowledge, model, binding, hook, schedule or website is created by package installation.

Tools provides one reviewed-commit refresh implementation. Knowledge provides the approval-bound adapter and optional Git post-commit event. Explicitly enable `maintenance` in a trusted local binding with an external version home, then opt into the event using the Knowledge guide. Existing non-managed hooks are preserved. Completed ingestion result commits are checked against exact report/manifest/Wiki bytes; reviewed manual maintenance uses explicit review-reference/scope commit trailers. Ordinary unreviewed commits do not refresh. Host callbacks may use the same adapter; no background watcher is installed.

Research and game-decision-support route real knowledge gaps through Query: BM25 first, bounded hybrid only for actual recall gaps, and original Query fallback. Full-source reading and approval contracts remain. Package upgrade and selected-Skill upgrade are separate; see the Skills upgrade guide and preserve modified recipient Skills.

Build and validate a fresh external version before atomically switching the binding. Retain the previous index and binding for restoration. Failed BM25 refresh preserves the pointer; stale-source queries use original Query. If optional hybrid refresh fails, a verified fresh BM25 may activate while stale hybrid is disabled and explicitly falls back. Repeated unchanged content does not rebuild. Busy/concurrent work and actual failure must be reported; do not rewrite approval hashes or remove another owner's lock.

For rollback, use the workspace transaction recovery. Preserve private Wiki, audit history, local bindings and external runtimes; restore the prior binding if needed. Set maintenance.enabled=false to disable future updates. The owned hook is inert after rollback to a version without its adapter; never delete unrelated hooks. No website deployment or model-generation savings are claimed.

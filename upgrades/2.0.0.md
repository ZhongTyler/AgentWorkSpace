# 1.30.0 → 2.0.0

2.0.0 moves every module and the complete meta framework into independent public repositories. AWS fixes their commits as Git submodules. Each module has an independent version and optional cooperation interfaces. Node, Python and configured tools remain module-specific prerequisites.

## Existing managed workspaces

Keep the 1.30.0 installation records, private data and transaction backups. Obtain AWS 2.0.0 in a separate directory. Preview the upgrade using `python scripts/workspace.py upgrade --target <workspace>`. The report lists missing source modules without downloading them. Use `fetch --packages <installed-ids> --apply`, or apply the selected upgrade to retrieve them. Add `--apply` only after reviewing the plan. Upgrading selects existing installed modules, while `--all` is an explicit choice for the whole catalog.

Full-mode workspaces retain their managed root-meta layout. Compatible-mode workspaces retain host authority. User projects, trips, Knowledge data, accounts, runtime and independent template copies keep their existing ownership and locations. Unchanged upstream files retain user edits. Changed managed files with owner edits block the transaction.

Update selected client Skills in a separate transaction using the Skills module's `scripts/skills.py upgrade`. Package upgrade does not enable all methods. Keep both transaction IDs. New modules can be added independently through AWS or their own repository entry.

## Existing standalone modules and workflows

Audit the host and requested modules before connecting them. A module.json identifies a candidate. Matching version, manifest and inventory establish same-module baseline reuse, which is recorded with its actual location. Existing independent Git clones remain external instances, with their Git repository and files owned by the user. An edited, duplicate or different-version instance requires owner selection and a separate reviewed upgrade. Similar workflows still need responsibility, I/O, authority and recovery review.

Modules provide their own domain rules. host-governance becomes an optional enhancement in 2.x. Existing frameworks and optional meta remain usable. Meta continues as one complete edition.

## Reverse recovery

Rollback the new client selection, then its client upgrade, then the workspace upgrade using each recorded transaction ID and a preview. Workspace rollback is `python scripts/workspace.py rollback --target <workspace> --transaction <id> --apply`. Later owner edits cause conflict refusal. The 1.30.0 tag, ZIP and recovery tools remain available. Source retrieval can leave a verified cache, which is separate from recipient transaction recovery.

Standalone peer retrieval preserves staging and receipts under `.module-manager` on failure. Inspect the actual installed instances and receipt before retrying. Existing independent module instances are preserved when reversing AWS registration.

## Download size and history

The 2.x aggregate ZIP contains the catalog, guides and tools. It retrieves selected modules from their locked repositories. A shallow Git clone likewise avoids 1.x historical payloads. Full-history clones can still download files retained in 1.x history. Existing tags and published assets keep their original identity.

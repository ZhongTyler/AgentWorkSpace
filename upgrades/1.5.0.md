# Upgrade 1.4.0 → 1.5.0

## Compatibility / 兼容范围

This version adds Travel 0.4.6 as the eighth optional package. Existing selections, module paths, host authority and user data remain unchanged. Upgrading does not install Travel automatically. The package has no required meta, Knowledge, Skills, game package, account service or server. Existing similar travel workflows require semantic review before integration; satisfied dependencies do not prove compatibility.

本版只新增可选 Travel，升级不自动安装它，不迁移用户已有行程、偏好、账号、网站或旧工作流。Travel 来源仓改为直接发布到 packages/travel，不再维护 released 副本；该变更只影响维护者。源码内版本保持 0.4.6，发布仓版本为 1.5.0。

## Upgrade / 升级

Use this repository version in a separate directory. Python 3.10+ runs the installer; Node.js 22+ is needed only for Travel tools. From the release repository:

```text
python scripts/workspace.py upgrade --target <workspace-path>
python scripts/workspace.py upgrade --target <workspace-path> --apply
python scripts/workspace.py audit --target <workspace-path> --needs travel
python scripts/workspace.py add --target <workspace-path> --packages travel
python scripts/workspace.py add --target <workspace-path> --packages travel --apply
```

For a workspace that does not yet use this installer, choose `init --mode compatible --packages travel` after review. No capability profile is required for Travel alone. Keep trip projects outside modules/travel, for example trips/my-trip. Read modules/travel/README.md and create the fictional demo before adding private information. Core commands do not install npm dependencies or contact account services.

Review reported conflicts before applying. User edits are preserved when upstream is unchanged; overlapping edits stop the operation. Existing installations are upgraded before optional packages are added so each step has its own recovery transaction.

## Recovery / 恢复

Record the transaction ID returned by each applied operation. Roll back the Travel add first, then the preceding upgrade if needed:

```text
python scripts/workspace.py rollback --target <workspace-path> --transaction <transaction-id>
python scripts/workspace.py rollback --target <workspace-path> --transaction <transaction-id> --apply
```

Rollback checks for changes made after the transaction. Do not overwrite conflicts or remove trips to make recovery pass. Projects stored outside the installed package are not owned by the installer and remain in place. The published v1.4.0 tag is unchanged.

## Verification boundaries / 验证边界

Release checks cover independent installation, existing-workspace audit, 1.4.0 upgrade/add/rollback with local content retained, source tests and a fictional offline browser demo on Windows. They do not establish current tourism facts, account-service availability, other operating systems, independent user acceptance or real travel safety.

# Upgrade to 1.21.1

Previous version: 1.21.0. This patch changes only five Research documents and its source marker; all other component file inventories are unchanged. Research protocol v0.9 keeps one maintained method with a thin research-study entry, a report template and a proactive guide.

The method now asks continuing research to compare prior conclusions, implementations and experiments before claiming new value. Diagnosis should trace real failures, output and reviewer decisions when available, distinguish causes from repairs, and report the depth actually supported by evidence. Simple research still needs no fixed experiment pipeline, extra model or new service. This release does not establish improved research quality or lower cost.

## Preview, apply and restore

Run these commands from this distribution checkout, keeping the target workspace separate:

```text
python scripts/workspace.py upgrade --target <workspace-path>
python scripts/workspace.py upgrade --target <workspace-path> --apply
python scripts/workspace.py status --target <workspace-path>
python scripts/workspace.py rollback --target <workspace-path> --transaction <upgrade-transaction>
python scripts/workspace.py rollback --target <workspace-path> --transaction <upgrade-transaction> --apply
```

If managed files have local edits, resolve the reported conflicts before applying; do not overwrite user work to make an upgrade pass. Keep the transaction ID for recovery. Install or add Research only if selected; upgrading an existing workspace does not implicitly add it or install a client-level Skill.

The research-study Skill remains inside the Research package. Read it from the installed Research directory or use that host's existing discovery setup. The standalone Skills library is unchanged. Package upgrade and separately managed client-level Skills remain independent transactions.

Keep research reports, experiment data, captured media, candidate lists and runtime outside installed modules. This patch neither reads nor migrates them; it changes no user schedules, accounts, models, Knowledge records, approvals or project decisions. Published scheduling templates retain their prior values; maintainer-local schedule changes are outside this release.

See [validation and limits](../docs/releases/1.21.1-validation.md). Technical packaging and upgrade checks do not prove research-depth improvements or long-term benefit.
